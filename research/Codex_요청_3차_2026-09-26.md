## 2. 현재 EC 모델 (리더보드 0.2055, 현재 최고)

## 3. 검증 방법 (중요)
EC에서는 **실제 리더보드 변화 방향을 3번 모두 맞힌 검증이 교차검증 A뿐**입니다.
- **주 검증: 교차검증 A.** `research/harness.py`의 `folds("A")`와 `common.split_mask`(전후 1일 버퍼)를 씁니다. 폴드끼리 날이 겹치므로 **폴드별로 따로 채점해 평균**하고, 몇 개 폴드에서 좋아졌는지(x/5)를 보고해 주세요. 기준 모델도 각 폴드에서 `ec_v6.pipeline`으로 다시 학습해야 합니다.
- **보조 검증: DIAG10.** 1·2차와 같습니다. 기준 OOF는 `research/local/oof_ec_diag.npz`에 있습니다.
- **쓰지 말 것**: 2차 구간만 떼어 낸 검증(SP, SP2). EC에서 실제와 반대 방향을 두 번 가리켰습니다. `day`를 빼는 변경을 SP2는 −31.5%로 봤지만, 실제 리더보드에서는 +3.8% 악화였습니다.
- 온실-날 블록 부트스트랩 95% 구간을 보고해 주세요. 전체 행 외에 **EC>1.5 행**과 **밀폐 날**(아래 4절) 오차도 따로 보고해 주세요.

## 4. Claude가 확인한 EC 사실 (이번에는 공유합니다)
| 사실 | 수치 |
|---|---|
| EC는 하루 수준값 문제 | 하루 평균이 분산의 95%. 3회차 모델 오차의 83%가 하루 오프셋 |
| 오차가 소수의 날에 몰림 | EC>1.5 행 5%가 오차제곱의 63%. 최악 15일이 63% |
| **"밀폐·팬 정지" 날 = EC 고값 구간** | 하루 유동팬 평균 < 10이고 천창 0인 시간 비율 > 0.85인 날. 학습 59/400일, 일평균 EC 0.99(나머지 0.44). **평가에는 21/60일로 비율이 두 배 이상.** 이 날들의 모델 일평균 오차 0.39(전체 0.19) |
| 밀폐 날 안에서 EC와의 순위상관 | 차광 0 비율 +0.60, 차광 평균 −0.56, 포그 −0.56, 내외 온도차 +0.46, 실내온도 +0.42. 모델 잔차와는 약함(최대 0.29) |
| 학습의 밀폐 날은 대부분 잡음 낀 날 | 학습 밀폐 날의 61%가 CO₂ 거친 날(나머지 19%). 평가의 밀폐 날은 대부분 깨끗함 |
| 생육 단계에 따라 EC 상승 | 기록 초반 0.2~0.3 → 중후반 0.8 이상. `day`가 중요함(실제 제거 시 +3.8% 악화) |
| 격일 구조 | 일평균 자기상관 lag1 0.13~0.20, lag2 0.52~0.73. 모델이 이미 잡고 있음 |
| 다른 49개 온실 | EC 정답 없음. 구동기 기록도 거의 없음 |

**이미 실패한 방법 (반복하지 마세요)**
- 잡음 낀 날 가중치 하향: EC 악화(밀폐 날을 깎아냄)
- 잡음 낀 날 실내 센서 평활: A −0.9%로 미미. 학습·평가 모두 평활하면 악화
- EC>1.5 행에 가중치 3: 실패(1차 보고서)
- 하루 요약값 최근접 5일 평균: 모델보다 크게 나쁨(0.504 vs 0.388)
- 이웃 날 정답(라벨 이력): 규정상 쓰지 않음. 진단상으로도 모델보다 나쁨
- 달력 위치 피처, "진짜 어제" 피처: A/B에서 악화
- 외부 기상, 물리 피처 추가: EC에는 해로움

## 5. 시도해 볼 만한 방향 (제안일 뿐, 자유롭게 판단하세요)
- **하루 수준 구조를 직접 쓰는 모델**: 하루 평균을 먼저 예측하고 하루 안 모양을 더하는 2단계 구조. 입력은 해당 시각까지만 씁니다.
- **밀폐 날 전용 하위 모델**: 밀폐 여부는 **해당 시각까지의 입력**으로만 판정해야 합니다(하루 전체 판정을 이른 시각에 쓰면 누출).
- **목표 변환**: 로그 EC 등.
- **다른 계열**: 스플라인 Ridge, 단조 제약 LightGBM 등. 현재 모델과 오차 방향이 다를수록 혼합에 유리합니다.

## 6. 규정 (이전과 같음)
- 평가 행 피처는 **같은 온실의 해당 시각과 그 이전 입력만** 씁니다.
- 이웃 날 정답, 다른 온실 입력, 평가 입력 전체의 분포는 쓰지 않습니다.
