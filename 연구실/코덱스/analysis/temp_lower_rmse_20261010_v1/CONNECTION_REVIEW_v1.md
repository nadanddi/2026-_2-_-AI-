# N2 공식 타농장 온도 증분 prior — 연결·계획 비평 v1

2026-10-10 연구실 코덱스 독립 비평. 새 모델 fit/predict·정답 재채점·외부자료/외부파생로그 접근 0. 사용자 명시 온도 연구 재개 지시에 따른 검토다. `PLAN_v1.md`는 작업 절차이며 후보 등록이 아니므로 본 비평도 구현 승인이나 성능 판정이 아니다.

**판정: N2는 읽고 검색한 공식 코드 범위에서 같은 구현의 실행·기각을 찾지 못했다. 기존 실패와 실질적인 차이는 있다. 그러나 LOFO 중단 기준·지원 열·누적 경계가 아직 봉인되지 않아 target 실험 등록으로 바로 넘어갈 수 없다.** 먼저 제한된 공식 other-farm 변화 예측의 타당성을 확인하는 진단으로 다루는 것이 적절하다.

## 2. 같은 증분·모양 전이가 이미 실행됐는지

직접 읽은 공식 `temp_transfer_v1/v2.py`의 target은 둘 다 `sub_temp`다. v1 입력에는 diff/lag/EWM이 들어가지만 **입력 diff가 존재하는 것과 target을 Δsub_temp로 바꾼 것은 다르다**. v2도 그 v1 특징 함수를 가져와 절대 target을 사용한다.

공식 온도 관련 코드 파일 목록 및 `delta.*prior / prior.*delta / sub_temp.diff / delta_sub / dsub_temp / LOFO / leave-one-farm` 계열 검색에서 같은 N2 실행 코드는 발견하지 못했다. 검색 범위는 집클로드research, 집코덱스analysis, 연구실코덱스analysis, 연구실클로드code의 `.py`이며 외부자료·문헌·도메인 폴더는 제외했다. 발견한 두 기타 공식 코드는 진단용 차분/지연 검사였으며 Δprior LOFO 학습 구현이 아니었다.

이것은 **동기화 완료 후 전체 아카이브·일지 전수까지 동일경로 부재를 증명한 결과가 아니다**. 이름·검색표현이 다른 코드, 아직 동기화되지 않은 산출물은 남는다. 60914 동기화 완료 후 신규집클로드파일과 공식 출처가 보장된 온도 code/log 목록을 한 번 더 대조해야 한다. 외부 `ext_public` 경로는 검색 결과 이름만 보였으며 내용 접근하지 않았다.

## 3. 현재 계획의 필수 보완

### A. LOFO gate가 ‘다수농장실패’라는 자연어로 남아 있음

실행 전 코드·등록에 고정할 항목은 다음과 같다.

- F13/F47/F32 제외의 정확 farm 목록·공식3CSV SHA·동일날 연속시간쌍 ID/SHA. 라벨 두 시점 유한, `farm/day` 동일, `t_h−t_prev=1`, h∈1..23을 강제한다. 결측을 건너뛴 diff와 자정 diff를 금지한다.
- Ridge alpha·intercept·predictor 순서·imputer/scaler/상수열 처리·sample weighting 고정. LOFO fold에서는 holdout 농장 입력으로 imputer/scaler/열선정/alpha를 fit하지 않는다. target 정답은 usecols row_id/sub_temp만 읽는다.
- 농장별 최소 유효쌍·최소날·비상수 target 조건과 탈락농장의 분모 포함/제외 방식. 지원없는 농장을 실패와 제외 사이에서 사후 바꾸면 결과가 달라진다.
- zero 및 .5Δair **둘 다 같은 유효쌍**에서 비교할지, 두 baseline 중 나은 쪽과 비교할지 고정. Δair가 결측인 쌍의 gate 산입도 고정한다. 서로 다른 행집합의 MSE는 비교 불가다.
- ‘다수’의 정확 비율/동률처리와 큰 농장 가중 pooled MSE 또는 farm 동일가중 중 무엇을 gate로 쓸지 고정. 작은 농장 다수만 통과하고 큰 농장이 크게 악화하는 경우도 먼저 처리한다.
- farm별 양자화/0변화·학습/검증 MSE 및 날별 방향을 보고하되 통과농장으로 prior를 사후 재학습하거나 threshold·alpha를 고치지 않는다. 실패하면 target fit 0으로 종료한다.

LOFO는 독립 타농장 전이 진단이지 F13/F47 잔차에 새 정보가 있다는 검정은 아니다. LOFO 통과는 다음 target 단계 진입 조건 하나로만 쓴다.

### B. ‘현재·이전14input’의 지원 불일치

CODEX14는 외기4·실내3·구동기7이다. 공식 다른농장에 해당 운영열은 거의 없다는 6b.20/6.19와 v1 주석의 실내3 중심 지원을 함께 봐야 한다. 단순 schema14 존재가 실제 관측14를 뜻하지 않는다.

other-farm 전체 학습에서 all-NaN 열이면 imputer drop/keep 처리와 target 재적용 열순서가 고정돼야 한다. 특정 LOFO에서만 관측되는 열도 있어 fold별 drop이 달라질 수 있다. 원시 missing marker를 넣으면 농장 지문으로 쓰일 수 있다. **부족한 열을 타농장에서 학습해 대상의 관측 운영값에 적용하는 것은 학습지원 밖 예측**이 될 수 있다. 첫 준비에서 농장×28개 현재/직전 열의 관측지원표를 저장하고, 원래 계획상 지원없는 열의 처리 규칙을 정해야 한다. 이 사전 무정답 지원 검사가 끝나기 전에는 ‘14변수 전이’로 설명하지 않는다.

### C. 누적 특징의 인과 경계·level 표현

`z_h = Σ_{k=1..h} prior(X_k,X_{k−1})`, z_0=0 같은 수식을 사전 명시해야 한다. 동일농장·동일날 prefix만 소비하고 미래행 변경/타농장 query변경/행순열에 불변이어야 한다. MASK상 h−1 입력이 비는 경우 0 혁신으로 할지 NaN 누적으로 할지, 누락 이후 재시작할지 고정해야 한다. `cumsum`의 NaN skip을 라이브러리 default에 맡기면 끊긴 경로를 이어붙일 수 있다.

Δtarget은 날별 상수 offset을 상쇄하지만 정적 현재온도·시간에 의한 예측 bias가 누적되면 z_h가 일수준·시각 대리가 된다. 따라서 **‘절대 수준 완전 제거’가 아니라 ‘학습 target의 같은날 상수차 소거’**라고 쓴다. 실제 sub_temp(h0)를 대상 anchor로 사용하지 않는다. 기존 물리 Ridge/BASE/PFN/계절/가중치는 바꾸지 않는다.

### D. target 검증의 계약

N2는 CODEX 잔차 **한 특징만** 바꾸는 조건부 후보다. target fold에서 학습/검증/±1purge 입력 격리, season fit·weights·MASK·query 순서가 baseline/candidate에 같아야 한다. prior 자체가 F13/F47 공개정답을 쓰지 않는 계약을 유지하면 target outer fold마다 prior 학습을 반복할 필요는 없지만, target 입력으로 prior 전처리·계수를 fit하거나 업데이트하면 계약이 깨진다.

LOFO 통과 뒤 구성원 사전 screen을 둘지 전체 W40G-S paired 검증으로 바로 갈지 지금 정해야 한다. 구성원 screen 실패를 전체무효 증명이라 하지 않되, 실패 후 같은 사후 농장/온도 gate로 재개하지 않는다. 최종 채택은 온도 기존 DIAG10·EXT10·EXT12 모든 seed 방향 + DIAG p<.025/k·CI상단<0이며, 원CODEX seed726/727 동일성을 독립seed로 세지 않는다. 신선한 BASE/PFN context/layout 확인계약과 과거탐색개수/이번k를 먼저 적는다.

## 4. 결론과 다음 연결

현재 관측은 공식 타농장에 온도 라벨·시간변화가 있다는 것, 인과 해석은 동역학의 일부 전이 가능성 가설, 허용 구현은 공식train-only 변화prior와 대상same-farm prefix 누적 특징, OOF효용은 아직 미검증이다. 전문가의 멀칭·수온·열지연 설명은 N2 계수를 실제 물성으로 해석하는 근거가 아니다.

다음은 동기화 완료 뒤 선행 동일구현 재대조 → 무정답 지원표/변화쌍 계약 → LOFO exact gate·recipe 사전 등록 → 진단 1회 → 통과했을 때만 사전 target CODEX/전체혼합 검증 순서다. 현재 파일로 새fit·후보코드·채택·제출을 했다는 주장 0.
