# 두 h0열 공동 제외 실험 최종 혹독비평

2026-10-07 · 연구실 · 코덱스 독립 최종 비평가. 신규 학습·후보 튜닝·제출·원본 수정 없이 계획, 구현, 완료 receipt, 기존 독립 검산 결과와 주요 점수 CSV를 검토했다. 이번 비평에서는 전수 검산과 tree routing을 반복 실행하지 않았다. 이 문서 작성 시 `실험결과_v1.md`는 아직 없어 보고서 문안의 최종 대조는 본 담당자에게 남긴다.

## 판정

**구현·산술 감사는 PASS이고, TWO_H0_DROP의 성능 확장 screen은 실패다. 후보 채택은 기각한다.** 선택 F47_161의 오류 감소는 재현됐지만 전체 성능 개선으로 연결되지 않았다. 사전 기준대로 이번 설정의 A/B 추가 학습은 하지 않아야 한다. 공개 pass2 보호 플래그도 참이다. 기존 EC14 구성과 제출 상태를 바꿀 근거가 없다.

`PLAN_v1.md`와 `PLAN_ADDENDUM_v1.md`는 main `7f13d0e`에 사전 등록됐음을 git 기록으로 확인했다. `run_v1.py`의 두 열 제외, 남은 열 순서, ET만 30회 적합, 다른 구성원 고정 및 raw 세 시드 평균 뒤 후처리 경로는 계획과 맞는다. 현재 run/score/tree-audit 소스와 trace SHA가 receipt의 값과 일치함도 확인했다. 차단할 새 구현 결함은 발견하지 않았다.

## 통계 문안의 경계

농장별 층화, 관측된 기록일차//5 블록 복원 추출, paired SSE/행수 합, RNG32617·20,000회, 95% percentile 구간이라는 사전 정의와 구현이 일치한다. p_worse=.96435(19287/20000), CI95 변화율 [−.423775%, +9.862782%]다.

따라서 '관측 전체 점수는 악화했고 개선 채택 기준을 충족하지 못했다'가 정확하다. CI에 0이 포함되므로 '95% 수준에서 악화를 확정했다'나 '진짜 악화 확률96.435%'라는 표현은 부정확하다. p_worse는 이 블록 재표집 절차의 악화·동률 비율이다. 20,000회는 독립적인 검증 자료20,000개가 아니다. 여러 실험에 재사용한 공개 DIAG, fold 간 학습집합 중첩, 두 농장만의 자료, 고정5일 블록의 가정은 남는다. 이 절차는 재표집 산술을 검산했으며 새로운 평가자료나 모든 불확실성을 검증하지 않았다.

이번 단일 arm에서 k=1인 screen을 사용한 것은 계획과 맞지만, 기존 여러 탐색을 포함한 연구 전체의 오류율이 통제됐다고 확대할 수 없다. A/B는 이번 설정에서 실행하지 않았으며 실제 평가60일의 효용은 미검증이다. 전체 공개360일 실패만으로 모든 h0 특징, 모든 EC 모델, 향후 다른 설계의 효용까지 무효라고 결론 내릴 수도 없다.

## 지원 혼동의 변화는 좁게 해석해야 한다

fold1·seed7·F47_161 변경 forest에서 평활 ET의 높은EC **학습날** 지원 비율은 기준70.1606%→변경25.0750%로 줄었다. 변경 raw0h는46.8333%, raw 하루평균22.6458%다. 학습날 평균EC≥1인 지원과 시간행 정답EC≥1인 지원은 분모·정의가 다르므로 혼용하지 않는다. 이는 실제 잎 가중합을 통해 이 한 모델·query의 학습 지원이 달라졌다는 근거다.

다른 시드의161 잎지원, F13_231/233 등 악화날의 새 forest 지원 기전은 이번에 추적하지 않았다. 선택161의 지원 변화를 일반61일의 단일 원인, 물리적인 EC 원인, 각 열의 독립 기여로 확대하면 근거 범위를 벗어난다. 두 열 공동 제외와 forest 전체 재구축의 결과이며 같은 시드라도 차원 변경으로 무작위 특징 선택과 분기 전체가 달라진다. 기존 forest에서 두 특징의 기여만 빼낸 효과가 아니다.

원입력400일0h에서 CO2 현재값과 h0값은 관측397일에서 같고 나머지3일은 양쪽 NaN이다. 난방은400일 관측값에서 같다. 그러나 CO2 current median과 h0 median은 fold별7~10 차이가 있어, raw NaN 동일성을 실제 imputed 모델입력 동일성으로 표현하면 오류다. 현재값·누적값·DP1 등 관련정보도 남는다. 난방의1h h0 재구성 항등식은 정보 관련성을 보이며 정보 전체삭제나 예측 동일성을 증명하지 않는다. 선택161의0h 두 입력은 관측돼 있으므로 이 결측 주의점을 그날의 실패 원인이라고 주장해서도 안 된다.

- 기존 `critic_verify_results_v1.json`: 기준30·후보30 캐시, 69120행, 2880일별 점수, 96그룹 점수, 32사례, 후처리와 bootstrap20,000회 재생의 독립 산술검산 PASS. 원 immutable 특징·계절·SG2 함수를 재사용했으므로 이 함수들의 모든 의미·규정 타당성을 새로 독립 구현해 증명한 감사는 아니다.

## 반영해야 할 개선사항

1. 최종 보고서 첫 문장에 '선택161 개선·전체 악화·확장screen 실패'를 함께 쓴다. 선택 사례 숫자 다음에는 F13_231/233 손실과 일반161 제외328일 수치를 붙인다.
2. 후보 기각, 감사 PASS, 통계적으로 악화를 확정하지 못함을 구별한다. p_worse와 CI는 정의를 함께 쓰고 공개46일을 평가60일로 부르지 않는다.
3. 상세지원은 seed7·fold1·161 범위를 제목과 본문에 반복해 명시한다. 지원비율은 학습날/시간행과 raw0h/rawday/평활day를 구별한다.
4. 후속 연구의 중심은 선택161 추가 맞춤보다 다른 일반날의 과대예측 손실이다. F13_231/233의 기존 보존 예측단계와 입력을 읽어 어떤 단계에서 손실이 늘었는지 정리하는 것은 후속 미실행 가설이며, 이 문서에서 원인을 확정하거나 신규 학습을 실행하지 않는다.
5. 추가 열 조합·pass2 적용·gate 문턱·후처리 변경은 이번 단일 arm의 보완이 아니라 새 실험이다. 기존 카탈로그 중복 확인, 새 사전설계와 해당 채택 규칙이 필요하다. 같은 공개 실패 결과로 문턱을 조정해 '개선'이라고 보고하지 않는다.

이번 검토로 새 차단 결함은 확인되지 않았으나 성능기각은 그대로다. 위 문안 제한을 반영한 결과보고서와 인계기록 작성은 root 담당 작업이다.
