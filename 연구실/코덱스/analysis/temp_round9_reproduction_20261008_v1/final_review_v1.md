# 9회차 온도 재현 최종 독립 비평

2026-10-08 · 연구실 · 코덱스 critic. verify_final_v1.py 실제 실행 exit0, 결과 critic_verification_v1.json. 모델 추가학습/평가정답 채점 0.

## 판정

**원패키지의 전체 재학습 실행은 성공했으나 9회차 온도 정확 재현은 실패했다.** 사전 기준인 1440행 온도 소수6자리 전수일치를 만족하지 않는다. 원실행은 1594.468초에 정상 종료했고 BASE/CODEX 및 PFN 문맥1~8 완료 로그를 직접 확인했다. critic 독립 CSV Decimal 비교에서도 1223행이 다르며 최대절대차 0.004595℃, RMS 차이 0.0007201695836166534℃이다. root 비교와 동일하다. 수치가 작다는 이유로 정확 재현 PASS로 변경할 수 없다.

## 독립 확인 증거

- ZIP에서 온도 원본51개 파일 bytes를 직접 읽어 추출본과 SHA 전수 대조했다. 원ZIP/최종 제출CSV/소스/wrapper/공식CSV3개/season2표/공개 체크포인트 해시가 보존됐다. 모델캐시의 유일 체크포인트는 2ab5a07d…이다.
- 온도 CSV1440행 ID 유일성·순서가 ZIP 기준온도CSV 및 실제 submission_14와 같다. ZIP 기준온도값은 submission_14의 온도값과 정확히 같다. 재현 CSV와 NPZ IDs도 전수 일치한다.
- NPZ8×1440 PFN 예측·BASE·CODEX·게이트·혼합예측 전부 유한값이다. 공식 test_X 현재 in_temp로 게이트를 재구성한 값이 전수 같다. 각 행의 PFN8 평균과 혼합식을 math.fsum으로 독립 계산한 원시예측 차이는 최대3.552713678800501e-15이다. NPZ 원시예측을 소수6자리 반올림하면 생성CSV와 전수 같다. 혼합·반올림·CSV 행대응 문제가 이번 차이를 설명하지 않는다.
- 실행환경의 수치패키지 버전은 원requirements와 같다. Python3.12.10은 기준3.12.4와 다르다. 프로젝트 모듈은 추출본code에서 로드됐다. 원모델 파라미터/시드/문맥/소스 변경 증거는 없다.

## 아직 판별하지 못한 원인과 제한

현재 제출 당시 BASE/CODEX/PFN 구성원 원시NPZ가 없어 구성원별 재현차이를 직접 대조하지 못했다. PFN=0인 gate0 행이 동일하면 그 215행에서 BASE·CODEX의 **가중 합계**가 저장CSV 정밀도에서 같다는 증거이나, 전체 BASE/CODEX 각각의 동일성을 증명하지 않는다. PFN 활성 구간의 차이는 PFN 실행환경/배치 민감성과 양립할 수 있지만 다른 구성원 차이의 가능성을 완전히 배제하지 못한다. CPU memory/device/배치가 원인이라고 단정하지 않는다.

온도 README의 결정론 주장(`재학습하면 같은 값`)은 이번 환경에서 소수6자리 수준으로 성립하지 않았다. Python 패치 버전 차이만으로 이를 설명하지도 않는다. 추후 원인 진단은 별도 결과로 남기며 이번 strict 실패 판정을 유지한다.

생성CSV의 EC는 submission_04의 복사 열이다. 이는 9회차 EC 재현이 아니다. 이번 작업으로 플랫폼 온도 점수0.5127의 재계산/추가 temp_v13_checks 규정 검사/새로운 채택 또는 제출 완료를 주장하면 안 된다. 파일 byte도 ZIP 온도기준CSV와 다르다.

결론 보고 권장: “9회차 온도 원코드는 새로 재학습하여 실행할 수 있었다. 제출값과 최대0.004595℃ 차이가 있어 정확 재현은 실패했고, 원인 분리 진단을 진행 중이다.”
