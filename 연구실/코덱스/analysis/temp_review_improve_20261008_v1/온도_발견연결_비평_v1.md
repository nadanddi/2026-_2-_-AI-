# 온도 발견 연결·기존 기각 대조 비평 v1

2026-10-08 연구실 코덱스 독립 비평. 모델 fit·predict·정답 재채점·새 제출 파일 생성 0. 공식 대회자료에서 나온 기존 보고서·카탈로그·로그·코드를 읽어 연결했다. 아래 수치는 원작성자/기존 독립검산 기록에서 인용하며 이번 새 계산이 아니다. 숨김 EC 정답열은 읽지 않았다. 부모 작업의 패키지 감사와 분리된 가설 비평이다.

## 2. 검증기를 해석하는 방법

### 확인한 분할 코드

원 `anal_q1_errors.diag_folds`는 농장별 정답 기록일을 정렬하여 **5개 정답날씩** 묶고 순번을 10fold에 순환 배치한다. 무작위 iid 행분할이 아니다. `common.split_mask`는 해당 농장의 검증 기록일과 ±1 기록일을 학습에서 뺀다. 기록일은 실제 달력 하루와 같지 않으므로 이 버퍼가 실제 출처·달력 독립성을 보장하지 않는다.

TK `world.py`의 EXT10/12는 원 FULL 세계의 `ph_in_temp_3` 하루 최저가 각각 10/12℃ 미만인 날 전체를 holdout한다. FULL은 원 분할 정의 보존에 쓰이고 학습 특징은 MASK로 만든다. 이 검증기가 잘못됐다고 바로 결론낼 수 없지만 **query 특징의 미래 독립성 검사와 FULL 기반 분할 선정의 평가와의 차이**는 별도 항목이다. EXT10⊂EXT12이므로 두 검증은 독립 표본 증거가 아니며, 모두 학습 추위 자료를 통째로 제거하는 외삽 시험이다.

TK EL1는 후반(day≥179) 정답날 56일을 농장별 5개씩 묶어 해당 농장만 제외하고 ±1일 버퍼를 둔다. 다른 농장 정답은 남긴다. 정답이 가까운 평가형 배치를 진단하지만 독립 잠금이나 DIAG·EXT 실패를 덮는 근거가 아니다. EC의 P2LOO/새 TM 기준을 온도 채택 기준으로 옮기지 않는다.

## 4. 기존 기각과 구별되는 후보 두 개 — 실행 승인/채택이 아닌 다음 진단 제안

### N1. CO₂ 파생만 학습에서 결측 처리하는 국소 지원 실험

관측: 최신 거친 30일은 실내–배지 결합이 약하되 센서 원인은 미확정이다. 현재 가중치가 이미 잡음 rank에 반응하고, 6.21은 실내온도·습도·CO₂ 세 채널을 모두 평활해 해로웠다. 학습일 자체를 0.2로 낮추는 RW1과도 다르다.

원인 가설: 신뢰 낮은 CO₂ 및 그 파생값이 잔차트리에서 학습 지원 선택을 방해할 수 있다. 이 가설은 실내온도가 틀렸다거나 거친 날 온도 정답이 틀렸다고 전제하지 않는다.

허용 구현: outer train 입력만으로 고정된 무공급 |ΔCO₂|·AC 정의를 계산하고 해당 학습행의 **CO₂ 관련 원값/파생 그룹만 NaN**으로 한 번 바꾼 CODEX 잔차 모델을 대조한다. 실내온도·습도·물리 Ridge·가중치·BASE/PFN·계절·혼합은 고정한다. NaN 복구 imputer는 outer train에서 fit하고 query는 raw prefix 그대로 사용한다. 학습 전 후보 열 목록/거친 판정시간/인접날 특징 파급범위를 저장해야 한다. 현재 CODEX CO₂ 물리포함 여부와 imputer 경로를 먼저 확인해 ‘잔차만 변경’ 계약을 정확히 써야 한다.

성공 반례/실패 조건: 거친 날 자체에서도 모델이 정확한 경우를 반드시 포함한다. CO₂는 정상 운영 출처 정보일 수 있으므로 삭제가 오히려 정상/추운 날 지원을 잃을 수 있다. F47 연속 무리 효과만 있거나 clean/F13/후반이 악화하면 일반화 근거 약화다. 6.437의 제안 자체는 EC용이었으므로 이것을 이미 새 온도 효과가 발견됐다고 말하지 않는다. **온도 N1 OOF 효용은 미검증**, 카탈로그 전체 완전검색이 아닌 읽은 범위에서 동일 온도 구현 실행을 찾지 못했다.

### N2. 공식 다른농장의 절대 수준을 버린 시간당 변화 prior

관측: 공식 다른49농장 온도 정답은 있지만 온실별 배지–공기 수준 차이가 크고 6.45 절대온도 멤버/절대 prior는 실패했다. 대상 온도의 하루 내부 모양 오차는 여전히 전체 상당 부분이다(TK/W30G 전체 약43~44%; 후반 약24%).

원인 가설: 농장별 절대 수준은 안 옮겨져도 **같은 기록일 안 다음 배지 변화의 공기·일사 반응** 일부는 옮겨질 수 있다. 다른농장의 수준을 대상 하루 수준으로 강제로 가져오지 않는 가설이다. F32 근권가온 차이는 선행 반례이며 처음부터 제외 여부를 사전 고정해야 한다.

허용 구현: 공식 other-farm train의 같은날 연속 h−1→h만 사용하여 Δsub_temp를 target, 현재·직전 실내온습도/CO₂·그 차이와 현재시각을 predictor로 하는 **하나의 고정 변화 prior**를 학습한다. h=0과 기록불연속은 정의하지 않는다. 대상 query의 같은농장 현재·직전 입력으로 prior를 평가하고 누적 변화 특징 하나만 CODEX 잔차모델에 추가한다. 원 BASE/PFN/물리 기준선/계절/가중치/혼합은 유지한다. 타농장 공개 정답은 모델 학습에만 쓰고 query 특징에 타농장 입력을 직접 연결하지 않는다. 이 방식에 필요한 query h−1 입력이 MASK에서 없는 경우 flag·NaN 규칙도 사전 고정한다.

먼저 필요한 무효화 진단: 원 other-farm별 leave-one-farm-out에서 변화 부호·증분 MSE가 단순 ‘이전 변화0/공기변화’보다 못하면 대상 전체fit을 하지 않는다. target은 Δ형이어도 lagged sub_temp를 predictor에 넣으면 query에서 unavailable이므로 금지다. 노이즈 증폭, 농장간 반응 차이, 대상의 나쁜 날이 level 문제라는 세 실패 가능성이 있다.

기존과의 차이: 6.45는 절대온도 전이/절대 prior, T-F1은 출력증분을 고정 .5×공기변화에 당기는 후처리, D1은 대상 학습의 증분손실 변경이었다. N2는 공식 타농장 학습 target을 시간당 변화로 제한한 prior 특징이다. **이 차이가 이득을 보장하지 않으며 N2 OOF 효용 미검증**이다. 기존 물리/현재시각 단독모델 실패와도 반드시 대조한다.

## 5. 과거 cache 재사용의 조건

TK/VW1 cache는 진단을 출발할 재료지만 현재 패키지 exact baseline으로 바로 부를 수 없다. 재사용할 때 적어도 다음을 전수 비교해야 한다.

1. row_id 순서·outer train/query ID·±1 purge·400일/9600행 범위·MASK 생성 경로 및 특징열 **순서까지** 일치.
2. 계절은 TK의 `day` 제외 후 `season` 추가와 패키지의 **기존 day 열 자리 값 교체**가 다를 수 있다. 트리/PFN 입력위치 민감성이 있으므로 이름·값 집합 동일만으로 호환 인정 금지. 저장 source와 matrix 해시를 비교한다.
3. BASE cache7/101 각각과 패키지3seed7/101/2024 평균은 다르다. CODEX726/727 실질동일성도 새환경에서 확인 필요. PFN CUDA vs package CPU, context1~8/17~24, weighted RNG subset·subset행 순서·modelseed·checkpoint·n_estimators4·float32·query batch가 모두 계약이다.
4. W30G 식 `(.4+.1g)BASE+(.6−.4g)CODEX+.3gPFN`은 W40G-S 식 `.4BASE+(.2+.4(1−g))CODEX+.4gPFN`과 다르다. 원시 구성원부터 현재 혼합을 계산해야 한다. 이미 혼합된 W30G 출력은 전체 current baseline으로 재사용 불가.
5. 다른 후보로 바뀐 학습행이 PFN weighted sample에 영향이 있으면 PFN cache를 고정하는 것은 전체 현재 구성 변경 효과가 아니라 **CODEX만 바꾼 조건부 실험**이다. 그 조건을 사전 명시해야 한다.
6. 새 baseline 재현을 동일프로세스에서 최소 첫 fold 확인하고, 순수 postprocess 실험이어도 멤버ID/recipe/SHA를 검증한다. 현재 raw 재현의 .000720℃ 차이를 허용오차로 silently 흡수하지 않는다.

성능 진단을 위해 일부 원시구성원 cache만 이용하는 것은 가능하지만, 호환성이 증명되지 않은 cache 위 작은 이득으로 W40G-S 개선을 주장하면 안 된다. 새 seed/layout 확인은 원래 생성되지 않은 해당 baseline·candidate OOF를 함께 만들어야 하며 원 cache 한쪽만 새환경으로 교체하지 않는다.
