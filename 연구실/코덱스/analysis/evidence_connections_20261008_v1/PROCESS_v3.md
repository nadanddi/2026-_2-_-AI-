# 발견 연결과 해석 갱신 — 실행 규칙 v3

**사용자 지시:** “해당 전수조사 처럼 기존 발견을 서로 연결하고 해석을 갱신하는 과정을 강화해보자.”

EC 분석·새 실험·결과 답변 전에 관련 카탈로그와 작업일지를 검색하고, 관측·원인·허용 구현·성능 효과를 구분한 현재 해석을 확인한다. 새 결과가 기존 해석을 지지/수정/반박/범위 제한하는 관계와 근거를 기록한다. 그래야 이미 알던 사실의 재발견, 옛 해석의 반복, 실험 실패를 정보 부재로 일반화하는 일을 줄일 수 있다.

## 1. 작업을 시작할 때

1. `공용/HANDOFF.md`에서 최신 현재해석표 경로를 확인한다. 최초 검토완료 표는 이 폴더 `현재해석_v3.md`다. 표는 **EC 핵심8개 주제의 시작점**이며 전체 카탈로그를 대체하지 않는다.
2. 관련 주제의 한국어·변수명·실험명을 2~3개 사용해 카탈로그와 일지를 검색한다. 번호가 가까운 결과만 보지 말고 실험명·핵심 주장으로 후속 검산/정정/기각을 끝까지 찾아 연결한다. (이번 FP1→FC0/1→FC2→FC3에서 FC3 누락을 독립검토가 발견했다.) “새 방법”이라는 표현 전에 **기존 관측 / 기존 시도 / 당시 정의 / 이번 차이**를 적는다.
3. 번호만으로 항목을 식별하지 않는다. 번호+짧은 제목+근거 경로를 함께 사용한다. 현재6.205처럼 중복 번호가 있다. 6.207은 구조 항목을 C6.205로 부르는 직접 정정이고,6.421은 다른 충돌의 번호 대응표다. 미확인 번호·누락 파일은 근거 없음으로 표시한다.
4. 조사에 사용할 데이터는 공식 배포 자료와 허용 출처가 확인된 파생물로 한정한다. 금지 외부 자료의 동·센서 정답표를 연결 근거로 가져오지 않는다.

## 2. 핵심 주장마다 네 가지를 따로 판정

| 항목 | 확인할 것 | 예시 |
|---|---|---|
| 관측 | 실제 계산·표본에서 무엇이 보였는가 | CO₂ 거친 집단의 학습·평가 비율 차이 |
| 원인 해석 | 그 관측을 무엇이 만들었는가, 다른 설명은 남는가 | 다른 센서인지 같은 센서 교란인지 미식별 |
| 허용 구현 | 현재·이전 입력/MASK/공개 학습자료로 재현 가능한가 | 하루 전체 진단을0시 특징에 쓰면 안 됨 |
| 성능 효과 | 정확히 어떤 구성·실험이 사전 기준을 통과했는가 | 가중치0.2 안은기각, 모든 잡음처리가 기각된 것은 아님 |

상태는 **확인 / 제한적 지지 / 미확인 / 해당 구현 기각 / 대체된 해석**으로 기록한다. 이 상태를 실제 데이터 생성의 확정이나 후보 채택으로 오인하지 않는다. 채택은 기존 `skill-not-luck.md` 규칙을 그대로 따른다.

## 3. 비교 전에 정의가 맞는지 확인

중요 수치에는 최소한 데이터 출처, 대상 농장, 입력일/공개 정답일,1·2차 구간, 모델 구성/시드, 검증기, 판정 문턱, 지표 단위를 남긴다. 해당 없는 항목은 명시한다.

- 400입력일과360공개 정답일을 구분한다.
- RMSE/MSE/SSE몫, Pearson/Spearman, 실패 여부/과대편향 문턱을 구분한다.
- 현재EC14/옛R3S/계절R3+DP1을 구분한다.
- 사후 정답으로 고른 집단, 실제 달력/동의 부재, 관측 부족, 중복fold·공유시드·같은날 재사용을 표시한다.
- 다른 정의의 결과는 **숫자를 합치지 않고 조건 차이**로 연결한다. 원문 근거가 없어 정확 재현할 수 없으면 그렇게 적는다.

## 4. 새 결과가 나오면 연결표에 추가

관련 옛 주장을 찾고 아래 네 관계 중 하나를 붙인다. 명확한 관계가 없으면 “관련 있으나 비교 불가”라고 적고 비교를 강제하지 않는다.

| 관계 | 조건 |
|---|---|
| 지지 | 같은 조건의 반복·독립 대조가 해당 주장에 부합 |
| 수정 | 더 구체적인 설명 또는 정의로 바뀜 |
| 반박 | 비교 가능한 조건에서 명제와 양립하지 않는 결과가 나옴 |
| 범위 제한 | 특정 농장·구간·모델·구현에만 성립, 일반화는 불가 |

각 연결에는 양쪽 항목 번호+짧은 제목, 관계 이유, 조건 차이, 지금 쓸 문장, 더는 일반화하면 안 되는 문장을 남긴다. 새 데이터가 없는 정리 작업은 새 실험 증거로 세지 않는다.

## 5. 현재 해석을 새 버전으로 갱신

실험 코드·결과·옛 카탈로그 항목은 보존한다. 내 폴더에 현재해석_v2.md처럼 새 버전과 변경 이유를 만들고, 공용 카탈로그에는 **정정/연결 항목을 새 번호로 추가**한다. HANDOFF에 최신 경로를 연결한다. 이전 버전은 최신 결론으로 인용하지 않는다.

표가 바뀐 날은 어떤 옛 표현이 대체됐는지, 아직 열린 대안은 무엇인지, 실험 우선순위가 어떻게 바뀌는지를 작업일지에 적는다. 단순히 번호 목록을 늘리는 것으로 끝내지 않는다.

## 6. 실험·답변 전 마지막 확인

- 관련 선행 발견과 기각·정정 항목을 확인했는가?
- 같은 정의를 비교하고 있는가? 다르면 차이를 적었는가?
- 관측에서 원인·허용 구현·효용으로 건너뛴 문장은 없는가?
- 성공 반례와 다른 농장/시드의 결과를 포함했는가?
- 기존 실패와 이번 가설의 차이를 설명할 수 있는가?
- 현재 해석표의 해당 문장과 답변이 일치하는가?
- 아직 미검증인 제안을 완료된 결과처럼 적지 않았는가?

모델 실험의 계획·중간·최종 독립 비평과 사전 기준은 기존 규칙을 유지한다. 문서 연결만 하는 작업으로 과거 미완료 비평을 완료로 바꾸지 않는다. 관측 부족이 있는 이상치 후보는 별도 목록으로 남기되 정답 오류 확정·라벨 수정과 구분한다.

## 바로 사용할 기록 틀

```text
주장 ID / 제목:
관련 선행 항목(번호+제목+경로):
기존 관측 / 기존 시도 / 당시 정의 / 이번 차이:
수치의 조건(자료·표본·구간·모델·시드·검증기·문턱·단위):
관측 상태 / 원인 상태 / 허용 구현 상태 / 효용 상태:
지지·수정·반박·범위 제한(비교 불가라면 이유):
현재 사용할 해석 / 대체되는 옛 해석:
성공 반례·열린 대안 / 다음 검증으로 가를 질문:
실제로 수행한 검산·비평 / 남은 한계:
```

이 규칙은 이번 요청으로 확정한 작업 방식이다. 메모리 도구 연결이 없어 저장소의 공용 메모리 목록과 HANDOFF에 경로를 남긴다. 실행 승인이나 제출 기준을 추가로 만들지 않는다.
