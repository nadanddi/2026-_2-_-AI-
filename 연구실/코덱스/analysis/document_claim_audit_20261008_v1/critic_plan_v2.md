# 계획·실행 전 코드 독립 비평 v2

검토: PLAN_v2_addendum.md, audit_v2.py 전체. 읽기만 수행했고 모델 학습/채점은 0회다.

## 첫 단계 판정

**첫 단계 실행을 차단할 치명적인 자료 범위 위반은 확인하지 못했다.** 공식 train_X/test_X/train_y 경로만 사용하며 train_y는 공개 ID 분기 후 float 변환한다. 허용 ID는 기존 preparation query 8640개에서 가져오고 train/query 분리와 기존 BASE receipt/소스/모델 SHA를 검증한다. test 정답·외부 출처표·원자료 경로의 신규 읽기는 없다. 각 시드 공개 ID 전수 존재 및 정답 일치 확인이 있다. R1/R2 유효성 미달은 중단하도록 보완됐다.

다만 이는 소스 검토 판정이며 실제 실행 성공, 각 저장 산출물의 provenance PASS, 수치 정확성까지 확인했다는 뜻은 아니다.

## 첫 단계 결과를 보기 전에 또는 해석 전에 고칠 항목

1. **K2 명칭:** 코드 K2는 h3~23 EWMA 실내온도와 배지온도의 날별 절편 회귀 잔차다. 당초 '같은 시각 선형회귀'가 원실내온도를 뜻했다면 정의가 달라졌다. EWMA 버전으로 고정했다는 사실을 계획/보고서에 명시하고 K1과 같은 원인 교란이 남음을 적는다. 원실내온도/배지온도 완전관측 마스크 대신 EWMA 유한성을 사용하므로 원입력이 NaN인 시각도 EWMA가 유한하면 들어간다. 실제 결측이 있으면 공통 원관측 마스크를 적용하는 새 버전이 필요하다.
2. **유한값과 행 타입:** seed별 ID 집합은 안전하게 검사하나 arm=BASE와 prediction/sub_ec/sub_temp 전수 finite는 명시 assert가 없다. manifest 작성 전에 확인하는 편이 좋다. pandas sum이 NaN 오차를 무시하고 n=24 분모를 유지하면 오차가 낮아질 수 있으므로 prediction finite는 중요하다.
3. **provenance receipt:** 과거 검산 json의 해시를 manifest에 남기는 것과 status PASS/범위를 검토하는 것은 다르다. 최종에는 baseline/PFN 각 receipt 상태와 대응 원자료 범위 확인 근거를 인용한다. src/receipt 해시가 통과해도 원문 모델의 동일성을 뜻하지는 않는다.
4. **K4:** in_temp↔in_hum 상관 K4가 코드에 추가돼 있으나 계획에 없다. 이미 코드를 실행 전에 고정한 보조 진단으로 명시하거나 해석에서 제외한다. 좋은 상관 결과만 골라 센서 설명 근거로 만들지 않는다.
5. **결측 통계 범위:** raw_training_missing은 두 농장을 합친 평균이다. 농장별 마스크·공개/전체 개수와 혼동하지 않게 표시한다. 뒤에서 다른49온실의 CO₂/NaN 통계까지 검증했다고 쓰면 안 된다.

## 후속 실행 전 사항

- **구조적 비교 불능:** 연속 2개를 A/B로만 정의하면 인접번호의 같은 역할 경계는 원칙상 발생하기 어렵거나 0개다. 0.52 대 1.39의 같은/다른 실제 동 비교를 이 설계로 재현할 수 없다고 명시해야 한다. 0개를 버그로 여기고 정답을 보며 역할을 재정의하면 안 된다.
- **역할 CV 계획:** 입력10종의 정확한 열 이름, 두 입력모드, class0/1, random_state, fold 생성 순서, fold별 AUC와 pooled OOF AUC 중 무엇을 보고할지 고정한다. 같은 외기묶음이 train/val에 나뉘지 않게 pair-group을 assert한다. h0는 해당 시각 입력의 진단일 뿐 실제 동 분류가 아니다. 하루평균은 사후 전체일 입력임을 유지한다.
- **작업량 표현:** audit_v2 docstring의 'no fitting models', manifest fit=0은 이 스크립트 예측모델 신규학습 없음이라는 범위에서는 맞다. 실제 진단 회귀 lstsq가 수행되며 후속 logistic 분류 학습은 별도 횟수로 반드시 기록한다. 전체 작업 '학습 0' 주장은 금지한다.
- **후속 빈집합:** structure()는 pairs/cross_farm/roles가 비면 빈 DataFrame 열 접근에서 실패한다. 실제 데이터가 비지 않더라도 계획상 NA 처리와 코드가 아직 일치하지 않는다. 빈집합은 정상 미확인 결과로 저장할 수 있어야 한다.
- **통계 해석:** cross_farm은 외기묶음 농장평균이므로 실제 날짜/동별 상관이나 동별 독립 사건이 아니다. persistence는 선택된 이전 가장 가까운 역할의 순서상 상관이고 비슷한 간격의 counterfactual이 아니다. boundary 출력에 same_weather를 유지하는 것은 적절하다.

중간 비평은 첫 실행 manifest와 유효 차분·공개 행 수·finite 검사·비율 및 손실 표를 보고 수행한다. 현 단계는 실행 전 읽기 검토만 완료됐다.
