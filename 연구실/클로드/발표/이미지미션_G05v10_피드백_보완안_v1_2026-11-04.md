# G05v10 이미지 미션 보완안 v1

2026-11-04 · 연구실 클로드 · 목표 G07. 정형 미션 보완안 v2(코덱스)와 같은 틀(화면 교체 문구, 대사, 근거 배치)로 이미지 부분(제2부 표지, 2.1~2.4)을 점검하고, 제안마다 근거와 적절성·타당성을 판정했다. 장 번호는 G05v10 기준.

## 정형 피드백에서 가져온 점검 질문
정형 보완안이 짚은 문제를 이미지 쪽에 같은 질문으로 다시 던졌다.
1. **같은 숫자가 제목·그래프·표에 여러 번 나오나?** (정형: 결과 요약 수치 중복)
2. **단위·표기가 장마다 같은가?** (정형: 이미지 97%, 증가율 %)
3. **코드 성격의 이름·전문 용어가 화면에 남았나?** (정형: 물리식 A·B → 무엇을 보는지로)
4. **장치가 어느 순서에서 작동하는지, 무엇이 무엇에 쓰이는지 화면만으로 읽히나?** (정형: 온도 보정에 쓰는 EC가 어느 단계인지)
5. **그래프가 무엇을 집계했는지, 방향(높을수록/낮을수록)이 분명한가?** (정형: 막대 이름과 집계 범위)
6. **현장 조건을 말할 때 맞는 숫자를 쓰나?** (정형: 실측이 있을 때만, 쓸 수 있는 예측이 있을 때만)
7. **장 구성이 정형과 같은가?** (정형: 구분 표지를 첫 장에 합침)

## 1. 제2부 구분 표지 → 2.1에 합치기

- **문제(7):** 정형은 G05v10에서 구분 표지를 1.1에 합쳤는데 이미지만 표지가 남아 있다. 표지에는 "다음은 이미지 미션입니다" 한 문장뿐이라 넘김 1회와 5초를 쓴다.
- **제안:** 2부 표지를 없애고 2.1 꼬리표를 "2.1 이미지 미션 · 문제와 전략"으로. 2.1 화면 맨 위에 과제 한 줄: "과제: 딸기 시설재배 사진 한 장이 실제인지, 생성·편집된 가짜인지 판별. 대회는 공개 샘플 21장만 제공".
- **대사:** "다음은 이미지 미션입니다. 딸기 사진 한 장이 실제인지, AI로 만들거나 고친 가짜인지 가려냅니다. 대회가 준 사진은 공개 샘플 21장뿐이었습니다. …"
- **근거:** 이미지 README 82줄(공개 샘플 21장, 학습에 넣지 않음).
- **판정: 채택.** 정형과 구성이 맞고 시간 5초 + 넘김 1회가 준다. 21장은 학습에 넣지 않았으므로 "정답 붙은 학습 사진이 없었다"는 제목과도 어긋나지 않는다.

## 2. 2.1 문제와 전략

- **문제(3):** '형식 맞춤(768×1024 JPEG)'이 왜 필요한지 화면에 없다. 처음 듣는 청자는 크기를 왜 맞추는지 모른다.
- **문제(4):** 아래 줄 "기본 판별기 학습: 실제 2,467장 / 가짜 7,124장"은 위 1단계의 152,043장과 바로 비교되어 "15만 장 중 왜 2,467장만?"이라는 질문을 부른다. 실제·가짜 수가 3배 차이 나는 것도 설명이 없다.
- **교체 문구:**
  - 3단계 "형식 맞춤" 본문: "대회 공개 샘플과 같은 크기·압축으로(768×1024 JPEG)".
  - 아래 줄: "기본 판별기 학습: 실제 2,467장, 가짜 7,124장(실제와 가짜 유형이 같은 비중이 되게 가중)".
- **질의응답(대본):** "15만 장 중 일부만 쓴 이유?" → 원천 사진은 원본 대조 DB에 모두 쓰고, 판별기 학습에는 가짜를 만든 원본 묶음 위주로 골랐습니다. 학습 가중은 실제 0.5, 가짜 6유형 균등입니다.
- **근거:** README ④ 표 첫 줄(가중 = 실제 .5 / 6유형 균등), ⑤ 5행(공개 21장 실측 형식과 같음).
- **판정:** 형식 맞춤 문구 **채택**(README와 일치). 가중 괄호 **채택**(사실 그대로, 짧음). '일부만 쓴 이유'의 질의응답 답은 **보류** — 고른 기준(원본 묶음 위주)을 README에서 한 줄로 확인하지 못했다. 질의응답에는 "원천 사진 전체는 원본 대조 DB에 썼고, 학습 장수는 README ④"까지만 넣는다.

## 3. 2.2 모델 구성

- **문제(3):** 화면에 'CLIP', '잡음·선명도 등 38개', '부분 스타일', '국소 조각'이 그대로 있다. 정형 1.4에서 모델 이름 대신 '무엇을 보는지'로 바꾼 것과 맞지 않는다.
- **문제(4):** 점선 상자가 맨 아래 따로 있어 장치가 언제 작동하는지 안 보인다. 실제 순서는 기본 판별 → 원본 대조 → 추가 판별(3종) → 정밀 원본 대조 → 저장 형식 조건 → 게이트 안 추가 판별기(README ⑤ 1~7)라 장치가 판별 사이사이에 끼어 있다. 화면만 보면 '마지막에 한 번 거르는 장치'로 읽힌다.
- **교체 문구:**
  - 기본 판별 본문: "사진에 무엇이 찍혔는지(사전학습 이미지 모델)\n잡음·선명도 같은 통계 38개\n→ 두 판단의 확률 평균".
  - 유형별 추가 판별기 본문: "일부 영역만 새로 그린 가짜\n일부만 화풍을 바꾼 가짜\n작은 조각을 고친 가짜".
  - 그림 7 캡션: "그림 7. 판별 순서. 점선 장치는 판별 중간중간에 끼어 작동하고, 조건이 맞지 않으면 건너뜀(현장 사진에서는 거의 꺼짐)".
- **노트:** 사전학습 이미지 모델 = CLIP ViT-L/14·B/16, 추가 학습 없음. 세 판별기 = E_pg·E_ps·E_L. 게이트 안 판별기 H·E_gr·E_gpt는 화면의 '일부 판별기'.
- **근거:** README ④ 표, ⑤ 1~7행, 81줄(CLIP 가중치).
- **판정: 채택.** 용어는 뜻이 같은 쉬운 말로만 바꿨다. '작은 조각을 고친'은 E_L(국소 조각 되붙임·국소 재생성 학습)의 뜻과 맞다(README ④ 넷째 줄 '되붙임 7판'). 순서를 그림 자체에서 바꾸는 안(점선 상자를 화살표 사이에 넣기)은 **기각** — 7단계를 다 그리면 글이 늘고, 캡션 한 줄로 오해를 막을 수 있다.

## 4. 2.3 검증과 개선 과정

- **문제(1):** 같은 숫자가 세 번 나온다. 제목 "0.94~0.96", 그래프 96.2·94.7·94.4, 표 0.962·0.947·0.944. 정형 결과 요약에서 지적된 중복과 같다.
- **문제(2):** 단위가 섞였다. 제목·표는 0.94(비율), 그래프는 96.2(%), 결과 요약은 97%, 2.4는 %p. 표의 '운영진 시험 정답률 0.97'도 결과 요약 97%와 표기가 다르다.
- **교체 문구:**
  - 제목: "학습에 쓰지 않은 검증 사진 묶음 3개에서 균형 정확도 94~96%".
  - 왼쪽 그래프를 빼고 표를 넓힘(그래프와 표가 같은 값). 표 열: 묶음 / 실제·가짜 장수 / 같은 원본의 가짜가 학습에 / 균형 정확도(%). 값 96.4, 96.2, 94.7, 94.4, 운영진 시험 행은 "정답률 97%(다른 지표)".
  - 왼쪽 빈자리에 읽는 법 두 줄: "균형 정확도 = (실제 정답률 + 가짜 정답률) ÷ 2. 실제와 가짜 수가 달라도 한쪽으로 쏠리지 않는 지표" / "모델 학습: 안 씀 · 후보 선택: 씀 · 새 농장 성능: 미검증".
- **대사:** 그대로(이미 '94~96%'와 '다른 지표, 다른 사진').
- **근거:** 2.3 노트(R2 .9637, R3 .9617, R4 .9468, R5 .9436), README 156줄.
- **판정: 채택.** 값 자체는 바뀌지 않고 표기만 %로 통일. 그래프를 빼도 표에 같은 값이 있어 정보 손실이 없다. 그림 번호는 8이 비므로 2.4 그림을 8·9로 당긴다.

## 5. 2.4 현장 적용 조건과 한계

- **문제(6) — 가장 중요:** 오른쪽 그래프는 **제출 모델**(장치가 켜진 판)의 오탐률이다. 그런데 장(章) 제목과 왼쪽 그림 9 캡션은 "둘 다 끔 = 현장 사진에 가까운 조건"이라고 말한다. 현장 사진에는 AI Hub 원본이 없어 원본 대조가 거의 작동하지 않으므로, 현장 조건에 가까운 숫자는 '둘 다 끈 판'의 오탐률이다. 노트의 ABL2 값으로 보면 둘 다 끈 판은 WebP 37.5 → **75.8%**, 색 덜 줄인 JPEG 5.4 → 13.8%, 다른 축소 2.1 → 8.2%, PNG 2.1 → 3.3%로 오히려 나쁘다(선명화만 90.7 → 86.5%). 지금 대사 "WebP로 저장하면 37.5%를 가짜로 봤습니다"는 현장 위험을 작게 보이게 한다.
- **문제(5):** 한 장에 방향이 반대인 그래프 두 개(높을수록 좋음 / 낮을수록 좋음). 대사에서 매번 방향을 말해야 한다.
- **문제(3):** '색 덜 줄인 JPEG'는 뜻이 잘 안 온다(4:4:4 저장).
- **교체 문구:**
  - 오른쪽 그래프를 두 계열로: "제출 모델" / "둘 다 끔". 제목 "다시 저장·처리한 진짜 사진을 가짜로 본 비율(%) · 낮을수록 좋음".
  - 라벨: '색 덜 줄인 JPEG' → '색 정보를 덜 줄인 JPEG'.
  - 그림 10 캡션: "그림 10. 검증 1의 실제 사진 429장을 다시 저장·처리해 넣음. 둘 다 끔이 현장에 가까운 조건".
  - 맨 아래 문장: "현장 사진으로 다시 학습·검증하기 전에는 선명화·WebP 사진을 판별에 쓰기 어렵다."
- **대사:** "대회용 장치를 모두 끄면, 왼쪽처럼 균형 정확도가 2.7~3.0%p 내려갑니다. 오른쪽은 진짜 사진을 다시 저장해 넣었을 때 가짜로 본 비율이고, 낮을수록 좋습니다. 장치를 끈 판에서 선명화한 사진은 86.5%, WebP는 75.8%를 가짜로 봤습니다. 그래서 현장 사진으로 다시 학습하고 확인해야 합니다."
- **근거:** 2.4 노트의 ABL2 처리 변형 값(제출 → 둘 다 끔), `연구실/클로드/발표/G00_자료점검_2026-11-03.md` 2절, 그림 9 캡션.
- **판정: 채택.** (가) 숫자는 이미 노트에 있는 ABL2 결과라 새 실험이 필요 없다. (나) '현장에 가까운 조건 = 둘 다 끔'은 덱이 이미 쓰는 정의라 오른쪽 그래프도 같은 기준이어야 앞뒤가 맞는다. (다) 제출 모델 값도 남겨 두어 대회 조건과 현장 조건을 비교할 수 있게 한다. 이 제안은 모델 성능을 더 나쁘게 보이게 하지만, 'no-exaggeration' 원칙과 운영위 현장 적용성 항목에서는 이쪽이 정직하다. **주의:** 둘 다 끈 판이 WebP에서 더 나쁜 이유(원본 대조가 처리된 진짜 사진을 진짜로 확정해 주던 효과)는 따로 재지 않았으므로 대사·노트에서 이유를 단정하지 않는다.
- 방향이 반대인 두 그래프를 두 장으로 나누는 안은 **기각** — 본문이 한 장 늘고 시간도 는다. 그래프 제목에 방향을 넣고(이미 있음) 대사에서 한 번만 말한다.
