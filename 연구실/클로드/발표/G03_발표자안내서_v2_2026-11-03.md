## 2. 정형 미션: 무엇을 했나

### 2.1 문제의 핵심 (1.1, 1.2)
- 자료를 보니 **하루치 기록(24시간)이 순서 없이 섞여 있고**, 같은 재배 동(棟)이 F13과 F47 두 이름을 오갔습니다. 확실히 이어지는 짝 190쌍 중 40쌍(21%)이 이름을 바꿨습니다(카탈로그 7.072).
- 오차를 뜯어 보니 **절반 가량이 '그날 하루가 통째로 어긋나는' 몫**이었고(0.49), 그날 입력으로는 설명이 안 됐고(R² −0.64), **어제 어긋나면 오늘도 어긋났습니다**(상관 0.64).
  - 집계 대상: 학습 자료의 온실 **51곳을 모두 분석**했고, 위 세 수치는 그중 **F13·F47을 뺀 다른 49곳의 중앙값**입니다(카탈로그 6.997, `집/클로드/research/dlv1_day_level_offsets_all_farms_v1.py`의 `O = S[~S.farm.isin(["F13", "F47"])]`).
  - 우리 두 온실: F13 0.49 / −0.18 / 번호 이웃 상관 0.15, F47 0.53 / −0.12 / 0.29. F13·F47은 기록이 섞여 '번호 이웃'이 진짜 어제가 아니라서 상관이 낮게 나옵니다 — 그래서 진짜 어제를 찾아야 합니다.
  - 51곳 전체 중앙값은 0.49 / −0.57 / 0.63(검수자 계산, `dlv1_v1_table.csv`)으로 결론은 같습니다.
  - ⚠ 덱 1.2의 표 2 캡션 '학습 자료 온실 51곳(의) 중앙값'은 틀린 표기입니다('다른 49곳'). G04에서 고칩니다.
- 그래서 핵심 아이디어: **같은 동의 진짜 '어제'를 찾아 이어 붙인다.** 현장에서는 달력으로 어제가 바로 정해지므로 이 아이디어 자체는 현장에서도 그대로 쓸 수 있습니다.

### 2.2 모델 구성 (1.3) — 그림
- 덱 그림: `연구실/클로드/local/발표렌더/G02v1/slide_06.png`(1.3, 세 단계와 β_h 곡선). 아래는 같은 내용을 글로 풀어 그린 것.
```
[1단계 기본 예측]                 [2단계 어제 이어 붙이기]               [3단계 추운 행 보정]
세 모델을 섞음                     어제 23시 실측이 있으면 → 앵커          EC가 높은 날의 추운 시간대에
 BASE 0.4 + CODEX + TabPFN          (어제 값으로 오늘을 끌어당김)           +0.25℃까지 조금 올림(TX3)
 8℃ 이하에서는 TabPFN 빼고 CODEX로   실측이 없으면 → 사슬
                                    (어제의 예측을 이어 받음)
```
- EC도 같은 구조: 기본 예측(R3 + TabPFN + 하루 수준 보정 HR5) + 어제 EC 앵커(정형 README ② EC).
- 모델 이름 풀이:
  - **BASE**: 물리 선형식 위에 LightGBM(잔차 0.65)·Ridge(0.25)·Nystroem 커널(0.10)을 섞은 모델, 시드 3개 평균(정형 README 90줄). **CODEX**: Ridge 물리 기준선 + LightGBM 잔차 모델, 시드 2개(같은 README 93줄). **TabPFN**: 표 자료용으로 미리 학습된 공개 모델(Prior Labs, 미세조정 없음, 가중치 사용 조건 있음 → A1·A6).
  - 섞는 식(따뜻할 때 0.4·0.2·0.4, 8℃ 이하에서 TabPFN 몫이 CODEX로 넘어감): `pred = 0.4·BASE + (0.2 + 0.4(1−g))·CODEX + 0.4·g·TabPFN`, `g = clip((실내온도 − 8)/2, 0, 1)`(같은 README 97줄).
  - **링커**: 섞인 기록 중에서 '같은 동의 어제'를 찾아 주는 짝 찾기 모델.
  - **앵커**: 어제 23시 실측과 오늘 예측의 차이 일부를 오늘 각 시각에 더하는 보정. 더하는 비율 β_h는 새벽에 크고(0시 약 0.76) 낮에는 작음(약 0.13~0.24)(1.3 그림 3).
  - **사슬**: 어제 실측이 없을 때 어제의 마지막 예측을 줄여서(0.9·exp(−h/8)) 이어 받음.
