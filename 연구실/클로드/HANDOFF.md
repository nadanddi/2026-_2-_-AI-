## 1. 데이터 구조 — 반드시 알아야 할 것

### 1.1 test는 같은 온실의 잘라낸 날짜 블록

test 1,440행 = **F13, F47** 두 온실 × 30일 × 24시간. 두 온실 모두 학습에도 있습니다.
블록 배치는 두 온실이 동일하고 F47이 2일 앞섭니다.

```
F13 (일차 8~245)  T=학습 E=평가 .=없음
183일차부터: T.EEEEE.TTTTTTTT.EEEEEEEEEE.TTTTTTTT.EEEEEEEEEE.TTT.EEEEE.TTTTT
             (블록 길이 5,10,10,5일 / 경계마다 1일 버퍼)
```

**경계의 1일 버퍼가 이 문제의 핵심 제약입니다.** test 행에서 가장 가까운 정답까지 최소 25시간, 중앙값 69시간입니다.

| test 행 기준 가용성 | 비율 |
|---|---|
| 입력 X의 t−1 | 99.44% |
| 입력 X의 t−24 | 86.67% |
| **정답 y의 t−1 / t−24** | **0.00%** |

→ **정답 lag 피처는 절대 쓸 수 없습니다.** 넣으면 CV가 극적으로 좋아지고 실제 제출은 망합니다.

### 1.2 컬럼 가용성이 온실마다 다름

| 컬럼 | 보유 온실 |
|---|---|
| `in_temp` `in_hum` `in_co2` | 51개 전부 |
| `in_rad` | 48개 — **F13·F47·F32 제외** |
| `out_*`, `act_vent/circfan/co2` | F13, F32, F47 |
| `act_shade/thermal/heating/fog`, `out_hum` | F13, F47 |
| `act_side/valve/cool/pump` | F32만 |

→ **test에서 100% 결측인 5개: `in_rad`, `act_side`, `act_valve`, `act_cool`, `act_pump`.**
실사용 입력은 19개 중 **14개**. 센서 부재이므로 대치 불가.

`act_pump`(양액 펌프) 부재가 EC 예측의 근본 한계입니다. 문헌이 공통으로 지목하는 배지 EC의 1순위 결정 변수가 급액량인데 데이터에 없습니다.

### 1.3 EC 정답은 F13·F47에만

`train_y.sub_ec`의 96.85%가 결측인데, 산발적 결측이 아니라 **온실 단위 전부/전무**입니다.
F13 4,800행 + F47 4,800행 = 9,600행, 두 온실 내부 결측은 0건.

### 1.4 라벨 해상도가 온실마다 다름

- F13·F47: `sub_temp` 0.01 단위 (고유값 1,842개), `sub_ec` 0.001 단위
- **나머지 47개 온실: `sub_temp` 정수값 100%** (1℃ 반올림). 예외는 F32(29%), F37뿐.

→ 49개 온실을 온도 학습에 섞으면 반올림 노이즈가 평가 대상(0.01 해상도)에 유입됩니다.

### 1.5 train_X에만 인위적 오염이 있음

문제설명서 4절: *"일부 학습 입력에는 결측과 통계적으로 복원·변형한 값이 포함... 평가 입력에는 인위적인 복원·변형이나 추가 결측을 적용하지 않았습니다."*

F13/F47 학습 구간 vs test 실측:

| | 학습 | test |
|---|---|---|
| `in_temp/in_hum/in_co2` 결측률 | 0.70~0.80% | **0.00%** |
| `in_co2` < 300ppm (물리적 이상) | 2.05% | **0.07%** |
| `in_co2` ≥ 2000ppm | 0.05% | 0.00% |
| `in_temp` 6시간 이상 고착 | 0.2% | 0.0% |

→ **X는 오염, y는 관측 기반** → 일부 구간에서 X–y 관계가 인위적으로 깨져 있습니다.
**Huber 손실이 효과적인 이유가 이것입니다** (두 타깃 모두에서 독립적으로 이김).

### 1.6 기타 데이터 특이점

- **F10 / F11은 동일 시계열이 11일 어긋나 중복 수록.** X 3변수가 완전 일치하는 2,123시간에서 `sub_temp`까지 100% 일치(그 외 구간 우연 일치율 19.2%). 24시간 통째 일치 블록 58일. → CV 분할 시 같은 그룹으로 묶어야 함.
- **커튼 값은 "열림 정도"** (PDF 정의). 데이터로 검증: 야간 `act_thermal`≈0일 때 내외부 온도차 +7.6℃(단열 중), ≈100일 때 −2.0℃. 시각별 평균도 주간 83 / 야간 8. **처음에 반대로 해석해 물리 피처가 무효였던 적이 있음.**
- **외부 기상 24시간 벡터가 정확히 일치하는 날 다수** (F13 230일 중 180일이 중복군). 복원 과정의 아티팩트로 보이며 활용 가치 없음. 다른 AI 계열도 같은 결론.
- **`out_rad` 야간값이 0이 아니라 정확히 5.0** (하한 클리핑).
- `sample_submission.csv`는 저장소·작업 폴더에 없음. test_X의 row_id 순서와 동일하다고 PDF가 보장하나 **제출 전 실물 대조 권장**.

### 1.7 두 타깃의 성격이 완전히 다름

**sub_temp** — 배지는 1차 저역통과 필터. 현재 실내온도보다 **3시간 전 실내온도와 상관이 더 높음**(F13 0.785 → 0.917). "그날 평균"으로 설명되는 분산 R² = 0.71~0.73.

**sub_ec** — 하루 안에서 거의 평탄, **자정에 점프**.

```
F47 16일차: 0.20 0.20 0.20 ... 0.19 0.19 ... 0.20 0.20
F47 17일차: 0.11 0.11 0.11 ... 0.10 0.11 ... 0.12 0.12
F47 18일차: 0.20 0.20 0.20 ... 0.20 0.21 ... 0.21 0.21
```

| 지표 | F13 | F47 |
|---|---|---|
| **"그날 평균"으로 설명되는 분산 R²** | **0.942** | **0.954** |
| 일 내 시간별 std (중앙값) | 0.023 | 0.017 |
| 자정 경계 \|Δ\| 평균 | 0.256 | 0.327 |
| 그 외 시각 \|Δ\| 평균 | 0.010 | 0.011 |

→ **EC 문제 = 사실상 60개(2온실×30일) 일별 수준값 맞히기.**

추가 규칙성:
- **2일 주기**: 일별평균 자기상관 lag1 0.13~0.20 < **lag2 0.52~0.73** (격일 관수 추정). 홀짝 고정효과 자체는 잔차std 대비 작아 단독 사용 불가.
- **계절 상승**: F47 초기10일 0.198 → 말기10일 0.842, F13 0.351 → 0.894. `day`가 단일 최강 피처급(상관 +0.44).
- 일 내 미세 패턴은 증산 신호(7시 최저 → 17시 최고).

## 2. 검증 설계 — 가장 중요한 교훈

### 2.1 세 가지 CV와 실제 점수

| 검증 방식 | 검증행→최근접 라벨일 거리 | 온도 | EC(current) | EC(v5) |
|---|---|---|---|---|
| 블록 CV, 후반부(≥183일차) 행만 | 평균 **11.2일** | 0.887 | 0.296 | 0.397 |
| 블록 CV, 전 기간 | 평균 4~5일 | 0.774 | 0.260 | 0.251 |
| **test 배치 평행이동 CV** | **평균 3.6일 = 실제와 동일** | 0.861 | 0.365 | **0.290** |
| **실제 채점 (1회차)** | 3.6일 | **0.745** | **0.244** | 미제출 |

### 2.2 왜 "후반부 CV"가 비관적이었나

후반부 학습일(T)은 test 블록(E) 사이에 끼어 있습니다. 그 T 구간을 검증용으로 떼어내면 **양옆이 라벨 없는 E 블록**이라 최근접 라벨이 8~12일 밖으로 밀려납니다. 실제 E 블록은 양옆 T가 2일 거리입니다.
→ 같은 시기는 맞췄지만 **라벨 거리를 3배 과장**했습니다.

### 2.3 권장 검증: `geometry_cv.py`

실제 test 배치(E5·T8·E10·T8·E10·T3·E5)를 앞쪽 연속 구간으로 평행이동해 5개 fold 생성. 라벨 거리가 실제와 정확히 일치(3.6 / 3 / 6).

```python
LAYOUT = list(range(0,5))+list(range(15,25))+list(range(35,45))+list(range(50,55))
SHIFTS = [70, 85, 100, 113, 126]
```

### 2.4 반드시 지킬 것

- **랜덤 행 분할 금지.** 5~10일 연속 블록 + 앞뒤 1일 버퍼.
- **단일 분할 금지.** EC는 분할당 ±0.02 노이즈. 실제로 후보 순위가 분할 수에 따라 뒤집힌 적 있음(huber 0.3088↔0.3192). 최소 5개 분할 평균.
- **절대값보다 순위를 믿을 것.** 세 CV 모두 절대값은 실제보다 비관적이지만, 라벨 거리가 맞는 두 CV에서 모델 간 순위는 일관됨.

## 3. 제출 모델

### 3.1 1회차 (채점됨: 0.7450 / 0.2442) — `--ec current`

| 타깃 | 모델 | 피처 |
|---|---|---|
| sub_temp | LightGBM(Huber) × 시드 3개 평균 | 98 |
| sub_ec | ExtraTrees(100그루, leaf 8) + LightGBM(Huber), 반반, 각 시드 3개 | 68 |

```python
T_HUB = dict(objective="huber", n_estimators=1200, learning_rate=0.03,
             num_leaves=63, min_child_samples=40, subsample=0.8,
             subsample_freq=1, colsample_bytree=0.6, reg_lambda=1.0)
E_HUB = dict(objective="huber", n_estimators=400, learning_rate=0.02,
             num_leaves=7, min_child_samples=240, subsample=0.7,
             subsample_freq=1, colsample_bytree=0.4, reg_lambda=5.0)
ET    = dict(n_estimators=100, max_features=1.0, min_samples_leaf=8)
```

`min_child_samples=240` = **10일 × 24시간**. EC는 하루 24행이 사실상 같은 값이라 행 단위 기준이 무의미하므로 일 단위로 환산한 값입니다.

예측값은 학습 관측 범위 `[0.062, 3.46]`으로 클리핑.

### 3.2 2회차 (준비 완료, 미제출) — `--ec v5`

온도는 1회차와 **바이트 동일**. EC만 교체:
- ExtraTrees(100그루, **leaf 2**) × 시드 3, 피처 **18개**
- 피처 = 원본 14개 + `day` + `hr_sin` + `hr_cos` + `midnight`
- 이력 피처 없음. Codex 계열 v5 레시피를 이식한 것.

근거: `geometry_cv` 기준 0.290 vs current 0.365. v5 레시피 내부 탐색에서 `day` 필수(빼면 0.326), leaf 2 > 4 > 8, 블렌드는 전부 악화.
1회차 EC와 상관 0.81, RMS 차이 0.216 (온실별 평균은 유사, 날짜별 배분이 다름).

### 3.3 피처 생성 (`features_v2.py`)

타깃별 시간 척도에 맞춰 분리 노출하는 것이 1차 과적합 방지입니다.

| | sub_temp | sub_ec |
|---|---|---|
| 물리 모델 | 1차 저역통과 필터 | 일 단위 수분·염류 수지 |
| 포함 | EWM(반감기 2/6/24h), 1~3h lag·차분, 24/72/168h 롤링, 당일 인과 누적, 전일 집계 | 전일/전전일 집계, 직전 7일 평균, 24/72/168h 롤링, 당일 인과 누적, 작기 누적 |
| 제외 | 작기 누적(시간 인덱스 과적합) | 1~3h lag·차분(그 척도에선 노이즈) |

물리 피처(온도 전용, EC에는 해로움):
```python
rad_eff    = out_rad * (act_shade/100) * (act_thermal/100)   # 배지 도달 일사 (커튼=열림률!)
screen_ins = (1 - act_thermal/100) * (in_temp - out_temp)    # 커튼 단열
transp_pm  = 0.4*rad_eff*3600/2.45e6 + 0.025*vpd_in          # Baille 증산 (kg/m2/h)
root_dh    = max(in_temp - 18, 0)                            # 딸기 근권 최적 하한
```

## 4. 규정 준수 (PDF 5절)

- 모든 피처는 **같은 온실의 해당 시각과 그 이전 입력만** 사용. shift, 인과적 ewm, 현재 시각에서 닫히는 롤링, 전일 집계, 당일 0시~현재 확장평균, 작기 누적만 사용. **중앙 이동평균·bfill·하루 전체 평균 금지.**
- `test_X` 입력은 같은 온실의 과거 입력으로서 피처 계산에 사용 가능(정답 아님). 예: 평가 블록 둘째 날의 "전일 평균"은 첫째 날 입력으로 계산.
- `train_y`는 학습 전용. 피처로 사용 금지.
- 추론 시 외부 API·원격 서비스·외부 데이터 조회 금지.

**`causality_test.py`가 자동 검사** — 특정 시각 이후 입력을 교란·삭제해도 그 이전 행의 피처 125개 전부 불변 / 생성기가 입력 열만 수령 / 행 순서 섞어도 동일. **모델 변경 시 반드시 재실행.**

| **고EC 가중치** (y^0.5, y^1) | 편향 −0.59→−0.51 개선되나 late RMSE 0.311→0.329~0.340 악화 | 8% 행 얻고 92% 잃음 |
| 최근성 가중 (τ=60/120/240) | 분할 수에 따라 순위 역전, 판정 불가 | 노이즈 범위 |
| 물리 피처를 EC에 적용 | 0.311 → 0.330 악화 | 온도엔 도움, EC엔 해로움 |
| lean 원본 피처만(19개) + 현재 CV | 0.3215 → 0.3480 악화 | 단, `geometry_cv`에서는 반대 결과(2회차 채택 근거) |
| 기상 쌍둥이 날 활용 | 아티팩트, 활용 불가 | Codex 계열도 동일 결론 |
| **문헌 기반 물리 피처를 EC에** | 기여 없음 (절제 실험 delta +0.005) | GBM이 원재료(out_rad, act_shade…)로 이미 근사 |

**다중공선성 검사 결과** (참고): 온도 98피처 중 VIF>10이 74개, VIF>100이 40개, `rad_eff_dev6` 등 3개는 정의상 완전 공선(VIF≈1e9). 그러나 상관 임계값으로 가지치기해도 CV 변화 ±0.003(fold편차의 1/25)으로 **예측에는 무해**. 트리 모델 특성상 예상된 결과.

## 6. 남은 최대 난제 — EC 고값 구간

현재 모델 OOF 기준:

| 구간 | 행 비율 | 오차(SSE) 비율 | 해당 구간 RMSE | 평균 편향 |
|---|---|---|---|---|
| EC > 0.5 | 36.6% | 77.1% | 0.382 | — |
| EC > 1.0 | **8.1%** | **62.9%** | 0.734 | **−0.544** |
| EC > 1.5 | 5.3% | 58.1% | 0.870 | — |

손실 함수(l2/huber), 가중치(y^0.5/y^1), 모델 계열(LGB/ET), 피처셋 전부 바꿔봤으나 편향이 −0.51~−0.62 범위에서 움직이지 않습니다.
**입력에 "EC가 곧 높아진다"는 신호가 없다**는 결론입니다.

### 다음 AI가 시도해볼 만한 방향

1. **미관측 관수 이벤트 역추정.** EC 시계열의 자정 점프 패턴 자체를 관수 스케줄의 관측치로 취급하는 상태공간/HMM 모델. 규모가 큰 작업.
2. **고EC 분류기 + 조건부 회귀.** Codex 계열 `ec_validation.py`에 P(EC>1) 분류기 + 저/고 구간 분리 회귀(mixture) 골격이 있으나 실행이 완결되지 않음. 단순 가중치와 달리 결과가 다를 수 있음.
3. **미사용 피처 아이디어** (Codex `causal_features.py`/`ec_features.py`에 있고 여기 없는 것):
   - `day_hinge{30..240}` — 작기 단계 구간선형
   - `_repeat24` — 24시간 전과 동일값 표시(고착/복사 탐지)
   - `hours_since_on`, `hours_since_change` — 구동기 이벤트 경과시간
   - 이슬점, 48/168h 구동기 가동비율
4. **온도 쪽 경량화** — |r|≤0.90 가지치기 64피처가 CV 동일(0.8576 vs 0.8611). 별도 회차로 확인 가치.

## 8. 다른 AI 계열(Codex, `analysis/`)과의 관계

같은 저장소의 `analysis/`는 별도 AI가 만든 v1~v5 계열입니다. 그 README는 EC 0.2654(v5)를 보고하는데, **채점 범위가 달라 본 문서 수치와 직접 비교 불가**합니다.

동일 채점판 위에서 재현·비교한 결과(`compare_v5.py`):

| | v5 레시피 | Claude 현재 모델 |
|---|---|---|
| 전 기간 (Codex CV 방식) | **0.250** | 0.285 |
| 후반부 (Codex CV 방식) | 0.424 | **0.299** |
| 후반부 (Claude CV 방식) | 0.397 | **0.299** |
| **geometry_cv (실제와 동일)** | **0.290** | 0.365 |

해석: v5는 "날짜가 가까운 학습 행을 참조하는" 성격이라 **라벨 거리가 가까울 때 강하고 멀 때 무너집니다.** 실제 test는 라벨 거리 3.6일로 가까우므로 v5가 유리하다는 것이 2회차 제출의 근거입니다.

**Codex 계열에서 가져온 것**: 커튼 부호 정정(온도 0.8949→0.8827), ExtraTrees leaf 채택, 고EC 오차 집중 진단, v5 EC 레시피.
**가져오지 않은 것**: EC `farm_id` 제거(Codex −11.5%, 여기선 무효 — 피처셋이 달라 이식 안 됨), 51온실 통합, 2일 전 bridge 피처(시간축 재해석 위험).
