# 여러 컴퓨터 × 여러 AI로 한 프로젝트 이어서 작업하기 — 운영법 설명서 (사람용)

> 팜모니 팀이 2026-09-29부터 집 노트북·연구실 PC에서 Claude와 Codex를 번갈아 쓰며 실제로 운영한 방식을 정리한 것입니다.
> 이 문서는 **사람이 읽는 설명서**입니다. AI에게 실제 설정을 시킬 때는 같은 폴더의 [`AI_여러컴퓨터_운영법_AI지시서.md`](AI_여러컴퓨터_운영법_AI지시서.md)를 AI에게 그대로 넘겨 주세요.

---

## 1. 한 줄 요약

**AI는 컴퓨터를 옮기면 아무것도 기억하지 못합니다. 그래서 "기억"을 AI 안이 아니라 저장소(파일) 안에 두고, 작업 시작·끝에 명령 한 줄씩으로 모든 컴퓨터를 같은 상태로 맞춥니다.**

```
 집 노트북                          연구실 PC
 ┌──────────────┐                  ┌──────────────┐
 │ 클로드  코덱스 │                  │ 클로드  코덱스 │
 └──────┬───────┘                  └──────┬───────┘
        │  작업 끝: sync_end                 │  작업 시작: sync_start
        ▼                                  ▲
   ┌──────────────────────────────────────────────┐
   │ GitHub (코드·문서·작업일지·규칙)                   │
   │ Google Drive (무거운 결과물: 모델, 예측값 등)       │
   └──────────────────────────────────────────────┘
```

## 2. 왜 이렇게 하나

| 문제 | 이 방식에서의 해결 |
|---|---|
| 연구실 Claude는 집 Claude와 대화한 내용을 모름 (계정·컴퓨터가 다름) | 그날 한 일을 **작업일지 파일**로 남기고, 다음 AI는 그걸 읽고 따라잡음 |
| Claude가 쌓은 "사용자 규칙 메모리"가 컴퓨터마다 따로 놂 | 메모리 폴더를 저장소의 `공용/ai-memory/`로 복사해 git으로 옮김 |
| 모델 파일·예측값처럼 큰 파일은 GitHub에 올리기 부적합 | Google Drive 폴더로 따로 동기화 |
| 두 AI(Claude·Codex)가 같은 파일을 고쳐서 꼬임 | **장소 × AI별로 폴더를 나눔.** 자기 폴더에만 씀 |
| "지금 뭐가 최선이고 다음에 뭘 하지?"가 흩어짐 | `공용/HANDOFF.md` 한 파일에 항상 최신 상태를 적음 |

## 3. 세 가지 통로

| 통로 | 무엇이 오가나 | 언제 |
|---|---|---|
| **GitHub** (비공개 저장소, 브랜치 `main` 하나) | 코드, 문서, 작업일지, HANDOFF, 규칙(ai-memory), 작은 로그·결과표 | `sync_start`에서 pull, `sync_end`에서 commit·push |
| **Google Drive** (`<프로젝트>_sync` 폴더) | 각 폴더의 `local/` 안 무거운 결과물 (git에서 제외) | `sync_start`에서 Drive→PC, `sync_end`에서 PC→Drive (새 파일·더 새 파일만 복사, **삭제는 절대 안 함**) |
| **AI 메모리** | Claude가 PC에 저장하는 메모리 폴더 ↔ 저장소 `공용/ai-memory/` | `sync_start`에서 저장소→Claude, `sync_end`에서 Claude→저장소 |

> Codex는 Claude처럼 자동 메모리 폴더를 쓰지 않으므로, `AGENTS.md`에 "`공용/ai-memory/MEMORY.md`를 읽어라"라고 적어 같은 규칙을 따르게 합니다.

## 4. 폴더 구조와 각 문서의 역할

```
C:\work\<프로젝트>\              ← 모든 컴퓨터에서 "같은 경로" (중요, 7절 참고)
  00_먼저_읽기.md                 AI가 가장 먼저 읽는 안내: 나는 누구인가 / 검토법 / 작업일지 틀
  CLAUDE.md                      Claude 앱이 자동으로 읽는 파일 → 00_먼저_읽기로 연결
  AGENTS.md                      Codex 앱이 자동으로 읽는 파일 (CLAUDE.md와 내용 동일)
  README.md                      사람용 소개
  tools\                         setup_env / sync_start / sync_end 스크립트
  공용\
    HANDOFF.md                   지금 상태·현재 최선안·진행 중·다음 할 일 (계속 갱신)
    확인기록.md                   "각 장소×AI가 다른 곳 작업을 언제까지 검토했나"
    발견_카탈로그.md               확인된 사실·기각된 방법을 번호로 누적 (고치지 않고 추가만)
    ai-memory\                   사용자 규칙 (MEMORY.md = 목록, 나머지 = 규칙 하나당 파일 하나)
    컴퓨터_설정_안내.md            새 컴퓨터 설정·매일 명령
  집\클로드\     작업일지\ + 작업 파일 + local\(Drive)
  집\코덱스\     작업일지\ + 작업 파일 + local\(Drive)
  연구실\클로드\  작업일지\ + 작업 파일 + local\(Drive)
  연구실\코덱스\  작업일지\ + 작업 파일 + local\(Drive)
```

### 문서별로 "누가, 언제, 어떻게" 쓰나

| 문서 | 쓰는 사람 | 쓰는 때 | 쓰는 방식 |
|---|---|---|---|
| 작업일지 `<장소>/<AI>/작업일지/YYYY-MM-DD.md` | 그 장소의 그 AI | **세션 끝날 때 반드시** | 하루 한 파일. 같은 날 또 하면 `## 세션 2`로 이어 씀. 기각한 것도 적음 |
| `공용/HANDOFF.md` | 모든 AI | 세션 끝날 때 | 맨 위에 `> **날짜 시각 장소 AI:** 요약` 한 단락 추가 + 현재 상태 갱신 |
| `공용/확인기록.md` | 모든 AI (자기 줄만) | 다른 곳 작업을 검토한 뒤 | 자기 줄의 "마지막 검토일"을 오늘로 |
| `공용/발견_카탈로그.md` | 모든 AI | 새로 확인/기각했을 때 | **새 번호로 추가만.** 틀린 게 있으면 고치지 말고 정정 항목을 새로 씀 |
| `공용/ai-memory/` | Claude가 자동 + 사용자 | 사용자가 규칙을 말했을 때 | 규칙 하나 = 파일 하나, 목록은 MEMORY.md |

### 작업일지 틀 (실제로 쓰는 양식)

```markdown
# 2026-10-01 · 연구실 · 클로드

## 한 줄
(오늘 무엇이 달라졌는지 한 문장)

## 한 것
- 실험·변경 (스크립트 이름)

## 결과
| 실험 | 수치 | 판정(채택/기각/보류) | 근거 파일 |
|---|---|---|---|

## 다른 곳에 알릴 것
- (상대 AI·다른 장소가 알아야 할 것. 없으면 "없음")

## 다음
- 이어서 할 일

## 파일
- 추가한 파일
```

## 5. 처음 1회 설정

### 5-1. 프로젝트 저장소 만들기 (팀원 한 명이 한 번만)
1. GitHub에 **비공개 저장소**를 만듭니다. 같이 쓸 사람은 저장소 Settings → Collaborators로 초대합니다.
2. Google Drive "내 드라이브" 바로 아래에 `<프로젝트>_sync` 폴더를 만듭니다. (다른 사람 계정이면 이 폴더를 공유하고, 그 사람은 "내 드라이브에 바로가기 추가")
3. 컴퓨터에 `C:\work\<프로젝트>` 로 저장소를 받고, Claude(또는 Codex) 앱에서 그 폴더를 연 뒤 **[`AI_여러컴퓨터_운영법_AI지시서.md`](AI_여러컴퓨터_운영법_AI지시서.md) 파일을 첨부하고 이렇게 말합니다.**
   > "이 지시서대로 저장소 운영 구조를 만들어줘. 장소는 집·연구실, AI는 클로드·코덱스, 프로젝트 이름은 ○○야."
4. AI가 폴더·문서·스크립트를 만들면 한 번 `sync_end`로 올립니다.

### 5-2. 각 컴퓨터에서 (컴퓨터마다 한 번)
PowerShell(시작 메뉴 → "PowerShell")에 한 줄씩 붙여 넣습니다.

```powershell
winget install --id Git.Git -e
winget install --id Google.GoogleDrive -e
```
(Python 등 프로젝트에 필요한 것도 설치. 설치 후 PowerShell 창을 닫았다 다시 엽니다.)

1. **Google Drive 로그인** → 탐색기에서 `G:\내 드라이브\<프로젝트>_sync`가 보이면 성공.
2. **저장소 받기** — 반드시 **OneDrive 밖, 모든 컴퓨터에서 같은 경로**:
   ```powershell
   git clone -b main https://github.com/<아이디>/<저장소>.git C:\work\<프로젝트>
   cd C:\work\<프로젝트>
   git config user.name "<GitHub 아이디>"
   git config user.email "<GitHub 이메일>"
   ```
3. **첫 동기화**:
   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\work\<프로젝트>\tools\sync_start.ps1
   ```
   `Done.`이 나오면 끝.
4. Claude 데스크톱 앱(Code 탭)과 Codex 앱에서 **작업 폴더를 `C:\work\<프로젝트>`로** 엽니다.

## 6. 매일 루틴 (이것만 지키면 됩니다)

### ① 작업 시작
```powershell
powershell -ExecutionPolicy Bypass -File C:\work\<프로젝트>\tools\sync_start.ps1
```

### ② AI에게 첫 마디
> **"너는 연구실 클로드야. 00_먼저_읽기.md 읽고, 마지막 확인 이후 다른 곳·다른 AI 작업 검토한 다음 이어서 해."**

장소와 AI 이름만 바꿔서 씁니다(예: "너는 집 코덱스야"). AI는 다음 순서로 읽습니다.
`00_먼저_읽기.md` → `HANDOFF.md` → `ai-memory/MEMORY.md` → `확인기록.md`의 내 줄 날짜 → 그 날짜 이후 다른 세 폴더의 작업일지 → 요약 보고

### ③ 작업
평소처럼 시킵니다. AI는 자기 폴더(`연구실/클로드/` 등)에만 파일을 만듭니다.
새 규칙이 생기면 "이거 기억해줘"라고 하면 Claude가 메모리에 저장하고, `sync_end` 때 `공용/ai-memory/`로 올라갑니다.

### ④ 끝낼 때 AI에게
> **"작업일지랑 HANDOFF 갱신해줘."** (카탈로그에 넣을 게 있으면 같이)

### ⑤ 작업 끝
```powershell
powershell -ExecutionPolicy Bypass -File C:\work\<프로젝트>\tools\sync_end.ps1 -Message "오늘 한 일"
```
그리고 **작업 표시줄 Google Drive 아이콘에서 업로드가 끝난 걸 확인한 뒤** 컴퓨터를 끕니다.

> 같은 컴퓨터에서 Claude와 Codex를 **동시에** 돌렸다면: 두 AI가 모두 일지를 쓴 뒤 `sync_end`를 **한 번만** 실행합니다.

## 7. 규칙과 그 이유

| 규칙 | 이유 |
|---|---|
| **모든 컴퓨터에서 저장소 경로를 똑같이** (`C:\work\<프로젝트>`, 영어 경로) | Claude는 메모리 폴더 이름을 저장소 경로로 정합니다(`C--work-프로젝트`). 경로가 다르면 메모리가 엉뚱한 곳으로 갑니다. |
| **OneDrive 밖에 둠** | OneDrive와 git이 같은 파일을 동시에 만지면 충돌·파일 손상이 납니다. |
| **브랜치는 main 하나** | 장소마다 브랜치를 만들면 합칠 때 꼬입니다. 대신 폴더를 나눠 충돌을 피합니다. |
| **자기 폴더에만 쓰고, 남의 폴더는 읽기만** | 두 AI가 같은 파일을 고치는 일을 원천 차단합니다. |
| **이미 만든·쓴 파일은 고치지 말고 새 이름(v2)으로** | 나중에 "그때 그 결과가 뭐였지?"를 재현할 수 있습니다. |
| **카탈로그는 추가만** | 다른 AI가 번호로 인용하므로, 고치면 인용이 틀어집니다. |
| **기각도 작업일지에 적음** | 안 적으면 다른 곳 AI가 같은 실험을 또 합니다. |
| **AI가 직접 커밋할 땐 `git add -A` 금지, 자기 파일만** | 같은 PC의 다른 AI가 작업 중인 파일까지 섞여 올라갑니다. |
| **동기화는 복사만, 삭제 안 함** | 한쪽 실수로 다른 쪽 결과가 지워지는 일을 막습니다. 지울 건 사람이 직접. |

## 8. 자주 겪은 문제와 해결 (실제 사례)

| 증상 | 원인 / 해결 |
|---|---|
| `git pull` 충돌 | 두 곳이 같은 날 HANDOFF·카탈로그를 고침. AI에게 "git 충돌 해결해줘" (보통 두 내용 모두 살리면 됨) |
| `farmai_sync not found` 같은 경고 | Drive 로그인 안 됨, 또는 폴더가 "내 드라이브" 바로 아래에 없음 |
| sync_start 했는데 다른 PC 결과물이 없음 | Drive가 아직 업로드 중이었거나(보낸 쪽이 확인 안 하고 끔), 받는 쪽 Drive가 아직 목록을 못 받음. Drive 아이콘에서 동기화 완료 확인 후 sync_start 다시 |
| 스크립트 실행이 막힘 | 명령 앞에 `powershell -ExecutionPolicy Bypass -File` 붙이기 |
| 스크립트에서 한글 폴더 이름이 깨짐 | `.ps1` 파일이 BOM 없는 UTF-8로 저장됨. AI에게 "BOM 붙여서 다시 저장해줘" |
| `sync_end`가 "not main" 오류 | `sync_start`를 먼저 실행 |
| HANDOFF가 너무 길어져 읽기 힘듦 | 오래된 단락은 `공용/HANDOFF_보관_YYYY-MM.md`로 옮기라고 AI에게 시킴 (우리 팀도 겪음) |
| 브라우저에 저장한 메모(HTML 페이지 등)가 다른 PC에 없음 | 브라우저 저장소는 PC마다 따로입니다. 남길 건 파일로 |
