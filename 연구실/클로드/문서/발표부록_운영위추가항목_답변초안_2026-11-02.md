## [정형 1] (자기 점검 4번) TabPFN 비중 0.3·0.4 중 최종안을 고른 방법

**슬라이드 요지**
- 두 후보의 차이: 같은 세 구성원(기준·Codex·TabPFN), **따뜻한 행(실내 10℃ 이상) 비율만** 다름 — 0.3안 기준 0.5·Codex 0.2·TabPFN 0.3 / 0.4안 기준 0.4·Codex 0.2·TabPFN 0.4. 8℃ 이하는 둘 다 기준 0.4·Codex 0.6·TabPFN 0
- 비교한 것: ① 내부 교차검증(일반 날 DIAG10, 추운 날 EXT10·EXT12) ② 공개 리더보드 온도 점수
- 내부 검증은 엇갈림: 일반 날 0.4가 −0.8% 나음, 추운 날 0.4가 +0.1~+0.2% 나쁨 → 사전 채택 규칙 미통과
- 엇갈린 두 후보를 공개 리더보드 한 번의 비교로 선택: 0.5193 → 0.5160(−0.64%) → 0.4. 최종 답안(24회차 35e)의 따뜻한 행 비중도 0.4

**발표자 노트(상세)**
1. **두 후보의 차이**: 구성원 세 개는 완전히 같고, 따뜻한 행에서 기준 몫 0.1을 TabPFN으로 옮긴 것만 다릅니다. 8~10℃는 g = clip((실내온도−8)/2, 0, 1)로 두 설정을 직선으로 잇고, 8℃ 이하 행은 두 후보가 같습니다. 실제 제출 답안 비교: 1,440행 중 1,225행 변경, 평균 −0.004℃, RMS 0.036℃, 최대 0.197℃(7회차 submission_09 vs 8회차 submission_11의 sub_temp, 2026-11-02 계산).
2. **0.3까지의 경위(데이터 근거)**: 처음엔 0.3이 추운 날 검증(EXT10)에서 나빠져 기각했습니다(카탈로그 6.60~6.62). TabPFN은 학습 범위 밖 추위에서 크게 틀리므로(추운 날 편향 +1.8℃), 8℃ 이하 행에서 TabPFN을 빼는 온도 게이트(6.67, 6.70)를 넣었습니다. 그 뒤 따뜻한 행만 0.2→0.3으로 올린 W30G가 새 표본 판정에서 사전 규칙을 통과해 7회차로 냈습니다(DIAG10 −1.19%, EXT10 −0.10~−0.17%, EXT12 −0.27~−0.30%, `제출/07회차_2026-10-01(팀)/설명자료_09`).
3. **0.3 vs 0.4 내부 검증(제출 전)**: 새 표본 9~12, W30G 대비 W40G
   - 일반 날 DIAG10: −0.77 / −0.78% (p_worse 0.089)
   - 추운 날 EXT10: +0.14 / +0.19%, EXT12: +0.17 / +0.22%
   - 일반 날은 0.4가 낫고 추운 날은 근소하게 나빠, "모든 검증기 같은 방향 + p_worse < 0.025" 규칙을 통과하지 못했습니다. 출처: 8회차 패키지 `온도/README.md` 5절. 이 수치를 낸 스크립트 `temp_user_w40g_check.py`와 로그는 현재 저장소·드라이브에서 찾지 못했습니다.
4. **리더보드 비교**: 그래서 패키지 README에 **"리더보드 판정용 후보"**로 적고 8회차로 제출했습니다. 공개 점수 0.5193→0.5160으로 내부 DIAG10과 같은 방향·비슷한 크기라 0.4를 유지했습니다(카탈로그 6.198, `제출/08회차_2026-10-03(팀)/설명자료_11`).
5. **사후 확인(리더보드를 본 뒤, 10-12 TW1)**: 이후 구성(W40G-S 구성원) 위에서 비중 285조합을 다시 계산한 결과, 0.3 칸은 0.4 칸보다 DIAG10 1차 구간 +0.85%, 평가 기간과 같은 2차 구간 +0.93% 나빴습니다. 주효과도 같은 방향입니다(2차 구간 +0.70% vs +0.25%). 한계: 리더보드를 본 뒤의 분석이고, 이 두 칸은 DIAG10만 있으며, 0.3 칸의 추운 행 비율이 0.5/0.5라 실제 W30G(0.4/0.6)와 조금 다릅니다(`집/클로드/research/tw1_w40gs_blend_sweep_v1.py`, `logs/tw1_v1.log`, 격자 `farmai_sync/research_local/tw1_grid.csv`).
6. **왜 엇갈렸나**: TabPFN 비중을 올릴수록 일반 날은 좋아지고 학습 범위 밖 추위에서는 나빠지는 경향이 반복 확인됐습니다(6.67, TW1 주효과). 0.3→0.4 구간은 두 효과가 거의 상쇄되는 지점이었습니다. 10-16에 비중 {.4,.5,.6,.7}을 데이터만으로 고르는 사전 고정 시험(B36)은 .4/.7로 엇갈려 불통과(7.051), 0.6 단독도 불통과(6.486)라 0.4를 유지했습니다.
7. **정리**: 0.4는 일반 날 검증에서 0.3보다 일관되게 나았지만(제출 전 −0.8%, 사후 평가 시기 구간 −0.9%), 추운 날 검증에서 0.2% 안팎 나빠 사전 규칙을 넘지 못했습니다. 이 엇갈림을 **공개 리더보드 한 번의 비교로 정했습니다**(자기 점검 4번의 '상수·가중치·구성 결정'에 해당). 한 회차 비교라 우연 가능성은 배제하지 못합니다.

## [이미지 2] (공통 1) 원본 대조 단계와 파일 형식 분기가 작동하는 입력, 작동하지 않을 때의 처리

**슬라이드 요지**
| 분기 | 작동하는 입력 | 작동하지 않는 사진 | 현장에서는 |
|---|---|---|---|
| 원본 대조(지문 DB) | AI Hub 원천 152,043장 중 **거의 같은 원본이 DB에 있는 사진**(R1: 3.5<d1<20·gap>8, 정밀: dg1≤1.011·gap≥3.474) | 규칙 미적용 → 기본 판별기+전문가 확률 그대로 | 새 농장·새 카메라 사진은 DB에 원본이 없어 **거의 항상 미작동** |
| 형식 게이트 | JPEG + 4:2:0 + PIL Q92 양자화표가 **완전히 같은** 파일 | 전문가 H·E_gr·E_gpt 미적용(기본+E_pg·E_ps·E_L+원본 대조만) | 휴대폰·카메라 원본(다른 품질·서브샘플링·PNG·HEIC 등)은 대부분 게이트 밖 |
- 지문 DB를 끈 성능(현장 근사): 학습 미사용 R2~R5 균형 정확도 −1.3~−2.3%p(.964→.945 등), 주로 실제 오탐 증가

**발표자 노트(상세)**
1. **원본 대조가 하는 일**: 사진의 12×16 색 지문·정밀 지문을 AI Hub 지문 DB와 비교해 1위 거리와 2위와의 차(gap)를 봅니다. 원본과 거의 같으면서 국소 차이가 크면 가짜 확정(p≥.95), 국소 차이도 작으면 진짜 확정(rc, p≤.3)으로 돌립니다(README ⑤ 순서 2·4). 즉 **"AI Hub에 원본이 있는 사진"에서만** 작동합니다. 이는 대회 자료의 출처 규칙성(자기 점검 3번)에 기대는 부분입니다.
2. **작동하지 않을 때**: 거리 조건을 못 맞추거나 계산이 실패하면 규칙을 건너뛰고 기본 판별기(CLIP+저수준) 평균과 전문가 max 결합 결과를 그대로 씁니다(README ⑤ 예외 대체). rc가 아니므로 전문가 H·E_gr은 기본 문턱 θ, E_gpt는 적용됩니다.
3. **현장 근사 성능(끄기 실험, 10-20, 서술용)**: 나단11 코드를 그대로 두고 지문 DB 입력만 뺐습니다(판 D). 학습 미사용 봉인 묶음에서 균형 정확도 R2 .964→.945, R3 .962→.948, R4 .947→.924, R5 .944→.921, 공개 21장 21/21 그대로. 실제 오탐률 1.4~2.8% → 4.0~5.9%, 처리 변형 실제에서 더 큼(webp 37.5→75.8%, 4:4:4 5.4→13.8%, 크기 변경 2.1→8.2%). 가짜 탐지 기여는 작음(부분 생성 82.3→79.2%, 부분 스타일 90.6→88.3%). 차이는 거의 정밀 원본 대조의 "진짜 확정"에서 나옵니다(12×16 R1만 끄면 −0.4~+0.1%p). 출처: `logs/ablation_원본대조_2026-10-20/결과.md`, `요약표.md`.
   - 주의: R2~R5의 실제 사진도 AI Hub 사진이라 **원본이 DB에 있습니다**. 판 A 수치는 현장보다 낙관적이고, 판 D가 현장(원본 없음)에 더 가깝습니다. 판 D도 같은 AI Hub 농장·촬영 조건이라 다른 출처 사진 성능은 아닙니다.
4. **형식 게이트**: 전문가 H·E_gr·E_gpt는 배포 형식(JPEG Q92 4:2:0, 공개 21장 실측과 같음)으로만 학습했기 때문에, 그 형식일 때만 씁니다(README ⑤ 순서 5, `data/README_data.md` 4절). 게이트 밖이면 이 세 전문가 없이 기본 판별기+E_pg·E_ps·E_L+원본 대조로 판정합니다. 이것도 대회 자료의 파일 형식 규칙성에 기대는 부분입니다.
5. **형식이 다른 사진의 성능**: 처리 변형 실제 묶음(R3 실제 429장, `im46_r3_proc.py`)으로 오탐률을 쟀습니다.
   - 게이트 **밖**: png(PNG 저장) 2.1%, webp(WebP q90) 37.5%, c444(JPEG Q92 4:4:4) 5.4%
   - 게이트 **안**(PIL quality=92 기본 저장 = 4:2:0): area(다른 축소 방식 후 Q92) 2.1%, sharp(선명화 후 Q92) **90.7%**
   - 선명화 사진은 형식이 배포 형식과 같아 세 전문가가 모두 적용되는데도 대부분 가짜로 판정됩니다. 현장 휴대폰의 자동 선명화에 매우 약할 수 있습니다.
   - **다른 형식으로 저장한 가짜의 탐지율은 미실시.**
6. 학습 자료와 출처가 다른 자료로 확인: **미실시**(모든 실제·가짜가 AI Hub 사진 또는 그 가공물. 공개 21장은 대회 자료).
