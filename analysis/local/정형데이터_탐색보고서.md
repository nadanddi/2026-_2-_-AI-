# 정형데이터 미션 최종 분석 요약과 다음 단계

작물은 딸기이며, 같은 1시간 구간의 평균 배지 온도 `sub_temp`와 배지 EC `sub_ec`를 추정한다. 기본 분석에 이어 초기 모델 v1 학습·로컬 예측을 완료했다. 원본 수정·대회 업로드는 하지 않았다. 아래 변수 수와 순서는 초기 설계안이며 실제 선택 결과는 마지막 절에 기록한다.

## 1. 반드시 지킬 조건

- 평가 온실은 F13·F47이며 각 720시간이다. 두 온실의 학습자료는 각 4,800시간, EC 정답은 이 두 온실에만 있다.
- 실제 입력은 **내부 3개 + 외부 4개 + 장치 7개 = 14개**다. `in_rad, act_side, act_valve, act_cool, act_pump`는 두 온실에서 전부 결측이므로 사용하지 않는다.
- 전체 51개 온실에서는 외부·장치 관측률이 낮지만, F13/F47의 외부 4개와 장치 7개는 학습·평가 모두 완전 관측이다. 전체 결측률을 이유로 버리지 않는다.
- 상대일차 +1은 공식적으로 하루 뒤다. 실제 날짜·정식일은 알 수 없다. 지연값은 행 순서가 아니라 온실별 실제 시간 키로 계산한다.
- 같은 온실의 현재·과거 입력만 특징에 사용한다. 미래값, bfill, 중앙 이동평균, 미래 시각이 섞인 당일 통계는 금지한다.
- 결측과 장치의 0을 구분한다. 정답 급변·고정값·중복을 근거 없이 삭제하거나 보정하지 않는다.

## 2. 확인된 데이터 특징

- 배지 온도는 현재 내부 온도보다 과거 온도와 관계가 강하다. 내부 온도 상관은 현재 0.785/0.747에서 3시간 전 0.917/0.893으로 증가한다(F13/F47).
- EC는 하루 안에서는 매끄럽지만 날짜 사이 수준 변화가 크다. 단일 환경변수보다 기간·운영 상태의 영향이 크다.
- 외부 4변수의 하루 전체가 정확히 반복되는 날짜가 많다. 그러나 내부환경·장치·정답은 같지 않으므로 중복 제거·정답 복사에 사용하지 않는다.
- 이틀 전 EC가 더 이어지는 구간이 많지만 큰 예외도 있다. 숨은 자료 계열의 단서일 뿐 홀짝 분리나 날짜 재배열의 근거는 아니다.
- VPD와 EC의 단순 상관은 두 온실 모두 약 -0.046이다. VPD 하나로 EC를 설명할 수 없다.
- EC에 중요한 배지 수분, 급액·배액량, 공급 양액 EC·pH, 생육단계는 제공되지 않았다. EC는 간접 변수로 추정해야 한다.

## 3. 도메인 지식을 반영한 변수 설계

연구사님 의견과 딸기 양액재배 자료는 **고정 가중치나 강제 방향**이 아니라 조건부 상호작용과 시간 이력을 설계하는 데 사용한다.

### 배지 온도 모델: 초기 40~55개

1. 원본 14개와 온실·시간 정보
2. `in_temp`, `out_temp`: 1/3/6시간 지연, 3/6/12시간 평균, 변화량
3. `out_rad`: 현재까지의 3/6/12시간 누적 에너지
4. 내외 온도차와 환기×온도차
5. 난방×보온커튼 닫힘, 일사×차광커튼 열림
6. 결측 여부·마지막 관측 후 경과시간

내부 온도 이력이 중심이고 외기·일사·장치는 보완 변수다.

### EC 모델: 초기 50~70개

1. 원본 14개와 온실·시간·상대일차
2. 내부 온도·습도·CO₂의 1/3/6시간 지연, 평균, 변화량
3. VPD와 내외 수증기압 차이의 현재·3/6시간 평균
4. 일사의 3/6/12/24시간 누적
5. 환기·팬·포그·CO₂ 공급의 현재값, 3/6시간 평균, 상태 전환
6. `포그×VPD`, `환기×수증기압 차이`, `CO₂×일사`, `팬×VPD`
7. 공식 자정 표시, 당일 현재까지의 입력 통계, 결측·고정값 지속 표시

EC는 현재 환경의 단일 방향보다 **단기 수분 수요 + 장치 운전 + 기간별 수준**을 함께 표현한다. 실제 EC 정답의 지연값이나 당일 정답 평균은 입력에 쓰지 않는다.

### 정의상 수정할 부분

- 커튼 값은 열림 정도다. `일사×act_shade/100`은 차광커튼이 열린 조건의 일사 대리값이다.
- 보온 효과는 `난방×(1-act_thermal/100)`처럼 보온커튼 닫힘과 결합한다.
- `act_heating`은 난방 팬·펌프 가동비율의 최댓값이지 열량이 아니다.
- 유동팬은 냉각기로 고정하지 않고 공기 혼합·운전 상태로 취급한다.
- 문헌의 배액 EC 권장 범위와 임의 온도 보정은 이번 배지 EC에 적용하지 않는다.

## 4. 모델과 가중치 원칙

- 온도와 EC는 별도 모델로 만든다.
- 첫 주력은 트리 부스팅 모델이다. 비선형 관계와 조건별 장치 효과를 다루기 쉽기 때문이다. 단순 평균·선형 모델은 비교 기준으로 유지한다.
- 변수별 수동 가중치는 주지 않는다. 트리가 분할을 학습하게 하고, 변수 묶음별 추가 효과를 검증한다.
- 단조 제약도 처음에는 사용하지 않는다. 팬·VPD·습도와 EC 관계가 기간별로 바뀌기 때문이다.
- F13/F47 통합 모델과 온실별 모델을 모두 비교한다. 다른 49개 온실은 온도 보조학습에만 별도 실험하며 단순 합산하지 않는다.

## 5. 다음 단계 가이드

### 1단계 — 특징 코드 정비

- 커튼 열림/닫힘 해석을 수정한다.
- 미래값 불변성, 시간 공백, 온실 분리 테스트를 다시 통과시킨다.
- 초기 특징을 온도 40~55개, EC 50~70개로 제한한다.

완료 기준: 각 특징의 계산식·단위·사용 가능한 시점이 명시되고 미래 입력을 바꿔도 과거 행 특징이 변하지 않는다.

### 2단계 — 검증 설계 고정

- 랜덤 행 분할 대신 F13/F47의 5~10일 연속 블록을 사용한다.
- 검증 이전만 학습하는 보수적 평가와, 공개 정답 중 검증 블록만 제외하는 평가를 구분한다.
- 동일 날씨 날짜가 학습·검증 양쪽에 있는 경우를 제거한 점수도 함께 본다.

완료 기준: 모델을 바꿔도 동일한 분할·평가지표를 재사용한다.

### 3단계 — 작은 변수 묶음부터 절제 실험

순서: `현재 14개` → `시간·온실` → `내부 이력` → `외부·일사` → `장치 이력` → `도메인 상호작용` → `품질 표시`.

각 단계는 바로 이전 단계보다 여러 검증 블록에서 일관되게 좋아질 때만 유지한다. EC 한 구간만 좋아지는 변수는 보류한다.

### 4단계 — 모델 비교

- 기준: 상수/선형 모델
- 주력: 히스토그램 기반 트리 부스팅 1종
- 보조: 다른 계열의 트리 모델 1종
- 이후에만 통합/온실별 모델과 앙상블을 비교한다.

초기에는 대규모 하이퍼파라미터 탐색보다 변수 묶음과 검증 안정성을 먼저 확정한다.

### 5단계 — 최종 점검과 제출

- 학습 범위 밖 평가 입력, 자정 급변, 결측 인접 구간의 예측을 별도 점검한다.
- 두 목표 모두 유한값인지, 1,440개 ID와 열 순서가 맞는지 확인한다.
- 마지막 유효 제출이 최종 답안이므로 후보 파일과 점수를 기록한다.

## 6. 현재 상태

최신 v5: EC 제거 후속 실험에서 온실 ID만 제거한 ExtraTrees가 5겹 CV RMSE 0.2998→0.2654 dS/m로 11.5% 개선했고 5개 fold 모두 좋아졌다. 데이터 품질 표시까지 함께 제거하면 0.2672로 소폭 악화되어 유지했다. 전체 9,600개 EC 정답으로 재학습하고 v4 온도 LightGBM을 그대로 결합한 1,440행 예측을 저장·검증했다. 결과: `ec_refined_v5/MODEL_CARD.md`, 예측: `ec_refined_v5/submission.csv`, 재현: `analysis/ec_removal_followup.py`.

변수 묶음 제거 분석: v4를 같은 5겹 CV에서 8개 묶음별로 재학습하고 온실-하루 5,000회 재표집 95% 구간을 계산했다. 온도는 내부 온도(+0.556℃), 외부·일사(+0.036), 구동기(+0.020), 내부 습도(+0.011) 제거 시 구간 전체가 0보다 커 유지 근거가 강하다. EC는 구동기(+0.049 dS/m), 내부 온도(+0.003), 내부 습도(+0.003)가 안정적 기여를 보였다. EC 온실 ID 제거는 0.300→0.265 dS/m로 5개 fold 모두 개선되어 다음 모델의 최우선 수정 후보이며, 데이터 품질 표시 제거도 소폭 개선했다. 이는 전통적 p값·인과 검정이 아니라 고정 CV의 예측 기여 안정성이다. 상세: `feature_group_ablation_v4/결과요약.md`.

최신 v4: v3와 같은 5겹 CV에서 온도를 LightGBM(51개 온실 통합+온실별 50:50), EC를 ExtraTrees(두 온실 통합, 최소 잎 표본 2)로 비교했다. 온도 0.8464→0.8398℃(5개 fold 모두 개선), EC 0.3139→0.2998 dS/m(4개 개선·1개 악화). 전체 정답 재학습 및 저장 모델 재예측·1,440행 검증 완료. 결과·모델·제출 후보는 `lgbm_extratrees_v4/`, 재현은 `analysis/compare_lgbm_extratrees.py`. 동일 CV 반복 선택에 따른 낙관 편향 가능성은 남아 있다.

최신 v3(전체 온실·5겹 CV): 온도 정답 51개 온실 304,965행을 통합 학습했다. 10일 블록 5겹 CV에서 온도는 대상 온실 가중치 20인 통합 모델과 온실별 모델의 50:50 혼합으로 0.8662→0.8464℃(5개 중 3개 fold 개선), EC는 정답이 있는 F13/F47 9,600행 통합으로 0.3522→0.3139 dS/m(5개 모두 개선). 결측 유지·센서 존재 표시·온실 범주를 사용하고 검증 인접일 및 동일 날씨/입력 중복을 제외한다. v1/v2와 검증 범위가 달라 점수 직접 비교 금지. 선택과 평가에 같은 CV를 쓴 탐색 결과다. 모델·예측·상세: `all_farms_cv_v3/`, 재현: `analysis/train_all_farms_cv.py`.

RMSE 개선 탐색(2026-09-20): 목표별 8개 설정을 동일 분할에서 비교했다. 온도는 트리 복잡도 증가(반복 300/최대 잎 23/최소 잎 표본 20)로 선택 0.939→0.921℃, 확인 1.243→1.222℃, 과거만 학습 1.332→1.308℃로 소폭 개선했다. EC는 기존이 최선이었다. 기존 확인 구간에서 EC>1인 17.1% 행이 제곱오차의 84.0%를 차지해 고EC 상태 식별을 다음 우선 과제로 둔다. 독립 새 평가가 아니며 제출 파일은 갱신하지 않았다. 상세: `rmse_exploration/결과요약.md`, 재현: `analysis/explore_rmse.py`.

가설 모델 v2 추가 완료: 이틀 전 입력 연결·현재까지 날씨 반복·당일 상태 특징을 추가했다(온도 111개/EC 67개). v1과 동일 분할·파라미터로 비교 시 확인 구간 RMSE는 온도 1.243→1.278, EC 0.498→0.484였지만 이전만 학습한 EC는 0.446→0.543으로 악화됐다. 일관된 개선이 없어 비교용으로 보관하며 공식 시간 재정의나 실제 다른 온실 복원으로 해석하지 않는다. 파일: `hypothesis_model_v2/submission.csv`, 상세: `hypothesis_model_v2/MODEL_CARD.md`.

초기 모델 v1 완료: 커튼 파생식 수정·인과적 특징 테스트 후 온실별 HistGradientBoosting 모델 4개를 저장했다. 선택 검증에서 온도는 파생 포함 62개(RMSE 0.939℃), EC는 원본·시간 18개(0.327 dS/m)가 채택됐다. 따로 둔 확인 기간의 RMSE는 1.243℃/0.498 dS/m이며 과거 탐색에서 본 기간이라 완전 독립 평가로 보지 않는다. 1,440행 `initial_model_v1/submission.csv`를 생성하고 저장 모델 재예측 일치를 확인했다. 대회 업로드는 하지 않았다.

다음 우선 작업은 EC 기간별 실패와 F47 온도 큰 오차의 진단이다. 모델·분할·한계는 `initial_model_v1/MODEL_CARD.md`, 문헌은 `딸기_문헌조사_변수활용.md` 참조. 상세 결과·모델은 로컬 보관한다.
