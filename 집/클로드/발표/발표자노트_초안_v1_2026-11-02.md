## 5. [정형] ① 기본 예측 (50초)
- **화면**
  - 온도 NX: 물리 선형식 + 트리 / Ridge 물리 기준선 + 트리 / TabPFN. 실내온도가 낮을수록 TabPFN 비중을 줄임
  - EC: 트리·신경망 + TabPFN, HR5(그 기록의 하루 평균 수준 보정)
- **말할 것:** 온도는 세 모델을 섞되, 추운 시간에는 TabPFN 비중을 줄였습니다. 학습 범위 밖의 추운 행에서 TabPFN이 크게 틀렸기 때문입니다. EC는 하루 안에서 수준이 통째로 어긋나는 오차가 커서, 하루 평균 수준을 따로 예측해 보정했습니다.
- **노트**
  - 온도 섞는 식: `g = clip((실내온도 − 8)/2, 0, 1)`, `pred = 0.4·BASE + (0.2 + 0.4(1−g))·CODEX + 0.4·g·TabPFN`. [정형 ②]
  - 학습 행 가중 0.2: 입력이 복원·보간된 흔적이 있는 행과 잡음이 낀 날입니다(학습 행만 판정). [정형 ②]
  - 추운 행 근거: 학습형 섞기(STK1)를 시험했는데 추운 날 검증에서 크게 실패했습니다(≤ 8℃ 행 +67~+84%). 손으로 정한 "추우면 TabPFN 끄기"가 외삽 안전 장치였다는 것을 확인했습니다. (검증, 카탈로그 7.014)
  - EC 남은 오차의 65~77%가 고EC 기록 35개에 몰려 있었고, 하루 통째로 어긋나는 몫이 78~92%였습니다. (검증, 카탈로그 6.756) → HR5 설계의 근거입니다.
  - TabPFN v2는 사전학습 가중치를 그대로 쓰고 미세조정은 하지 않았습니다. 학습 행 2,000개를 참고 예시로 넣어 예측합니다.

## 6. [정형] ② 어제 이어 붙이기 (50초)
- **화면**

  - 어제에 실측 정답이 있으면 → 23시 값으로 오늘 앞부분 보정(앵커)
  - 어제가 평가 기록이면 → 어제의 최종 예측을 이어 씀(사슬)
- **말할 것:** 배지 온도와 EC는 자정을 넘어 이어집니다. 어제 23시 값을 알면 오늘 새벽 예측이 크게 좋아집니다. 보정은 시간이 갈수록 약해지게 했습니다.
- **노트**
  - 앵커 식: `pred_h = q_h + β_h·clip(A − 0.36 − q_0, −2, 2)`. β_h는 시각별 감쇠로, 학습 정답으로 쟀습니다. [정형 ②]
  - 적용 조건: 링커 확신 p ≥ .8, 실내 공기 자정 변화 |dT| ≤ 1.5℃. 또는 (TAG2) .5 ≤ p < .8이면서 외기만 본 판단 또는 실내만 본 판단이 같은 어제를 고른 경우.
  - 사슬 식: `pred_h += 0.9·exp(−h/8)·β_h·clip(A − 0.36 − x_0, −2, 2)`. A는 앞 기록의 최종 23시 예측입니다.
  - 규정: 평가 기록 사이의 정보 전달은 사슬 하나뿐입니다. 주최 측 10/16 답변 2항(앞선 평가 기록에 대해 고정 규칙이 낸 값을 뒤 기록의 고정식 입력으로 쓰는 것)에 해당한다고 판단했습니다. [정형 ③]
  - 링커 반사실 검사: 평가 기록을 후보에서 모두 빼도 정답 앵커 15기록의 어제는 그대로였습니다. 즉 앵커는 평가 기록의 존재와 무관합니다. [정형 ③]
  - 금지된 W2(평가 자료에 앞 기록이 있는지로 갈리는 규칙)는 최종 답안에 없습니다. [정형 ③]

## 12. [이미지] 검증과 개선 과정 (1분)
- **화면**
  - 검증: 봉인 묶음 R2~R5(촬영 묶음이 학습과 안 겹침), 촬영 묶음 단위 교차검증, 문턱 = 실제 오탐률 기준
  - 점수: 팀원 기준 .77 → 나단1 .90 → 나단6 .95 → 나단9·11 .97 (LB)
- **말할 것:** 같은 원본의 진짜와 가짜가 학습과 검증에 갈라지지 않게 촬영 묶음 단위로 나눴습니다. 후보는 봉인 묶음에서 "실제 사진 오판이 늘지 않는가"를 먼저 봤습니다.
- **노트**
  - 회차 흐름 [성능 6절]
    - 나단1(.90): CLIP + 저수준 + 원본 대조
    - 나단3: 시간 초과로 반려(실패)
    - 나단6(.95): 전문가 + 정밀 원본 대조
    - 나단9(.97): + GPT 재그리기 전문가
    - 나단11(.97, 환산 25.59): + GPT 편집 전문가
  - 실패와 수정: E_gpt 첫 판은 GPT 가짜 26장 중 14장을 새로 잡았습니다. 하지만 실제 오탐 기준을 근소하게 넘어 불통과였습니다. 원인이 "진짜 확정" 사진이라는 것을 찾아 그 사진은 제외했습니다. 불통과를 본 뒤 같은 자료로 정한 변형이라 낙관적일 수 있다는 점을 밝힙니다. [이미지 ⑤]
  - 10-16에 내부 불통과로 버린 후보도 있습니다. 필터 전문가 재학습(C1)은 R3 하락, 토큰 LR(A2)은 R3~R5 하락이었습니다. [성능 6절]
  - 최종 선택: 사전 규칙은 "LB ≥ .98이면 유지"였습니다. Accuracy 표시는 둘 다 .97이었지만, 환산점수(23.82 → 25.59)와 내부 검증을 보고 나단11을 유지했습니다. [이미지 ⑤]
  - 봉인 R2~R5는 후보 채택 판정에 썼으므로 선택에 쓰인 자료입니다. 출처는 학습과 같은 AI Hub 데이터셋입니다. (부록 A5)

## 13. [이미지] 현장 적용 조건·한계 (50초)
- **화면:** 지문 DB를 끄면 (봉인) 균형 정확도 R2~R5에서 −1.4~−2.3%p, 주로 실제 사진 오탐 증가(R5 1.4% → 5.1%)
- **말할 것:** 원본 대조는 AI Hub에 원본이 있는 사진에서만 작동합니다. 현장 사진에는 원본이 없으므로 이 부분이 빠진 성능으로 봐야 합니다. 빠지면 가짜 탐지는 거의 그대로지만 실제 사진 오탐이 늘어납니다.
- **노트**
  - 끄기 실험(10-20, 계획 사전 고정, 서술용) [이미지 ⑤]
    - 균형 정확도: R2 .964 → .945, R3 .962 → .948, R4 .947 → .924, R5 .944 → .921
    - 공개 21장은 21/21 그대로입니다.
    - 처리 변형 실제(webp) 오탐: 37.5% → 75.8%
    - 가짜 탐지 기여는 작습니다(부분 생성 82.3 → 79.2%).
    - R1(색 지문)만 끄면 영향이 작고(−0.4~+0.1%p), 차이는 대부분 정밀 대조의 "진짜 확정"에서 옵니다.
  - 형식 게이트: 파일이 JPEG·4:2:0·Q92 양자화표일 때만 전문가 3개(H·E_gr·E_gpt)를 켭니다. 현장 사진 형식이 다르면 이 셋이 빠집니다. 이 게이트를 끈 성능은 미실시입니다. (부록 A4)
  - 학습 자료와 출처가 다른 자료로 확인한 성능: 미실시입니다(봉인 묶음도 같은 데이터셋).
  - 지문 DB는 사진별 아주 작은 축소본(12×16 컬러, 24×32 흑백)을 담고 있습니다. 이용조건 판단은 부록 A6에 있습니다.
