# 5점(현장 적용) 모델 계획 v1 — 2026-10-14 집 클로드

사용자 결정(10-14): **현장 정보 해석.** 모델 = 오늘 입력 + 날짜 + 같은 동의 최근 센서값(+ 학습 자료).
대회 자료에서 날짜·동·전날 기록을 되살리는 **복원 단계**는 모델과 분리해 정확도·손해를 따로 보고. 목표: 지금 점수 수준 유지.
근거 기준(발표평가 안내 PDF 10-12): 0점 = 핵심 성능이 대회 특유 규칙성에 의존하고 **그 전제가 실제 적용 환경에서도 성립한다는 근거가 부족**.

## 1. 지금 구성 부품 분류 (submission_24 기준)
분류: **F** = 그날 입력·학습 자료만 / **R** = 현장에선 원래 있는 정보(날짜·동·어제 센서값)를 대회 자료에서 복원해 씀 / **X** = 현장 대응물 없는 대회 자료 규칙

| 목표 | 부품 | 쓰는 정보 | 분류 | 처리 |
|---|---|---|---|---|

| EC | 계절 지표 v2 | 1차 = 기록 번호, 2차 = 외기 일치 날짜 | R(날짜) | 유지, 날짜 복원으로 분리 |

## 2. 근거 시험 (모두 사전 고정 후)
- **C1 현장 조건 성능**: 학습 자료 중 전날이 확실한 날(정답 연속성으로 확인된 연결)에서, 진짜 전날 값·진짜 날짜를 줬을 때의 성능 = "현장 전제가 성립하면 이만큼".
- **C2 과거만 학습(현장 시간 전제)**: 현장 모델은 미래 날짜 정답을 볼 수 없음 → 대상 날짜보다 앞선 학습 기록만으로 학습하는 검증(굴리는 기준점). 계절 지표 이득이 '앞뒤 이웃 정답 빌리기'인지 확인(SZ2 해석 검증). 무거움 → GPU 우편함.
- **C3 복원 정확도**: 날짜 복원(2차 외기 일치) 적중률, 링커 전날 적중률(EV), 복원 오류가 점수에 주는 손해.
- **C4 X 부품 제거 손해**: B5·SG2·V3(번호 순서) 각각 뺄 때 검증기 변화. (W2·B5 는 검증기 재현이 어려웠음 → 필요하면 리더보드 가설 검정, 사용자 결정)

## 3. 순서
1. EC-F: 9회차 EC − SG2 + HR5(=NH1 A1) + 어제 값 부품(링커) − B5 → 검증기 비교
2. 온도-F: V3 → V3-L(링커 전날) 또는 제거 → 검증기 비교
3. C1·C3 (집), C2 (연구실 GPU)
4. 사용자가 제출하자고 할 때만 묶음 제작
