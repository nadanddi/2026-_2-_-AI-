# 연구실 클로드에게 — 서버의 생성 이미지 회수 요청 (2026-10-20, 집 클로드)

## 왜 필요한가
- 운영위원회가 다른 팀 문의에 이렇게 답했습니다: "재배포 제한으로 문서 대체하는 자료(AI Hub 원본과 이를 소재로 편집·합성한 이미지)를 제외하면, **최종 모델 학습에 실제 사용한 이미지 전체가 제출 대상이며 생성·편집 이미지도 포함**."
- 우리 학습 묶음에는 AI Hub 원본 없이 **문장만으로 만든 전체 생성 이미지**가 있습니다. 이것은 문서로 대체할 수 없으니 파일로 내야 합니다.

| 묶음(서버 `~/storage/nadan/farmai_img/data/local/`) | 행 조건 | 장수 | 집에서 접근 |
|---|---|---|---|
| `im_set_v5` | `kind == ai_gen_xl` (`ai_gen_xl_*.jpg`) | 900 | **불가(서버에만 있음)** |
| `im_set_gpt1` | `kind == gpt_gen` (`gpt_gen_*.jpg`, 학습에 쓴 JPG) | 25 | 불가(드라이브에는 코덱스 원본 PNG만 있음) |
| `im_set_sd2` | `kind == ai_gen` | 42 | 드라이브에 있음(집에서 처리) |

## 해 줄 일
1. 서버에서 위 두 묶음의 해당 행 이미지 925장을 연구실 PC의 아래 폴더로 복사해 주세요. 그 폴더는 드라이브 `lab_claude_local/최종검증_생성이미지/`로 동기화됩니다.
   - `연구실/클로드/local/최종검증_생성이미지/im_set_v5_ai_gen_xl/` (900)
   - `연구실/클로드/local/최종검증_생성이미지/im_set_gpt1_gpt_gen/` (25)
   - 각 폴더에 `sha256.csv`(file, bytes, sha256)를 함께 만들어 주세요. 파일 이름은 manifest의 `file` 열 그대로 씁니다.
2. 확인해 줄 것:
   - 두 묶음이 최종 모델(기본 판별기 `im20`, 전문가 `im20e`, E_gpt 등) 학습에 실제로 들어갔는지
   - `gpt_gen_*.jpg`가 코덱스 원본 PNG(`ai_gen_work_20261013_v1/결과_GPT/1_전체생성/`)를 어떤 스크립트로 변환한 것인지(`im21_gpt_set.py` 등)
3. 다른 학습 묶음에도 AI Hub 원본(`source`)이 없는 행이 있는지 서버 manifest로 한 번 더 확인해 주세요.
   - 집에서 확인한 결과: `source`가 빈 행은 위 3종(v5 900, sd2 42, gpt1 25)뿐입니다.
   - 확인한 범위: v4·sd2·v5·gpt1·gpt2·gpt3·gptr·gptr_src·newreal·v7tr·qwentr·h3·h3j
4. 끝나면 사용자에게 "드라이브 동기화 완료"라고 알려 주세요. 집 클로드가 아래 셋을 묶어 접수용 ZIP을 다시 만듭니다.
   - 위 이미지
   - 원본 대응 해시 표(학습 이미지 → AI Hub 원본 경로 → 원본 SHA256, 집에서 계산 중)
   - README 보완

## 용량
- SDXL 900장은 768×1024 JPEG Q92 기준 약 0.3~0.5GB로 예상합니다.
- 이미지 ZIP 합계는 1.5GB 안팎일 것입니다(한도 파일당 10GB).
