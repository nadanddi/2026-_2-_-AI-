## 문제와 진행 범위
기존에 합의한 EC 예측 문제를 유지하고 원시 자료부터 다시 계산했다. 목표는 현재·이전 같은 온실 입력으로 sub_ec를 설명하고 기존 EC v2보다 안정적인 모델을 찾는 것이다. 이번에는 데이터 품질과 변동 구조까지 완료했다. 모델 훈련·성능 개선 주장·제출 파일은 없다. 이후 모델 단계에서 predictive-modeling을 적용한다.

## F1. 대상 자료는 온실별 200개 완전한 하루로 구성되지만 연속 200일은 아니다
- 근거: train_X 309,990행/51개 온실, train_y ID 304,965행. F13/F47 입력 각각 4,800행·200일, 모든 관측일이 24행. 각 온실 시간 공백 4곳, 관측 시작~끝 사이 미관측 912시간.
- EC 탐색은 잠금 40일·960행을 제외한 360일·8,640행이며 두 온실 각각 180일·4,320행이다.
- 키 중복 및 선택 EC 정답의 입력 조인 실패 0. 사용할 입력 14열의 완전 중복 벡터도 이번 8,640행에서 0.
- 코드: run_profile.py의 keys/compute. 검산: csv 단독 파서로 EC 행수·일수 일치.
- 신뢰도: 높음(배포 자료 안의 구조). 한계: 상대 day는 달력 날짜가 아니고 시간 공백을 실제 센서 고장으로 해석할 수 없다. 전역 정답 ID 조인 실패를 모두 검사한 것은 아니며 EC 분석에 사용한 정답만 검사했다.

## F2. 대상 온실에 직접 관리 채널 일부가 전혀 없고 실내 센서에는 결측이 있다
- 근거: 대상 입력 9,600행에서 in_rad/act_side/act_valve/act_cool/act_pump 각각 9,600행 결측. 평가 MASK와 일치한다. 가용 열 14개.
- in_temp 73/9,600행, in_hum 67/9,600행, in_co2 77/9,600행 결측. 결측 합집합은 이 셋의 합과 같다고 가정하지 않는다.
- 습도·장치 0~100, 일사·풍속·CO₂ 음수 검사에서 대상 입력 위반 0. 온도는 음수가 합법적일 수 있어 동일 규칙을 적용하지 않았다.
- 코드/근거: column_profile.csv(target_train). 원본 삭제/치환/보간 0건. 정제 전후 대상 입력 9,600행 유지.
- 신뢰도: 높음(결측/명목 범위). 한계: 범위 안이라고 센서가 정상임을 증명하지는 않는다. 급액·배액량·수분 상태를 직접 관측할 수 없다는 한계를 구동기 대리로 자동 해결했다고 가정하지 않는다.

## F3. EC 변동은 하루 안보다 날짜 간에 훨씬 크다
- 근거: 잠금 제외 8,640행의 평균 중심 제곱합 1,356.118157. 온실 평균 차이 9.772434(0.7206%), 같은 온실 내 하루 평균 차이 1,281.967975(94.5322%), 하루 평균 주변 일내 변동 64.377748(4.7472%). 세 항의 합이 총 제곱합과 일치한다.
- 원자료를 두 번 독립적으로 다시 읽어 계산했고 csv/math.fsum 방식으로 네 제곱합을 검산해 일치했다. verification PASS.
- F13 EC 평균 .554879/중앙값 .4435/범위 .063~2.739, 하루 최대−최소 중앙값 .068. F47 평균 .487616/중앙값 .345/범위 .063~3.232, 하루 최대−최소 중앙값 .055. 각 n=4,320행·180일.
- 코드: compute 분산 분해, cross_check 독립 산술. 근거: profile_result.json 및 unlocked_daily_ec.csv.
- 신뢰도: 높음(기술통계 항등식). 한계: **정답 변동 분해이며 v2 예측 오차 분해가 아니다.** 하루 평균은 정답을 본 사후 요약이고 예측 특징으로 사용하면 안 된다. 94.53%는 성능 개선 가능 비중 또는 성능 하한이 아니다.

## F4. 상대 날짜 후반의 EC 평균이 높지만 원인은 아직 구별되지 않았다
- 고정 구간 day<179/day>=179 사용(기존 잠금 구간 구분과 동일).
- F13: .544052(n=3,744행/156일) → .625257(n=576행/24일).
- F47: .476149(n=3,792행/158일) → .569973(n=528행/22일).
- 코드: compute의 period 집계, period_ec.csv. 방향이 두 온실에서 같음.
- 신뢰도: 높음(해당 표본의 평균), 낮음(인과 및 다른 기간 전이). 한계: 후반 소표본, 큰 EC 날·출처/운영 상태 구성 차이, 자료 재배열과 잠금 제외의 영향을 구별하지 못했다. 날짜만으로 보정할 근거가 아니다.

## 검증과 반론
1. “기존 결론을 복사한 것 아닌가?” → 원시 CSV 재독·두 번 재계산·별도 csv/math 검산 완료. 과거 자료를 다시 보는 연구이므로 독립 확증은 아니다.
2. “94.53%면 하루 수준 모델만 만들면 해결되나?” → 설명 가능한 입력이 있는지 아직 확인하지 않았다. 변동 크기와 예측 가능성은 다르다.
3. “센서 범위가 정상이면 정제 필요 없나?” → 명목 범위만 통과했다. 반복·출처 전환·센서 거칠기와 결측의 영향은 다음 탐색 대상이다.
4. “봉인 데이터도 봤나?” → 40일 목록은 제외용으로만 읽었고 해당 정답 문자열을 숫자로 변환하기 전에 건너뛰었다. 어떤 잠금 점수도 계산하지 않았다. 대상 입력 구조 진단에는 잠금일 입력이 포함되며, 정답 분석과 분리된다.
5. “평가 입력으로 규칙을 골랐나?” → test_X는 열과 전결측 MASK만 사용했다. 값 분포·빈도·평가 가중치·채택 판단에 사용하지 않았다.

유의성 검정 0회, 모델 선별 0회. 삭제·값 치환 0건. 판정: 구조 진단 완료, 모델 채택 없음.
