이미지 미션 독립 개발 계획 v7 — 금실·설향 350GB 수신 단계
2026-10-10 · 집 · 코덱스
상태: 계획. 수신 경로는 G:\내 드라이브\농업 AI 경진대회\이미지 미션. 현재 PC는 RTX4050 Laptop/6141MiB(nvidia-smi), C: 여유 약167GiB(이번 목록 조사 시점). 학습 장소는 아직 지정되지 않았으므로 현재 PC는 QA 예산의 기준으로만 사용. 350GB는 사용자 전달 규모이고 전체 수신량/해제 크기/농장·개체 구성은 미확인. 디렉터리 목록만 조사했고 대용량 archive 내용은 읽지 않음.

1. 이번 방향과 목표
팀원 v5 모델·설명서·사용자 전달 0.77은 참고자료로만 격리한다. 해당 가중치/학습 구성/점수를 우리 기준 모델, 목표 점수, 채택 근거, 필수 재현 조건으로 사용하지 않는다. 팀원 학습 코드 확보 때문에 우리 진행을 기다리지 않는다. 기존 PLAN_v4의 10절은 이번 지시로 대체한다. 우리 데이터 계보와 검증을 독립 설계하고 우리 기준 모델을 처음부터 학습한다.
목표: 실제 사진(0) 대 전체 생성·합성·의도 필터·전체 스타일·부분 생성·부분 스타일(1). 규정상 threshold .5, Accuracy 주지표. 공개21은 이미 관찰한 진단 예시로만 유지하고 학습·임계값 조정·확증에 쓰지 않는다. 이미지 점수의 숨김 유형 비율은 모른다.

2. 다운로드 중부터 가능한 일 — 전량 해제보다 인벤토리 먼저
사용자가 다운로드 중이므로 다운로드를 중단·재배치·삭제하지 않는다. provider/전송 완료·예상 파일 목록/크기·분할 파트·로컬 오프라인 가용성을 각각 확인한 완결 파일만 읽는다. 크기 안정과 일반 파일 속성만으로 로컬 완료를 판정하지 않는다. 부분 ZIP이나 분할 압축 일부를 정상 자료로 간주하지 않는다. split archive는 모든 파트와 무결성 확인 후 처리한다.
수신 manifest: archive 경로/크기/수신완료 상태/품종/배포 split/이미지·JSON 수/압축내 해제예정 byte/중복 entry/압축검사 결과. 오프라인 가용성을 확인하기 전에는 archive open·CRC 전체검사·전체 SHA를 하지 않는다. Drive seek/해시가 대량 캐시 다운로드를 유발할 수 있다. 실제 수신 폴더는 099.지능형 수직농장 통합 데이터(딸기)/01.데이터/1.Training/원천데이터_add_20260807 및 라벨링데이터_add_20260807이며, 확인된 형식은 TS_1.금실N.tar와 TL_1.금실N.tar이다. 전체 설향 수신 여부는 아직 확인하지 않았다. TAR에는 ZIP 중앙목록이 없으므로 전체 헤더 순회도 사전 I/O 예산 없이 하지 않는다. 작은 TL 한 묶음을 오프라인 확인 후 분석하고 그 목록으로 대응 TS의 선택 범위를 정한다. TL의 fname/image_id와 TS archive member 이름이 일치한다고 가정하지 않고 대응 규칙을 실제 소량 대조로 확인한다. TS 선택 추출도 순차스캔 비용을 별도로 계산한다. 공급자 sidecar/index가 없으면 완결 로컬 TAR 한 개를 전체 파일 byte가 예산 안에 들 때만 순차 스캔하고 member offset 로그를 보존한다. 선택 몇 장만 추출해도 탐색 I/O는 전체 TAR일 수 있으며 HTTP/Drive range 최적화를 실측 전에 약속하지 않는다. TAR 경로 탈출/링크/중복 entry는 추출전 차단한다. 배포 Training/Validation 구분은 출처 정보로 보존하되 원본 그룹 누수 없는 분할이라는 보장으로 사용하지 않는다.
로컬 여유공간·해제 byte·작업 캐시·파생 출력·가중치/로그를 합산해 필요한 공간을 계산한다. 350GB를 일괄 해제하거나 자동 삭제하지 않는다. G: 표시 여유공간을 독립 로컬 여유나 cloud quota로 해석하지 않는다. Drive cache 실제 볼륨/오프라인 보존 위치를 확인하고 C:와 공유하면 합산한다. 첫 QA의 신규 로컬 작업 캐시 상한은10GiB, 현재 작업 볼륨 free-space 최소30GiB를 예산에 남기며20GiB 미만이면 읽기·추출을 중지한다. 이는 QA 자원 상한이며 다운로드 원본의 이동/삭제 지시가 아니다. 선택 archive 한 묶음의 hydration+추출+파생 예상 byte가 남은 예산 안에 들 때만 진행하고 예상 초과/전송 불일치면 중지·기록한다. 다음 확대의 캐시 예산은 실제측정 후 새버전에 등록한다. ZIP 랜덤 접근이 느리면 승인된 저장 위치의 선택 원본만 캐시하며 archive+entry 좌표를 보존한다. 원본 ZIP과 작업 복사본을 구분하고 원본은 불변 보존한다.
완료된 작은 묶음부터 금실·설향 모두의 여러 농장/개체/날짜/생육단계를 점검한다. 품종 하나만 먼저 준비되면 파이프라인 QA까지만 수행하고 양 품종 일반화 완료라고 하지 않는다. 원본 구조·권리/실제사진 제작이력도 자료에 근거해 확인한다. 350GB 전체를 모든 epoch에 읽을 이유는 없다.

3. 데이터 진단과 누수 방지 — 사진 수보다 독립 그룹 수
이미지 decode/실제크기/색공간/EXIF회전/JSON 연결/촬영시각/농장·개체 ID 의미/품종/생육단계/손상·중복·근접연속 장면을 코드로 조사한다. 파일명 숫자를 검증없이 개체 ID로 삼지 않는다. 금실·설향 각각의 농장·개체·촬영날짜 교차표와 자연 blur/noise/압축의 분포를 보고한다. 허브 raw 전체에 라벨0을 붙이는 것은 출처가 실제 촬영임을 확인한 뒤에만 가능하다.
그룹은 농장→개체/카메라/촬영세션→같은 장면/연속 프레임 계보를 추적해 구성한다. 동일 식물의 다른 날짜는 독립으로 취급하지 않는다. 정확 SHA와 근접 영상 검색으로 양 품종·배포 split 사이 중복을 감사한다. EXIF/JSON·파일명은 분할 감사용이며 모델 특징으로 쓰지 않는다.
기존 관찰 샘플340의 근접 장면과 공개21의 대응 후보 계보는 별도 개발 영역으로 격리한다. 이미 시각 확인한 장면은 새 잠금 확증에 들어가지 않게 목록을 등록한다. 정확히 누가 무엇을 봤는지도 로그에 적는다.

4. 검증자료부터 잠금 — 양 품종이 있어도 농장 다양성이 보장되지는 않음
우선 자료의 농장×품종 교차표를 확인한다. 한 품종이 한 농장에만 있으면 품종 효과와 농장 효과를 분리할 수 없다고 명시한다.
주 개발검증: 농장을 나눌 수 있으면 농장 단위 그룹 CV를 우선. 세 fold 각각에 필요한 두 라벨·여섯 양성 유형이 있어야 하며 가능한 경우 양 품종도 배치한다. 조건이 부족하면 fold 수를 줄이고 성능 범위를 제한한다. 농장 외삽을 못 하는 경우 개체/장면 그룹 CV는 농장 내부 성능으로만 해석한다.
보조검증: 개체 단위, 새 촬영세션/시기, 금실→설향 및 설향→금실 전이(가능한 경우)를 각각 별도 진단. 교차 품종 결과는 농장 공변량 때문에 품종의 순수 효과라고 하지 않는다.
잠금 확증: 점수 확인 전 미사용 농장/원본 그룹을 따로 예약한다. 개발자에게는 메타데이터/자동중복 감사 결과만 공개하고 예약 원본·파생 contact sheet/생성 결과/QA는 모델 개발과 분리된 담당이 확인한다. 이 담당은 최종모델 예측을 보지 않고 recipe hash와 무결성/제작실패 보류 규칙을 먼저 동결한다. 분리 담당을 확보하지 못하면 개발자가 검토한 자료는 개발 평가로만 보고 독립 확증이라고 부르지 않는다. 우리 비평가는 계획/자동 누수 감사는 볼 수 있지만 개발 조언에 사용할 확증 이미지/개별 예측은 잠금 해제 전에 보지 않는다. 파일·그룹·실제사진 수를 고정하고 평가쪽 양성은 그 fold 내부 원본/공여자/참조만으로 만든다. 합성의 모든 부모와 공여자를 같은 split 안에서 고르고 계보를 상속한다. split을 먼저 하고 증강은 나중에 한다. 평가 공개 금지 대상은 개별 결과·연락시트·모델 오답 선정까지 포함한다.
평가 변형은 개발과 다른 사전 등록 recipe/generator family로 만들고 저장한다. 같은 생성기의 다른 seed는 unseen-generator 검증이 아니다. 생성기 하나뿐이면 그 일반화는 미평가. 평가자료 생성 담당/보존 절차를 로그로 남기고 최종 확증은 개발팀에 숨긴 채 평가만 수행한다.
잠금 자료를 보고 수정한 모델은 그 자료로 다시 확증하지 않는다. 새 확증 자료가 없으면 탐색 결과로만 남긴다.

5. 작은 제작 QA에서 단계적 확대 — 수치들은 계획 상한
첫 제작 QA: train 원본 최대8개를 가능한 서로 다른 그룹에서 선택, 양 품종을 포함할 수 있으면 각각4개. 실제8 + 양성6유형 각8 = 56파일 목표. 그룹/품종 부족이면 수를 줄이고 독립성능 측정에 사용하지 않는다. 진짜 생성모델을 못 쓰는 유형은 미제작으로 적고 고전 필터로 바꿔 유형을 채운 척하지 않는다.
다음 개발 파일럿: train 원본 최대200개(품종별 목표100, 그룹 수가 허용할 때만). 원본 그룹 균등 우선, 반복 장면은 추가 독립 표본으로 계산하지 않는다. 여섯 유형 각1변형을 원본당 만든다고 가정하면 train 실사진200+양성1200=1400파일; 생성비용·독립그룹 수에 맞춰 줄일 수 있으며 1400은 성능 보장 목표가 아니다. 검증 원본·파생은 별도 예산으로 산정한다.
개발 원본 200→1000→5000 확장 후보는 새 농장/개체/단계가 늘거나 오류 유형을 보강할 때만 진행한다. 반복 프레임과 같은 레시피만 늘리는 것을 다양성 확보라고 하지 않는다. 학습곡선은 같은 잠금 개발검증에서 원본 그룹 수 대비 측정하고 최종 확증은 건드리지 않는다.
유형별 제조: 전체 생성은 장면/조명/배경/생육단계를 분산하고 실제 모델 생성 기록을 보존; 합성은 split 내부 작물/배경 donor와 경계; 의도 필터는 blur/noise/saltpepper/JPEG; 전체 스타일은 실제 표현 변환; 부분 생성은 생성 모델로 위치·면적을 분산한 재구성; 부분 스타일은 제한 영역 표현 변경. 품종 이름은 참조/조건 기록이지 출력 식물의 품종을 보증하는 라벨이 아니다.
부분 편집은 최종 입력에서 실제 바뀐 영역과 비율을 QA한다. 모델이 제공하지 않는 mask/seed/version은 unknown으로 적고 추정 사실로 채우지 않는다. 작은/중간/큰 영역, 식물/배경, 약한/강한 신호를 분리 보고한다.
공통 resize/crop/JPEG 저장은 두 라벨에 같은 규칙. 의도적인 JPEG 위조 제작과 공통 배포 저장은 별도 이력. 자연 촬영 blur/noise를 label0으로 포함하되 필터를 새로 넣은 이미지를 label0으로 뒤집지 않는다. 라벨은 제작 이력 기준이고 양성만 특정 확장자/테두리/해상도/워터마크를 갖게 하지 않는다.
원본·모든 부모·donor·모델/서비스·prompt·mask·변형값·최종 SHA 보존. 최종 픽셀이 대조 real과 완전 동일하거나 실제 편집0/관측영역 밖이면 라벨·파일 보존 후 학습/집계 보류 목록에 둔다. 비영 약신호는 어렵다는 이유로 제거하지 않는다. 보류 정의는 첫 학습 전에 코드 고정한다.

6. 독립 기준 모델과 한 번에 한 변경
GPU/VRAM/디스크/파이썬 환경을 실제 확인한 뒤 비용을 산정한다. 다운로드 종료 시간이나 학습 시간을 추정으로 약속하지 않는다.
B0: 상수 확률 .5, 출력 계약과 지표 코드만 검증. threshold>=.5 규칙이면 전부1이므로 정확도는 라벨분포에서 계산하고 임의로50%라 단정하지 않는다.
B1: 독립 ImageNet 초기화 ResNet18 전체화면384 비율보존/공통pad. 이는 팀원 weights와 무관한 신규 모델. 기존v3의 optimizer·학습스케줄은 초안으로 유지하되 VRAM 검사 후 첫 fit 전에 코드로 고정. 공개21로 hyperparameter 선정 금지.
B2: B1 기준과 같은 자료/초기 seed로 원본 해상도 국소patch bag 추가. 부분 양성의 모든 patch에1을 붙이지 않고 mask가 있을 때에만 위치감독 또는 이미지 bag 감독을 쓴다. patch 개수·선택·집계는 train 개발검증에서 등록하고 잠금 평가에서 변경하지 않는다.
고주파 경로는 B2가 필요하다는 오류 증거가 있을 때 별도 한 변경 후보. 팀원의 top5/highpass를 필수 채택하지 않는다. 데이터 보강과 모델 구조 변경을 동시에 하지 않는다.
훈련 sampling은 real/positive 각.5, 양성6유형 균등은 시작 진단 가정이며 숨김 분포와 일치 주장X. 원본 group 균등을 우선하고 품종/농장 sampling 가중치를 로그에 남긴다. 학습과 평가의 클래스·유형 가중치 차이를 보고한다.
먼저 한 seed 파이프라인 시험, 중간 비평으로 누수/라벨/배치/메모리 점검 후 동일 실험의 3seed[20261010,20261011,20261012]를 완료한다. 일회 run을 기준 성능 채택으로 삼지 않는다.

7. 지표와 후보 판정
threshold .5 고정. raw Accuracy/AUROC/F1 + real 오탐률/여섯 유형 미탐률/품종/농장/생육단계/자연 흐림/편집 면적별 원분모·원본그룹수를 보고한다. real:positive .5:.5 및 양성6유형 균등 표준 Accuracy는 내부 진단 가정으로만 보고한다. 숨김 유형 비율을 모르므로 단일 예상 대회점수로 환산하지 않는다.
후보는 3seed×사전 등록 주검증 모두 같은 개선 방향, real 오탐 및 여섯 유형 미탐이 악화하지 않는 guard를 기본으로 둔다. 어떤 유형이 없는 검증은 그 guard 미평가이므로 전유형 채택을 보류한다. 품종/농장 보조검증의 악화도 확인하고 원인 조사 전 채택을 보류한다. 작은 수의0오류를 완벽한 일반화라고 하지 않는다.
원본/농장 그룹 paired 비교 및 그룹 bootstrap 구간·악화 꼬리로 불확실성을 제시하되 이를 보통 빈도주의 p값이라고 하지 않는다. 그룹 수 부족/퇴화는 탐색으로 판정. 첫 fit 전 자료 프로파일 후 농장·개체·품종·유형별 최소 독립 분모와 신뢰구간 정밀도 목표를 등록한다. 정밀도 목표 초안은 real 오탐률 및 유형별 미탐률의95% 구간 반폭≤.10이며 이 기준 자체도 첫fit전에 동결한다. 필요한 수는 cluster 크기/그룹 간 편차를 반영한 사전 계산으로 정하고 사진200/1000/5000에서 환산하지 않는다. 분모/정밀도 미달층은 탐색 등급으로 표시하고 전유형 확증 채택을 보류한다. 개발3fold 구성 불가 또는 확증 농장 외삽 자체 불가이면 각 검증 범위를 축소·명시하며 가상의 충분성 수치를 채우지 않는다. EC의 DIAG10을 이미지에 그대로 적용하지 않는다. 원칙은 개발에서 고른 후보1개를 새 잠금자료에1회 확증한다. 여러 후보의 예외는 평가 전에 가족 전체가 고정된 동시 평가에 한하며 사전 k와 .025/k 꼬리 기준을 등록하고 가족·재사용 횟수를 공개한다. bootstrap 꼬리는 빈도주의 p값/가족오류 보장을 의미하지 않으며 단독 채택 근거로 삼지 않는다. 개발 적응 탐색이 이 기준만으로 모두 보정됐다는 주장은 금지. 유효 확증 설계와 충분 독립 그룹이 확보되지 않으면 정식 채택 없이 탐색 후보 유지.
실험 로그에는 가설/단일 변경/등록시점/split hash/recipe hash/코드·가중치 hash/seed/농장·유형별 분모/시간·VRAM/원본 OOF/비평·수정 내역을 남긴다.

8. 혹독한 비평가 운영 — 각 실험 세 차례, 수정 뒤 재검토
계획 전: 별도 비평가에게 원본 계보·split·의도 라벨·공통처리·선정 편향·표본 수·규정·재현·비용을 공격하게 한다. 치명적/중요 지적은 새 버전으로 고치고 재검토 전 본 실험을 시작하지 않는다.
중간: 첫 제작 QA와 첫 seed/fold 결과에서 파일/마스크/중복/누수/출력/오탐 사례 확인. 관측한 개발 문제에만 수정을 적용하고 영향 받는 기존 실험을 새 버전으로 재실행. 잠금 확증 오답을 보고 학습 수정 금지.
최종: 코드·전체 로그·OOF·원분모·seed·누수·여섯 유형·주장·실행 계약을 독립 확인. 개선 불확실/미평가 항목이 있으면 탐색/보류로 낮춘다. 결과/계획→비평가 평가→확인된 문제→적용한 개선을 사용자에게 보고한다.
계획의 중간 수정 검토는 계획 리뷰이며 실제 학습 중간 점검을 대신하지 않는다. 비평가는 실제 근거를 읽고 모델 실행이 없는 단계에서 런타임 검증했다고 말하지 않는다.

9. 단계별 완료 조건과 다음 행동
A 수신/목록: 완결 ZIP 경로·수/해제 byte/공간 계획 확인 → 선택 진단 캐시.
B 진단/그룹: 농장×품종 표·중복/연속 계보·실촬영 출처·이미 본 자료 목록 → 분할 및 잠금 manifest.
C 제작 QA: train쪽 최대56파일 실제 전후/마스크/신호 보류 검토 → 비평가 중간 점검.
D 기준학습: 개발 파일럿과 B0/B1 한 seed 계약 확인 → 비평 → 3seed 기준 결과.
E 개선: 데이터/국소정보 등 단일 변경을 오류 근거로 비교 → 비평 → 탐색/보류/확증 후보 구분.
F 확증: 새 잠금 원본/변형 단회 확인 → 최종 비평. 그 후에도 사용자 요청 전 제출파일·확정 구성은 만들지 않는다.
보존 위치: 코드/계획/작은 로그는 집/코덱스/analysis/, 무거운 캐시·파생·가중치는 집/코덱스/local/. 외부 다운로드 원본은 사용자의 저장 경로 그대로 보존. main 단일브랜치/새 버전 원칙 유지.
