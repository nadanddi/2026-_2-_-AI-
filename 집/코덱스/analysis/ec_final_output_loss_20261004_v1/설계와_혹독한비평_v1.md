# 최종 출력 손실에 맞춘 LGB 학습: 설계와 비평

2026-10-04 · 집 코덱스 · family22/23 최초실행 전 설계 감사

사용자 #1 요청은 실제 출력 `clip(S(b+.24exp(F)),lo,hi)`의 시간별 RMSE에 맞춘 학습이다. 여기서 `b=.48ET+.08MLP+.20PFN`이고 query b는 기존 actual계절v2 캐시를 고정한다. 학습 b는 innerOOF 구성원만으로 만들어 자기정답을 맞춘 in-sample ET/MLP/PFN이 새 LGB의 학습목표를 왜곡하지 않게 한다. 이 문서는 합성만 실행했으며 실제 EC fit/predict/score/rawEC/test/EL1 접근0이다.

## 정확한 수식과 근사 구분

한 farm/day의 시각 순서에 대해 `S=.5I+.5P`, `P_hk=1/(h+1)`(k≤h), 나머지0이다. 여러날 S는 block diagonal이고 각날24행 완전성을 검사한다. 부분 batch 추론에서도 **그 batch의 첫시각부터 새로 누적**하면 안 되고 해당평가 h까지 같은날 prefix가 포함돼 있어야 한다.

`u=exp(F), d=.24u, a=S(b+d), z=clip(a,lo,hi), r=z−y`라 두고 학습손실은 `L=.5∑r²`로 고정한다. RMSE와 제곱손실의 최소화점은 같은 n에서 같지만 gradient·regularization scale은 다르다. 평가 RMSE를 학습손실 스칼라와 혼동하지 않는다.

lo<a<hi의 output active mask C에서 clip 경계를 피한 매끄러운 영역의 미분은 다음과 같다.

```
q(raw EC)에 대한 gradient = .24 Sᵀ C r
F(log raw score)에 대한 gradient g = d ⊙ Sᵀ C r
GN = diag(d) Sᵀ C S diag(d)
정확 F-Hessian H = GN + diag(g)
```

정확 H는 같은날 비대각 항을 갖는다. log-chain의 `diag(g)`는 음수일 수 있어 H는 일반적으로 positive definite가 아니다. '제곱손실이라 Hessian은 항상 양수'는 q의 선형좌표와 F의 비선형좌표를 혼동한 것이다. clip 경계 a=lo/hi에는 고전적인 양방향미분/Hessian이 없고 경계밖 output의 미분은0이다. 구현에서 경계 mask strict/closed 선택은 수치 convention으로 기록하고 새로운 매끄러운손실이라고 주장하지 않는다.

**주의: output i가 clip됐다고 raw F_i gradient를0으로 만들면 틀린다.** 해당raw가 뒤시각active output에 들어가므로 C는 r에 먼저 적용한 뒤 Sᵀ로 전달해야 한다. forward S로 residual을 평활화하는 것도 틀리다. 정확한 backward adjoint는 각날 끝에서부터 `.5 r_i + .5∑_{h≥i}r_h/(h+1)`를 계산한다.

LightGBM sklearn custom objective는 raw prediction좌표에 대한 행별 grad/hess 배열을 받는다. 이 API로 full cross-row Hessian을 전달할 수 없으며, objective(y_true,raw_pred)의 **정확히2인자 closure**를 권한다. 이전 온도group-loss는 optional3인자가 sample_weight로 해석된 실제오류가 있었다. [공식 LGBMRegressor 문서](https://lightgbm.readthedocs.io/en/stable/pythonapi/lightgbm.LGBMRegressor.html)

### family22 대각 surrogate의 정직한 표현

대각 Hessian만 반환하는 경우 **정확 gradient + 명시한 curvature surrogate로 트리를 학습**한다고 기록한다. diag(H)를 그대로 넘기면 음수 가능, diag(GN)는 양수지만 log-chain와cross항을 모두 버린다. 어느것을쓸지는 최초fit전 고정한다.

선택가능한 보수적인 local 대각majorizer는 `h_i=∑_j GN_ij+|g_i|+eps`다. GN원소는 비음수이며 `diag(h)−H = Laplacian(GN)+diag(|g|−g+eps)`가PSD다. row sum은 densematrix없이 `d ⊙ Sᵀ[C(Sd)]`로 계산한다. 이는 **현재점의 해당smoothregion Hessian 상계**이며 전역 clippedloss upper-bound/MM수렴 보장이 아니다. eps/정규화/step 정책은 원EC결과보기전에고정한다. 이 방법도 정확 Newton이 아니다.

원reg_lambda=1을 유지해도 loss좌표/curvature scale 변화로 실효정규화가 달라진다. mean loss로 나누고λ1을 그대로두는 것은 sum loss와 같지 않다. derivative 전체에 임의상수를 곱하거나 .24를떼고λ1을유지하면 후보정의가 바뀐다. user가 지정한 변경범위를 기록하고 사후λ·혼합비·시드 튜닝은 하지 않는다.

### fixed-tree leaf를 공동 최적화하는 설계

현재트리의 각훈련행leafmembership행렬 T와 leaf logincrement θ를 정의하면

```
F_new=F_old+Tθ
G_leaf=Tᵀg
H_leaf=TᵀHT
```

H_leaf는 crossleaf도 결합한다. 같은leaf 안의 crossrow도 포함돼 `diag(H_leaf)`조차 '각행 h의leaf합'과 일반적으로다르다. 트리구조선택은 surrogate여도 고정leaf이후 true final loss의 jointly refined θ를 구하는 실험은 가능하지만, 전체트리/global optimum을 정확히풀었다고 말하면 안 된다.

정확 H가indefinite일수있어 고정한 damping/trust-region과descent검사, 실제clippedloss line-search가 필요하다. clip active set이바뀌면현재Hquadratic은맞지않으므로 true loss로step수락한다. 선탐색의 λpenalty가 적용되는좌표가 unshrunk θ인지 실제update=.03θ인지 고정하고 .03은한번만적용한다. jointsolve에l2를넣고nativeleaf에서도다시l2를넣거나, nativelearningrate뒤에다시.03을곱하면중복이다. 같은날정답 전체를학습목적으로사용하는것과 평가행future feature를추론에쓰는것은별개다.

표준 C++ RenewTreeOutput 인터페이스는 leaf당 scalar를 반환하며 seriallearner는 leaves를병렬로돌며출력을쓴다. 따라서 독립leaf callback만 고쳐 coupled전체해를얻었다고주장할수없다. trainingfullrow currentF/b/y와전leafmembership를집계해 **한번에θ를계산하고 한번에적용하는 별도중앙경로**가필요하다. 임의공유state로perleaf callback끼리serial같은갱신을하면스레드순서비결정성도생긴다. 이는원Tweedie에서각leafλ1근을독립정확갱신하는사용자#2와다른변경이다. [공식 objective 인터페이스](https://github.com/lightgbm-org/LightGBM/blob/main/include/LightGBM/objective_function.h), [공식 seriallearner 구현](https://github.com/lightgbm-org/LightGBM/blob/main/src/treelearner/serial_tree_learner.cpp)

위온라인소스는검토시main이며 runtime핀의패키지/C++source동일성을증명하지않는다. 실제overlay는로컬고정version/source/binarySHA와등록후재검사를별도로한다.
