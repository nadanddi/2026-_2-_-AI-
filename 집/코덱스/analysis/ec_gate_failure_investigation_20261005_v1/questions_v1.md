# EC 동적 앙상블 실패를 분리하는 조사

2026-10-05 집 코덱스. 목표는 해결 가능한 경로의 근거 확보이며 제출 후보 채택은 이 조사에서 하지 않는다. 이미 프로파일·검산된 공개 OOF/원입력만 사용한다. 탐색 수치를 본 뒤 문턱/하이퍼파라미터를 바꾸지 않는다.

1. 고EC 손실은 잘못된 이동 방향, 올바른 방향의 과도한 이동, 작은 도움이 합쳐져 생겼는가? ΔSSE=-2r·gd+(gd)^2를 원행과 일별 수준/모양으로 정확히 분해한다. r=y-A,d=B-A.
2. B endpoint 승리확률은 최적 혼합률과 얼마나 다른가? B가 패배해도 부분 혼합이 도움되는 행 및 oracle 이득을 집계한다. 정답 기반 oracle은 분석 전용이다.
3. 내부 메타학습에만 잘 맞는가? 원 inner b 안에서 farm별 정렬한 5기록일 블록을 3fold(ordinal//5 %3)로 나누고 ±1일 purge한 메타 OOF를 새로 만든다. 기존 A/B와 모든 게이트 설정은 고정한다. A/B는 별도 a에서 이미 학습했으므로 b의 새 meta fold 정답은 A/B나 gate fit에 들어가지 않는다. DIAG10 원10fold×3seed×3모델×3meta fold=270 fit(단일class/빈자료 fallback은 그대로). 점수 채택/튜닝 목적이 아니다.
4. 참조자료 차이가 원인인가? 외부 query/A/모델을 고정하고 B 참조를 outer train에서 inner a로 제한한다. B만 교체, 게이트 입력만 교체, 양쪽 교체의 2×2 대조로 계산 경로를 분리한다. 같은 참조 수라도 고EC 비율/농장/pass/보정 방향은 다를 수 있음을 층화한다.
5. 고EC 손실은 소수 날짜/하루 수준에서 집중되는가? 일별 positive 손실합·net 손실합 및 level/shape 차를 구분한다. net 분모의 비율>100%를 설명하고 오해하지 않는다.
6. 고정 실패/오탐 사례 F47/229·231, F13/151, F47/154, F13/231·233, F47/216의 0/6/12/23시 참조 날짜·참조정답평균·현재prefix/A/B·gate를 실제 추적한다. 코드에 사례ID 예외는 넣지 않는다.
7. 어디를 고쳐야 할까? 입력만으로 계산 가능한 down/up 제거 대조와, 정답으로 잘못된 방향/overshoot를 제거하는 분석 oracle을 분리한다. 사후 대조의 개선을 채택 또는 일반화 증거로 취급하지 않는다. 검증A/B에서도 같은 문제가 있는지 확인한다.

근거 계약: 모든 발견은 실행 수치+코드+층화+반론을 포함한다. 원SSE/RMSE/분해를 fsum/독립 scalar로 재계산하고 270 메타fit의 분할/비용/스케일러/직렬화를 검산한 뒤 결론을 낸다. 통계 가설 채택 검정이 아닌 사후 기전 조사이므로 p값을 찾거나 유의한 subset을 고르지 않는다. 기존 원모델/동료파일/TabDPT 변경0·잠금0·test값0·제출0. 남은 불확실성은 정보부재라고 단정하지 않는다.
