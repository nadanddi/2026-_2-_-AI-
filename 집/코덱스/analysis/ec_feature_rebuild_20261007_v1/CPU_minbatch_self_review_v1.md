# CPU 최소 배치 수치 조사 — 자체 검토 (2026-10-07)

이 문서는 독립 비평이 아니다. 독립 비평가 재요청은 workspace credits 부족으로 실패했다. 기존 사전 채점 비평과 이번 변경의 자체 검토를 구분한다.

## 시작 증거와 범위

- 문맥8 기존 감사는 단일 마지막행 차이 2.0265579223632812e-6로 고정 atol=1e-6 실패. scattered96/역순8/교란8은 차0. 기존 실패 파일 보존.
- 숫자 연산 경로 차이는 가설이다. 정확히 어떤 Torch 연산이 차이를 만들었는지는 아직 특정하지 않았다.
- 최소8행은 이전 역순8 일치라는 정답 없는 수치 증거에 따른 조사 정책이다. 검증 정답/성능에 따라 선택한 파라미터가 아니다. CPU 정책이며 배포/GPU와 바이트 단위 동등성을 주장하지 않는다.
- adapter는 fit을 부르지 않고, 비어 있지 않은 2차원 float32 query 행렬만 받는다. 1~7행이면 전달된 마지막행을 복제해8행으로 만들며 실제행 개수만큼 출력을 반환한다. 8행 이상은 원래 입력을 그대로 예측한다. 새 센서값/정답/다른 날짜를 구해 추가하지 않는다.

## 로컬 라이브러리에서 직접 읽은 범위

- `.analysis-tools/extra/tabpfn/architectures/tabpfn_v2.py` 200행 이후: query projection은 행별 적용. key/value는 `:N` 학습행에서만 계산하고 평가행 attention은 그 학습 key/value만 참조. cached 경로도 학습 KV만 사용한다. 이 코드 부분은 평가행 간 attention이 없음을 뒷받침한다.
- `preprocessing/ensemble.py`의 `transform_X_test`는 `cpu_preprocessor.transform(X).X`를 호출한다.
- `preprocessing/pipeline_interface.py`의 `transform`은 `_process_steps(..., is_fitting=False)`를 호출한다. 실제 전체 전처리 구현이 모든 경우에 행별 독립이라는 포괄적 증명은 아니다.
- `preprocessing/steps/add_fingerprint_features_step.py` 전체를 읽음. salt는 fit 시 학습 셀 수로 고정하고 평가 변환은 중복행 hash를 그대로 사용한다. 평가 중복행에 새 충돌 salt를 만드는 학습 분기와 구분돼 있다.

## 통과 전 필요한 증거

1. 문맥8 기존96/역순8/교란8/실패 단일행을 동일 허용오차로 재검증하고 추가8개 독립 단일행을 검사한다.
2. 결과가 통과해도 나머지 문맥5..7에 같은 정책을 적용해 재검증한다. 작은2~7행 경로는 별도 검사가 필요하다.
3. 실제 전체1440행은 adapter의 무패딩 경로이므로 수치 정책 자체가 입력을 바꾸지 않는다. 새 gate는 원 전체출력/등록/adapter/감사소스의 SHA를 함께 검사해야 한다.
4. 실패가 남으면 gate를 열지 않는다. 허용오차를 올리지 않고 실패를 보존한다. 이 조사가 통과해도 성능 개선이나 최종 채택을 뜻하지 않는다.

## 아직 남은 제한

유한한 행 대조로 전체 수치 영역을 증명하지 못한다. 새 독립 비평은 미완료다. 원검증기 성능 및 처음 쓰는 seed/layout 확정 판정도 남아 있다.
