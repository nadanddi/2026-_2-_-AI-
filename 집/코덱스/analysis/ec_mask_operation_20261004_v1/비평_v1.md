## 가장 먼저 기각해야 할 가정

현재 코드 경로에 MASK를 적용해 제어 결측을 늘리는 단계가 있다는 근거는 없다. DP1→DB1→SE3→DC5→DC4→집/코덱스/analysis/ec_restart_phase3_20261001_v1/run_benchmark.py의 prepare를 텍스트로 추적했다. prepare는 train_X의 RAW14를 읽어 core.features(raw)에 넘긴다. core는 codex_independent/rl_ec_v1/run.py이며 features는 제어 원열을 그대로 반환한다. 원열 fillna나 MASK 상수 적용은 없다. lab는 이후 정답·split inner merge와 잠금 제외로 선택된다. 이는 소스 확인이며 금지 파일 내용을 읽은 것은 아니다.

따라서 'MASK 결측→0가 실제 실패 원인'은 아직 가설이다. train_X F13/F47의 해당 5열에 실제 결측이 없으면 이 구현의 fillna(0)는 실제 입력에서 아무것도 바꾸지 않으며, 결측 치환을 현재 실패의 설명으로 쓰면 안 된다. 결측이 존재해도 성능 원인이라는 결론은 나오지 않는다. 전수 train_X의 감사는 실제 lab의 선택된 행을 복원한 감사가 아니다. 다만 전수에서 결측이 0이면 모든 부분집합에서도 0이라는 반론은 확실하다.

## 실제 코드의 정보 손실과 반례

- seal_run: v==0에 NaN도 포함되어 미관측 시간을 연속 닫힘으로 세며, 관측된 닫힘과 결측을 구분하지 못한다. [0, NaN, 0]은 [0, 0, 0]과 완전히 같다.
- vent_open_hours/co2_hours: 양수 관측 개수만 센다. NaN이 양수인지 0인지 알 수 없지만 이를 0시간 운영으로 확정한다. coverage가 낮은 날과 실제 운영이 적은 날이 섞인다.
- first_open_hour: 결측 prefix 뒤 양수가 처음 보이면 '처음 관측된 개방 시각'이며 실제 최초 개방 시각을 보장하지 않는다. 24는 아직 개방이 관측되지 않았다는 sentinel이다. 하루 모두 닫힘인지 관측 부재인지 확정하지 못한다.
- thermal_switches/shade_switches: [양수, NaN, 양수]를 1→0→1로 해석해 가짜 전환 2회를 만든다. [0, NaN, 양수]에서는 결측 중 실제 전환 시각을 알 수 없다.
- since_curtain_change: 가짜 전환에서 시계를 재설정한다. 실제 시간 차가 아니라 행 위치 k 차를 쓴다. [hour0, hour2]처럼 누락된 격자에서 1은 1시간이 아니다.
- heat_run: [양수, NaN, 양수]에서 지속 난방을 끊어 버린다. seal_run에서 NaN이 연속을 늘리는 것과 반대 방향이다.
- vent_max: 미관측 양수 피크를 누락한다. 음수값이 가능하면 NaN→0가 관측된 음수 최대를 높일 수도 있으므로 실제 음수/비정상값 개수도 감사해야 한다.

core.features의 기존 *_tdz는 (s==0).where(s.notna()).expanding().mean()으로 결측을 분모에서 제외하고 *_tdm도 관측값 평균이다. DP1은 결측을 0 상태로 포함한다. 이 차이는 실제 결측이 있을 때만 발생한다. 기존 누적 평균과 DP1을 '같은 관측량의 다른 순서 표현'이라고 부르려면 coverage 차이를 먼저 제외해야 한다.

run_len과 since_curtain_change는 행 수 기반이다. vent_open_hours/co2_hours 역시 시간 적분이 아니라 관측 행 수다. 정렬만으로 중복 hour·누락 hour·24시간 완전성을 보장하지 않는다. 실제 행 격자가 매일 0..23이면 이 문제는 현 데이터에서 발현하지 않는다. 중복 row_id는 core에서 assert하지만 서로 다른 row_id가 같은 farm/day/hour로 해석되는 경우도 별도로 점검할 가치가 있다.

## 입력 감사가 충족해야 할 조건

1. DP1 원모듈을 import하지 않는다. upstream import에는 환경 로드와 OUT mkdir 등 부수효과가 있다. AST로 run_len/day_feats만 추출하고 원 함수의 텍스트 SHA를 저장한다.
2. 원열 5개 각각 NaN·실제 0·양수·음수·비유한 값을 farm 및 day<179/day>=179로 분리한다. NaN과 문자열 MASK를 동일시하지 않는다. 문자열 sentinel이 있으면 수치 변환을 암묵적으로 하지 말고 별도 검사한다.
3. F13/F47 전수 row_id·farm/day/hour 정합성, 중복, 하루 행 수, 정확한 0..23 격자를 확인한다. 완전한 격자 여부와 제어 관측 coverage는 다른 검사다.
4. pandas 원 함수 재생과 독립 루프 구현을 모든 행/9열에서 대조한다. NaN=0의 반사적 검산만으로 '의미 감사 PASS'를 선언하지 않는다.
5. 위 반례를 합성 입력으로 검사한다. synthetic missing과 실제 missing 영향수를 분리한다. 실제 입력에서 없는 결측을 주입해 얻은 변화는 실제 성능 문제의 증거가 아니다.
6. future perturbation, 다른 farm perturbation, prefix truncation, 행 순서 permutation으로 인과 범위와 정렬 불변성을 검증한다. 결측 의미 보존과 인과성은 서로 다른 성질이다.
7. missing을 별도 상태로 둘 때 기존 값과의 불일치 행 수는 '정답 구현으로 수정된 행 수'가 아니다. 누적 불확실성의 가능한 범위 또는 observed-only 지표로 명시한다. missing 다음 관측까지 실제 연속성은 입력만으로 복원할 수 없다.

## DCP1와 인과·성능 주장 제한

DCP1은 dp1.day_feats를 그대로 사용하면서 query season도 DC7로 바꾼다. 코드상 두 변경을 동시에 넣으므로 특징 의미 감사는 DP1/DC7의 성능 기여를 분해하지 못한다. R3S 기준선은 현재 계절v2의 .8R3+.2PFN과 같지 않다. 감사에 기준선 예측 복원이 없다는 사실을 분명히 해야 한다. 입력 특징 일치가 모델 출력 일치를 뜻하지 않는다.

DC7의 h>=5는 6개의 완전한 관측 시간이 있다는 검사가 아니다. nanmean은 남은 극소수 weather 성분만으로도 작은 거리를 줄 수 있다. match pair별 유효한 시간 수/4채널 완전한 시간 수와 차원 수를 따로 세어야 한다. 본 감사가 제어 5열에 국한되면 DC7 coverage 안전성은 검증 미완료로 둔다.

lab 정답보유일·잠금 제외가 train_X 전수와 다르므로 입력 전수의 prefix/coverage 분포를 기존 공개 검증 대상의 분포 또는 평가 분포라고 부르면 안 된다. 같은 후기 46일을 새 fold와 seed로 재사용한 선택편향은 결측 의미 감사로 해소되지 않는다. 운영값과 EC의 상관 또는 synthetic perturbation은 실제 운영의 인과 효과를 증명하지 않는다. 제어값 0도 센서 정의상 닫힘이라는 물리적 보장은 이번 코드만으로 나오지 않는다.

판정: 코드에 조건부 정보 손실은 확인된다. 실제 결측·격자 위반 빈도는 root의 입력 전용 재생 감사로 확정할 대상이며, 개선 또는 실패 원인·새 모델 채택은 이 범위 밖이다.
