# DP1 누적 count 수식 감사 비평

2026-10-04 · 집 코덱스. audit_count_identity_v1.py/count_identity_v1.json, core.features의 정의와 DC5 r3 및 DP1/DCP1의 FS/BS 전달을 텍스트로 확인했다. 새 fit/predict/score는 하지 않았다. 수치 오차는 root 실행의 저장 JSON 확인이다.

판정: **두 count의 조건부 수식 재구성과 component별 입력 차이 주장을 수용한다.** 무용한 특징·삭제 대상·성능 개선 원인이라는 판정은 이 감사에서 나오지 않는다.

제어값이 유한·비음수이고 시간0..h의 모든 행이 관측됐을 때 n=h+1이다. 기존 tdz=zero_count/n이며, 비음수 관측값은 0 또는 양수다. 따라서 positive_count=n-zero_count=(h+1)(1-tdz)가 된다. vent_open_hours와 co2_hours는 정확히 이 양수 누적 개수다. hr_sin/hr_cos의 atan2로0..23의 정수 hour를 복원하는 것도 소스 정의에 부합한다. 실제9,600행의 두 count19,200개 대조에서 최대오차1.7763568394002505e-15라는 저장 결과는 부동소수점 반올림 범위의 일치를 지지한다. v2에서 해당5제어의 finite/결측0/음수0/완전격자를 확인했으므로 수식의 현 데이터 전제도 충족된다.

코드의 acts/indoor/base/full 상수는 audit 안에 수동으로 재작성되어 있다. 현재 읽은 core의 ACTS/INDOOR/BASE/FULL과 일치하지만 코드가 이 상수 일치를 AST로 assert한 것은 아니다. 현 소스 수식 감사에는 문제가 없으며 향후 core 변경 후 자동 재사용한다면 이 일치도 새로 확인해야 한다. 또한 이 감사가 train_X 전체를 새로 읽은 뒤 DP1 특징을 core 출력에 재생한 것이지 실제 lab/학습된 모델을 복원한 것은 아니다.

실제 DC5 r3는 ET에 full_cols, Tweedie LGB에 base_cols, MLP에 base_cols를 각각 전달한다. DP1은 core.FULL-day+season+NEW를 FS로, core.BASE-day+season+NEW를 BS로 전달한다. DCP1도 FS0/BS0를 만들고 candidate에는 각각 DP1 NEW를 추가한다. 원 core.FULL에는 tdz 및 hr_sin/hr_cos가 있지만 BASE에는 tdz가 없다. 따라서 두 count는 ET 기준선 입력에서 정보적으로 재구성 가능하나, LGB/MLP 기준선의 행별 BASE 입력에는 없는 누적 제어 이력을 추가한다. BASE의 현재 값·season·시각만으로 서로 다른 과거 운영순서를 일반적으로 복원할 수 없다.

정보적 재구성 가능성과 실제 학습기의 표현 가능성은 다르다. ET의 축 방향 분할은 (h+1)(1-tdz)라는 결합을 count 열 하나만큼 쉽게 표현한다고 보장할 수 없다. count가 ET에 결정론적 중복이라고 해도 실측 성능이 같거나 무용하다는 결론은 허용되지 않는다. 다른7개 DP1 특징까지 중복이라고 확대하거나 count 삭제를 제안하지 않는다. component별 손실·예측 기여를 측정하지 않았으므로 .6/.3/.1의 혼합 가중치만으로 개선 기여도도 계산할 수 없다.

결측·음수·불완전 시간격자가 생기면 n=h+1 또는 positive_count=n-zero_count의 전제가 깨진다. 이 수식은 현재 관측된 입력에서 확인한 항등식이며 test/다른농장/일반 센서자료에 대한 보장은 아니다. 이번 결과는 이전 '운영 순서9특징 전부가 ET에 새로운 정보'라는 해석을 좁힐 수 있지만, 전체 후보의 성능 또는 인과적 운영효과를 판단하지 않는다.
