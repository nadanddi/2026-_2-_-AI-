## 새 독립 실행

`independent_bootstrap_critic_v1.py/result`: 합성8640행에 날짜·시간별 서로 다른 양/음 loss 변화가 있는 자료를 만들었다. family24 whole의 bootstrap을 다른 후보의 독립 math v4 경로와 비교했다. 후자는 draw별 fsum·정렬 후 수동 quantile을 쓴다. 세 seed7/101/2024의 p, adjusted CI,95% CI와 strict gate가 모두 일치했다. actual input reads/EC fit/predict/score 모두0이다. 이 수를 writer의 기존13오염·C++8오염 PASS와 합산하거나 해당 검사를 여기서 다시 실행했다고 주장하지 않는다.

## 핵심 검토

- exact alias가 원 Tweedie gradient/Hessian/exp transform/initial bias를 상속하며 λ_l2=1,ρ1.5 고정 root를 실제 inbag leaf 행으로 계산한다. `t`의 penalized loss는 `2A exp(-t/2)+2B exp(t/2)+.5t²`이고 derivative `-A exp(-t/2)+B exp(t/2)+t`의 Hessian은 항상 양수다. weighted sum이며 mean으로 바꾸지 않는다.
- native gbdt.cpp를 직접 읽어 `double(label)-prior_score` residual getter → RenewTreeOutput → learning-rate Shrinkage → UpdateScore → firstbias 저장 순서를 확인했다. 기존 split Train은 Newton gradient/Hessian이다. exact leaf 후 F가 바뀌어 다음 트리의 분할도 바뀔 수 있으므로 트리 구조 자체가 원형과 같다고 주장하면 안 된다. gain은 정확 penalized loss 개선으로 재최적화하지 않는다.
- 같은 DLL Newton66 공개캐시 재현1e-12를 exact66 전에 완료한다. source/library/overlay/build/compiler/원 DLL/API binding과 매 fit source/input/cache freshness를 결속한다. λ_l21/BASE14/.8bag/.03 원 레시피를 유지하며 설치 DLL을 수정하지 않는다.
- whole은 original R3 caller provenance와66 guard, PFN4bag IDs/targets/cache, 공개8640labels, farm/day ±1 purge, manifestfeaturehash/bounds/params, Newton66 controls, 모든66 exact 모델·CSV·meta·SHA 및83160aggregate 동일성을 검증한 후15RMSE를 계산한다. raw delta .24 identity와 원one shrink/one clip 및 independent scalar baseline/candidate를 확인한다.
- 최초 C++ trace의 실제 bag membership/float32label/w/F/수학 A/B/root/leaf membership/.03 firstbias/final raw 재귀를 다른 solver로 검산한다. 실제 native fresh 학습은 verifier가 재실행하지 않으며 저장된 fresh/order/single/prefix 감사의 schema/SHA/1e-12 문턱을 검증한다.
- strict15와 DIAG3seed bootstrap p<.025/24 및 adjusted upper<0를 유지한다. 결과 크기가 작거나 일부 개선이어도 문턱을 바꾸지 않는다.

## 남는 한계와 실행 조건

1. 800은 requested n_estimators budget이다. LightGBM 원형 no-split 자연 종료가 있으므로 새 exact800채택조건은 추가하지 않는다. 모델 requested params800와 실제 positive treecount≤800, feature_namesBASE14, .03/.8/freq1/ρ/λ 및 trace실제treecount 일치 보강을 요청했다. no-split 때 추가 bag trace가 남거나 한 leaf이면 현재 helper가 거부할 수 있다. 실제 결과를 보고 문턱을 느슨하게 하지 않는다.
2. 실제 sklearn wrapper는 훈련 Dataset을 해제한다. 실제첫fit의 private native score cache를 직접 읽었다고 주장할 수 없다. synthetic_result_v4의 Newton/exact cache maxerror0은 합성 직접 증거, actual F 재귀는 간접 증거다. 후속65셀의 내부 F/root trace까지 독립 재계산하는 것은 아니다.
3. checkpoint 재생은 동일 pinned DLL prediction이며 다른 라이브러리 구현의 독립 tree traversal은 아니다. root 수학·scalar ensemble/clip·RMSE/추가 수동 bootstrap 경로가 독립 산술 증거다.
4. runner에는 complete-cell/control 재사용 branch가 존재한다. 실패 raw/json 또는 부분 cell은 보존·중단하지만 외부 hard kill 후 완성 일부 셀을 재사용하는 코드 경로까지 금지하지 않는다. prereg의 부분 재시작 금지는 부모의 실행 운영 규칙으로 유지해야 한다. 임의 재시작/부분 채점은 허용되지 않는다.
5. whole은 버전/runtime 숫자와 core/env/source SHA, pinned DLL을 확인한다. 모든 Python package 파일의 독립 전체 wheel SHA까지 확인하는 것은 아니다. 동일 DLL Newton66 재현을 통과하기 전 원 레시피 동등성 또는 후보 성능을 주장하지 않는다.
6. first trace NDJSON은 Python json.loads로 읽으며 추가필드/duplicatekey strict schema까지 검사하지 않는다. traceSHA가 최초 감사에 결속되고 필요한 수치/행·모델 동일성을 검사하므로 현재 trusted native output 범위에서 P1로 판단하지 않았다.

새 submit/test/EL1/raw EC 접근과 actual fit/score를 이 독립 검토에서 수행하지 않았다. 채택 판정은 completed66+whole 이후에만 가능하다.
