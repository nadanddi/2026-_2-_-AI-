## 먼저 판단할 사항

**공개 회귀 후보는 TabDPT v1.3과 TabICLv2 두 개로 한정한다.** TabDPT는 실제 데이터의 열 복원 사전학습과 입력별 문맥 선택이라는 차이가 있다. TabICLv2는 이미 과거 선별에서 탈락한 모델이며, 최신 논문을 읽었다고 새 모델이 생긴 것은 아니다. 현재 계절 입력 조건에서 재시험할 여지는 있으나 우선순위는 낮다.

EC 개선 효과는 아직 측정하지 않았다. 이 문서의 모델 차이·라이선스 표시는 공개 원문 확인 결과이며, 개선 가능성·검증 설계는 조건부 제안이다.

### TabPFN V2와 실제로 다른 부분

원 논문 §3에서 읽은 차이는 **실제 표의 한 열을 목표로 뽑고 나머지 열로 복원하는 자기지도 사전학습**이다. 열 삭제·순열을 사용하고, 가까운 행을 문맥/질의로 나눠 학습한다. 새 자료에서는 학습 행의 가까운 이웃을 문맥으로 사용한다. 합성 표 사전학습의 TabPFN V2와 다른 정보 압축·귀납 방식이다. 논문은 iid 직사각형 표를 가정하며 시간·계층·분포 이동은 미해결 범위로 남긴다. [TabDPT 본문 §3·§5](https://arxiv.org/html/2410.18164v3)

**현재 구현과 원 논문의 차이를 구분해야 한다.** 현재 regressor 기본 문맥 선택은 subsample이며, retrieval을 명시해야 질의별 kNN을 사용한다. fit 단계의 평균 결측 대체·scaler·필요시 PCA는 train에 적합하고 predict에서는 transform한다. retrieval 인덱스도 X_train에서 만들며 질의 입력으로 이웃을 찾는다. y_train은 전체 학습 목표로 표준화한 뒤 문맥을 선택한다. 전처리 근거는 [estimator.py](https://raw.githubusercontent.com/layer6ai-labs/TabDPT-inference/main/src/tabdpt/estimator.py), 회귀 경로는 [regressor.py](https://raw.githubusercontent.com/layer6ai-labs/TabDPT-inference/main/src/tabdpt/regressor.py).

최신 model.py는 문맥 목표를 층마다 value에 결합하고, attention의 key/value는 문맥 부분에서만 만든다. feature 정규화/자름도 평가 시 eval_pos까지의 문맥을 기준으로 호출한다. 이 구조를 읽었으므로 질의가 같은 batch에 들어온다는 사실만으로 곧바로 행간 누수라고 부르지 않는다. 실제 적용 전 단일 행/배치·미래 입력 변화 대조는 따로 필요하다. [model.py](https://raw.githubusercontent.com/layer6ai-labs/TabDPT-inference/main/src/tabdpt/model.py)

**EC에 연결되는 가설(우리 해석)**: 높은 상태와 가까운 입력 문맥을 쓰면 일반 행의 혼합을 줄일 수 있다. 그러나 입력상 가까운 고EC 행의 크기 자체가 낮거나 숨은 관리 상태가 다르면 kNN도 같은 과소를 낸다. 하루 24행이 많이 이웃으로 들어오면 행 수 대비 독립한 날 수가 작아진다. 문맥 확대가 정보 확대를 뜻하지 않는다.

### 평균 출력의 두 경로를 먼저 고정해야 함

현재 regressor.py의 mean 경로는 각 ensemble의 softmax 확률로 bin 중심의 기대값을 계산한 뒤 산술평균한다. full 경로는 ensemble logits를 먼저 평균한다. 따라서 full 출력에 distribution_mean을 적용한 결과와 predict(mean)는 일반적으로 다르다. [regressor.py](https://raw.githubusercontent.com/layer6ai-labs/TabDPT-inference/main/src/tabdpt/regressor.py), [분포 평균 코드](https://raw.githubusercontent.com/layer6ai-labs/TabDPT-inference/v1.3.0/src/tabdpt/bar_distribution.py)

합성 반례: bin 중심 [0,1], 두 ensemble logits [0,0]와 [0,ln9].

- mean 경로: (0.5+0.9)/2 = **0.70**.
- full 경로: softmax([0,ln3])의 높은 bin 확률 = **0.75**.
- 지수 계산과 분수 계산 두 방법으로 일치 확인. 실제 EC 차이는 아직 측정하지 않았고 어느 경로가 더 좋다는 주장도 하지 않는다.

v1.3 분포는 유한 bin 구간 안의 piecewise-uniform histogram이다. 그 분포의 평균은 범위 밖으로 갈 수 없다. 숨은 EC 크기를 자유롭게 외삽하는 모델로 소개할 수 없다. [bar_distribution.py](https://raw.githubusercontent.com/layer6ai-labs/TabDPT-inference/v1.3.0/src/tabdpt/bar_distribution.py)

정확한 반복 재현이 불가능하다는 문구가 현재 공식 README의 논문 재현 절에 있다. 이 문구가 현재 CPU·고정 seed 전체에 해당한다고 단정할 수는 없지만, 재현성 통과를 사전에 가정해서도 안 된다. [공식 README](https://github.com/layer6ai-labs/TabDPT-inference)

본문에서 확인한 계산 차이는 열 embedding → 행 압축 → 행 사이 ICL 구조, 목표를 이른 embedding에 결합하는 방식, 문맥 길이와 query에 맞춰 softmax를 조절하는 QASSMax다. 회귀는 **999 분위수(0.001…0.999)에 pinball loss**를 사용하며 점 예측은 그 산술평균이다. TabPFN V2의 목표 bin/cross-entropy와 다르다. 사전학습은 합성 표를 사용한다. Appendix I는 분위수 crossing 보정과 지수 꼬리 분포 구성을 설명한다. 분포 회귀의 본문 검증은 toy 수준이라는 한계, 평균 결측 대체/결측 indicator 미탐구도 명시한다. [TabICLv2 본문 §3–5·§8·Appendix I](https://arxiv.org/html/2602.11139v2)

우리 해석: 전체 조건부 분포를 통해 평균을 복원하는 계산은 과소 압축을 달리할 수 있으나, 실제 EC 정보를 새로 관측하지 않는다. 특히 **999개 값을 정렬하는 것만으로 점 예측 평균은 바뀌지 않는다**. 합성 [3,1,2]의 원/정렬 평균은 모두 2이고, 같은 가중치 PAVA [2,2,2]도 평균 2다. 분위수 crossing을 고치는 처리가 그대로 EC 평균 과소를 해결한다는 주장은 틀리다. 꼬리까지 적분한 분포 평균은 별도 계산이며 기본 산술평균과 같은 대상으로 혼용하지 않는다.

### 과거 결과와 중복

C6.48은 TabICL **2.2.0/regressor-v2 CPU 선별 탈락**을 기록한다. 읽은 집/클로드/research/web_tabicl_screen_v1.py는 old day 입력, 전체 train-fold 문맥, DIAG 두 폴드의 선별이며 TabICLRegressor(random_state=0, device=cpu)를 사용했다. checkpoint version/hash는 코드에 고정되지 않았고 해당 로그는 이번 환경에서 찾지 못했다.

## 희귀 EC 크기 과소에 더 직접 맞는 보정·앙상블 해석

### CDF calibration은 점 예측 보정과 목표가 다르다

Kuleshov·Fenner·Ermon(ICML 2018)은 관측 목표가 원 CDF에서 차지하는 누적 확률을 사용해 R:[0,1]→[0,1]을 등위 회귀로 적합하고 R∘F를 사용한다. 충분한 iid 자료에서 구간의 빈도 calibration이 목적이다. 본문은 calibration만으로 정확한 조건부 예측이 되지는 않는다고 명시하고, 별도 calibration set 또는 교차 적합을 제안한다. 주요 실험 표는 MAPE와 calibration error이며 EC의 전체 RMSE 개선 시험이 아니다. [본문 §3–4, Algorithm 1](https://proceedings.mlr.press/v80/kuleshov18a/kuleshov18a.pdf)

우리 해석: 보정된 구간 포함률이 좋아져도 고EC 날의 평균 크기 부족이 줄었다는 증거는 아니다. ET 트리 투표의 산포도 자동으로 y|x 분포가 되지 않는다. C6.251의 과소 날 확률 진단이 있고, C6.177의 점 예측 등위 보정도 이미 실패했다. 같은 표본에 여러 calibration을 시험하여 높은 예측을 올리는 방향만 고르면 원래 목표 전체 RMSE에서 일반 날 손실을 숨기기 쉽다.

검증 가능한 형태는 outer-train 내부의 **OOF 분포/예측으로만** 보정기를 적합하고, outer-val의 점 예측 RMSE와 확률 지표를 별도로 평가하는 것이다. 24행이 독립 표본이라는 가정으로 신뢰구간을 좁히지 않는다. 이 문서에서는 새로운 보정기를 적합하지 않았다.

### 입력별 가중치는 수학적으로 가능하지만 기존 시도와 겹친다

FWLS(Sill 등, 2009)는 모델별 가중치를 메타특징의 선형함수로 두어
`w_i(x)=Σ_j v_ij f_j(x)`, `p(x)=Σ_i,j v_ij f_j(x)g_i(x)`
를 학습한다. 회귀 입력은 모델 예측×메타특징의 곱이고 Ridge로 과적합을 줄인다. 저자는 반드시 out-of-sample 모델 예측을 쌓을 것과 학습/평가 분포 차이를 강조한다. [본문 §2·§3.2](https://arxiv.org/pdf/0911.0460)

이 식은 “문제마다 전문가 가중치를 다르게”라는 요구에 맞는 기본형이다. 다만 비음수/합1 조건은 원 논문의 자동 보장이 아니므로 우리 구성에서는 따로 제한해야 한다. C6.94/6.96의 조건별 혼합, C6.265의 현재 내부 전문가 혼합과 개념이 겹친다. 별도의 새 발견으로 세거나 현재 실험을 수정하지 않는다.

아래는 논문 결과를 베낀 레시피가 아니라 **현재 실험 해석에 쓰는 우리 도출식**이다.

- 실제 기준 예측 p0와 전문가 방향 d를 고정하면 후보는 p0+λd.
- 잔차 r=y−p0일 때 전체 SSE 변화는 `−2λΣ(r d)+λ²Σd²`.
- 일반 날/고EC 날로 나눠도 항들의 합은 동일하다. 높은 실제 EC만 잘 고쳤다고 전체 이득이 되지 않는다.
- λ를 맞출 자료는 outer-train 안쪽 OOF다. outer-val의 잔차로 λ나 gate를 고르면 안 된다.
- 동일 입력에서 전문가가 갈라지는 d의 방향이 잔차를 설명하는지 먼저 본다. 상관이 높다는 말만으로 작은 혼합 성공을 보장하지 않는다.
- gate는 현재·이전 허용 입력/모델 예측만 사용한다. 실제 당일 y가 높은지를 아는 오라클 gate는 추론에 사용할 수 없다.

합성 검산 y=[.2,2,.3], p0=[.3,1.2,.4], 전문가=[.2,1.8,.2], λ=.2에서 SSE는 .66→.4724, 직접 차이와 위 전개식 차이는 모두 −.1876이다. 이 수치는 실제 EC 성능이 아니다.

## 대회 제공 자료만으로 가능한 조건부 검증 설계

대회 입력 49온실이 EC 정답 49온실을 뜻하지 않는다. 현재 프레이밍의 공개 정답은 F13/F47, 360일×24행=8640행이다. 이 수량은 부모/기존 프레이밍을 사용한 범위이며 원시 목표를 읽어 다시 세지 않았다. 독립된 날·동·날씨 군집 수는 행 수보다 작다.

새 가중치 사용 자체의 대회 허용 해석과 버전별 조건은 실제 실행 담당자가 먼저 확인해야 한다. 아래는 **제공 자료에서 새 누수를 만들지 않는 실험 방식**이며, 새 외부 모델에 대한 포괄적 규정/상업 사용 승인 선언이 아니다.

1. **단일 변경부터:** R3/계절 생성/후처리를 고정하고 TabPFN 몫 .2를 대체하는 후보 하나를 사전 명세한다. TabDPT라면 context 방식·수·ensemble 수·seed·mean/full 선택까지 점수를 보기 전에 고정한다. retrieval/균등 추출 비교를 추가하면 별도 후보/다중 비교 수로 센다.
2. **기존 검증기 유지:** 같은 A/B/DIAG10 및 기존 스트레스 검증과 같은 seed를 쓴다. 공개360일 안에서만 점수를 계산하며 잠금, EL1, test는 건드리지 않는다. 기존 반복 탐색으로 이미 본 자료라는 한계도 남긴다.
3. **같은 전처리 경계:** 현재 계절 v2의 행 특징을 그대로 사용하되 학습 행은 MASK 적용, 평가 행은 같은 온실의 현재·이전 입력만. imputer/scaler/PCA·문맥 추출·보정 학습은 outer-train 범위 안에서 한다. 다른 온실의 질의 값이나 이후 시각 값을 특징으로 결합하지 않는다.
4. **단일 질의 대조:** 허용되지 않은 미래/다른 질의 입력을 바꿔도 해당 행 예측이 유지되는지 확인한다. 단일 행·batch·순서·반복 호출도 비교한다. 문맥 키/값을 train에서만 만드는 공식 코드를 읽은 사실이 실제 파이프라인 검사 통과를 대신하지 않는다.
5. **분포 출력이면 계산 경로 고정:** TabDPT full logits 평균을 mean 산술평균과 섞지 않는다. TabICL 분위수 산술평균·분포 적분 평균·중앙값을 서로 다른 후보로 기록한다. RMSE 후보는 기본적으로 평균이다.
6. **일반 날 손익 같이 보기:** 전체 RMSE를 채택 목표로 고정하고, 고EC 일별 과소/일반 날 SSE/온실별/전후반을 진단한다. 고EC 기준은 진단용 정답 구분이며 gate 피처가 아니다. 새 후보의 모든 seed×검증기 방향과 DIAG10 일별 p_worse 기준/본페로니를 부모의 사전 규칙으로 판정한다.
7. **복제/동조 감사:** 같은 날짜 날씨가 같은 두 온실, 같은 날 24행, 복제 입력의 train/val 경계를 보조 감사한다. 공식 기존 검증 점수와 군집 보조 감사는 구분한다. 49온실 입력으로 만든 대리 자기지도 목표는 EC 외부 정답으로 취급하지 않는다.

주안점은 “고EC를 더 올리는 함수 찾기”가 아니라 **같은 입력에서 EC 크기를 달리하는 부분을 학습 문맥·분포 평균·전문가 방향이 실제로 설명하는지**다. 이 조건을 충족하지 못하면 새로운 사전학습 모델도 현재 과소 압축을 반복할 수 있다.

## 주장 검산과 반론

- **TabDPT는 회귀 지원:** 공식 release, regressor API, 공식 모델 파일 목록을 교차 확인. 신뢰도 높음. 로컬 실행 성공·EC 개선은 미확인.
- **TabICL은 새 미시험 모델이 아님:** C6.48과 과거 실제 스크립트 확인. 신뢰도 높음. 옛 로그가 없고 checkpoint hash도 없어 최신 파일과 완전 동일하다는 주장까지 하지 않음.
- **라이선스 표시:** 각 코드 LICENSE와 공식 모델카드가 일치함. 신뢰도 높음(읽은 문서 범위). 개별 weight 최신 revision의 고지까지 검사/승인한 것은 아님.
- **TabDPT 평균 경로 차이:** regressor.py와 bar_distribution.py 교차 확인, .70/.75 합성 반례를 서로 다른 계산으로 재검산. 신뢰도 높음. 실제 모델에서 차이가 작을 가능성과 EC 우열 미확인은 남음.
- **확률 calibration이 RMSE 해결을 보장하지 않음:** 원 논문의 목적/가정/평가를 확인. 신뢰도 높음. 특정 EC 보정이 유효할 가능성까지 부정하는 것은 아님.
- **입력별 전문가 가중치 가능:** FWLS 원식과 OOF 요구 확인. 신뢰도 높음(계산 가능성). 현재 EC 개선 신뢰도는 낮음/미측정. C6.265와 중복이다.
- **세 핵심 산술 검산:** ensemble 평균(.70/.75), 분위수 순서 보정 평균(2 유지), SSE 전개식(−.1876)을 재실행하고 각각 독립 계산과 맞춤. [검산_v2.json](검산_v2.json)에 저장했다.

우선순위: 실제 계절 v2 내부 전문가 혼합의 현재 결과를 먼저 마무리한다. 이후 새 가중치 실행이 허용되고 환경이 맞으면 TabDPT의 고정 mean 경로 단일 후보가 구조적 다양성을 시험하는 다음 선택이다. TabICL은 과거 model/hash와 현재 계절 입력 조건 차이를 먼저 확인한 뒤 재시험 여부를 정한다. 이 문서만으로 새 모델을 채택하지 않는다.
