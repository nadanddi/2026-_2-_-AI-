검산 코드: [check_tabdpt_v4_aggregate_v3.py](C:/work/farmai/집/코덱스/analysis/ec_harsh_review_20261004_v1/check_tabdpt_v4_aggregate_v3.py). 결과: [tabdpt_v4_aggregate_check_v1.json](C:/work/farmai/집/코덱스/analysis/ec_harsh_review_20261004_v1/tabdpt_v4_aggregate_check_v1.json).

1. **모델·식·시드·문턱 변경 없음.** v3와 v4를 전체 AST로 비교했다. 두 `oof.csv` 존재 assert, 최종 `open('x', encoding='utf-8', newline='')` 저장, `preparation_v3.json`→`preparation_v4.json` 상수 2곳만 정규화하면 전체 AST가 정확히 같다. 그 밖의 함수·특징·모델 생성·예측·후처리·seed·수치 문턱은 동일하다. v4 SHA256은 `136f72ce14cf7afc078185f0e1c421052910153d6f156ebe8eed604cc3a6d2f2`이며 preparation_v4의 상위 및 22개 fold manifest의 run SHA와 모두 일치한다. 준비 JSON은 PASS/22fold/fit_count=0이다. 준비 자체를 다시 실행하거나 데이터 해시를 재산출한 것은 아니다.

2. **기존 집계와 저장 충돌을 보존함: 실제 코드 추출 합성 6/6 PASS.** v4 main의 첫 관문까지를 그대로 추출하고 loader/preflight/parser만 합성 stub으로 대체했다. 기존 집계가 없으면 통과하고, 있으면 runtime probe import 및 모델 단계 전에 지정한 오류로 중단했다. 최종 assert와 with도 실제 AST를 추출해 실행했다. absent일 때 새 CSV 생성, 기존 파일에 대한 최종 assert 중단, assert 없이 실행한 exclusive 저장의 FileExistsError, assert 통과 직후 다른 파일이 생긴 경우의 FileExistsError를 각각 확인했다. 기존 파일을 보존한 4개 검산 사례의 SHA가 모두 그대로였다. 이들은 3개 합성 파일을 사용했고, final_present 파일은 assert와 exclusive 두 검산에 재사용했다. 실제 실험 OUT 파일은 읽거나 수정하지 않았다.

3. **CI 표기는 v6에서 정정됐고 남은 감사 범위는 그대로다.** 사전v5의 95% CI 표현은 사전v6에 작성 오류로 기록되어 있으며 family20 조정 CI `[alpha, 1-alpha]=[0.00125, 0.99875]` 상한<0이 명시됐다. p_worse<0.00125와 15셀 모두 개선 조건을 유지한다. 이 코드 delta에는 점수 산출·선택 변경이 없다. 첫 감사 day 값을 별도 재계산하지 않는 점, 37개 core 특징의 선택한 prefix 감사가 모든 fold의 season 인과성 증명이 아닌 점은 v16의 한계 그대로 남는다.

반론·한계: exclusive 생성은 기존 파일 덮어쓰기를 막지만 전체 CSV의 원자적 완성을 보장하지 않는다. 저장 중 중단되면 부분 집계도 남아 다음 학습을 막는다. 따라서 파일 존재만으로 완료를 주장해서는 안 되며, 이런 경우 별도 검산으로 처리한다는 v6 방침이 필요하다. 새 존재 assert를 포함한 기존 guard들은 `python -O`에서 제거되므로 기존 실행법처럼 최적화 옵션 없이 실행해야 한다. 이번 합성 검산은 `__debug__=True`였다. 실제 최초 fit/predict 감사가 아직 필요하며 라이브러리의 batch·single·fresh-fit 동일성은 이번 검산으로 판단하지 않았다.

감사 이력: check_v1은 문서의 '사전v5'를 '문서v5'로 잘못 기대한 문자열 assert에서, check_v2는 세미콜론 문장이 여러 AST 문장으로 분리되는 점을 반영하지 않은 고정 위치 assert에서 각각 중단했다. 두 중단 모두 후보 결함이 아니며 합성 파일 생성·적합·예측 전에 발생했다. 기존 파일을 보존한 새 check_v3에서 실제 문구와 상대적 AST 순서를 확인하고 위 6개 사례를 완료했다.
