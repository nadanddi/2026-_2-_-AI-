**run_v2.py의 핵심 식과 누수 경계에서 새 치명적 오류를 발견하지 못했다. v1의 입력 signature/첫cell 부분복구 문제도 보완됐다.** 검토 소스 SHA256는 `0b3bec17176fa4674105745c817a3eb40c07767b9cee43e299715354c0b97f16`이다. `run_v2.py`, 사전문서v1/v2, 호출하는 고정 guard/LOG/support 코드를 읽었고 원 스크립트를 import/실행하지 않았다. 1. **사전식과 현재 구현은 일치한다.** inner oldET와 LOG는 같은 a/FS38/season-last/seed로 fit한다. season 및21기록일 b는 a만으로 재적합한다. inner p0는 현재 matched R3/PFN의 raw 혼합 뒤 shrink/clip이고 p1는 그 p0에 .48 component delta를 더한 뒤 먼저 clip한다. 방향은 p1−p0다. 비중은 두 farm·모든 innerquery행의 `e=p0−y_b`를 사용하고 λ.01/[0,1]을 적용한다. outer는 저장된 **ratio 산술/b_query 복원** LOG endpoint를 사용하여 이미 bounded된 두 endpoint를 섞는다. 원 y leaf family18과 혼합하는 코드 경로는 없다. 마지막 convex clip의 수치 차도 검증한다. 내부해·0·1·d전부0 네 합성 경계의 actual weight helper는 Decimal 닫힌식/KKT와 일치했다. 소스상 outer q의 labels는 row/target 감사와 출력에만 쓰이며 weight 식으로 들어가지 않는다. 이 확인은 현재 코드의 학습 범위 검토이지 실제 모델 성능 검증은 아니다.

2. **두 재현 관문은 실제 helper 실행으로 확인했다.** features_sha는 입력값/season/행순서/열순서 변경을 구별하고 같은 NaN의 payload 차이는 정규화한다. 현재 train_X를 기존66 R3 provenance 입력hash와 대조하며 source/core/season/env/support/guard/LOG와 공개 기준선 cache도 signature에 담는다. 준비v2 기록의 core hash는 현재 파일 및 과거 R3 metadata의 core hash와 같았다. 첫cell의 CSV/NPZ/meta/firstaudit 존재 조합16개 중 전무/완전만 허용하고 부분14개는 중단했다. 완전 파일의 첫 signature가 다를 때도 중단했다. 호출 순서도 guard→fit_direction이며 firstaudit는 cell3파일 및 scalar 검사 후 저장한다. 따라서 firstaudit만 남은 상태에서 재적합을 호출하던 v1 경계가 해소됐다. 근거는 `check_nested_log_v2_code_v1.py`/`nested_log_v2_code_check_v1.json`이다. 실제 전체 학습 산출물의 resume 검증은 아직 실행하지 않았다.

3. **남은 경계는 최종 실행·환경·감사 범위다.** 준비v2는 status=PASS,22CPU/88PFN,outerLOG66cache 감사로 기록되어 있고 검토 source hash도 일치한다. 이 기록은 적합0 관문 통과이고 결과의 합격 판정은 아니다. 실제 첫cell replay/leaf/배치/미래변조, 전66cell 저장 raw→endpoint→direction→weight→candidate의 독립 재계산과 공개 판정이 여전히 필요하다. `verify_full_v2.py`의 logblend 경로는 저장 raw/shrink/b/ratio·현재 matched baseline·full endpoint·e/d·num/den/w 및 outer scalar를 다시 검사하도록 구성되어 있다. helper의 self-consistency만으로 leaf 집계나 저장 방향이 맞았다는 검증을 대신하지 않는다.

   소스 hash와 X hash는 런타임 라이브러리 버전 고정을 대신하지 않는다. env를 먼저 import한 현재 런타임은 Python3.12.14/NumPy2.5.3/pandas3.0.1/sklearn1.9.1로 원 R3 metadata와 일치했다. 지금 버전 불일치 증거는 없지만 다음 컴퓨터·다음 재개에도 이 조건을 유지하거나 버전 manifest를 함께 보존한다. 마지막 `fit_audit_v1.json`은 S.savej로 새 파일만 쓰므로, 완전 완료 후 같은 스크립트를 다시 실행하면 기존cell 검증을 통과한 뒤 최종 audit 기존파일에서 중단할 수 있다. 완료 재검증에는 별도 verifier를 쓰며 이를 새로운 모델 실패로 해석하지 않는다. 중간 partial 파일은 삭제/덮어쓰지 않는 현재 정책을 유지한다.
