1. **변경 범위를 전체 AST로 확인했다.** 새 `guard_original_r3`, 실제 66셀의 guard 호출·기록·개수 assert, 결과에 r3_cache_audit 추가, 새 합성 구간만 정규화하면 전체 AST가 v1과 정확히 같았다. sha/readj/array_sha/ids_sha/runtime bootstrap/compare/RMSE/prefix_scalar/boot_diag/validate_first/check_runtime/calculate_scores 12개 함수는 자체 AST가 동일하다. 상수·seed·15셀 채택식·고EC31일 및 ordinary329일 정의·조정 CI·CLI도 동일하다. v1에서 수행한 수학 검산을 v2에서도 전부 재실행했다고 확대하지 않고, 이번 delta와 추가 guard만 독립 검산했다.

2. **요청 5종을 포함한 오염 23개가 모두 거부됐다.** 실제 v2 helper를 AST로 추출해 정상 합성 1개를 통과시킨 후 학습 순서, 저장 목표, 부품 합산식, 파일 digest, 학습 bounds 5종을 독립 거부했다. seed/fold/kind/key, 학습·평가 행수 및 온실×일수, query 순서, NaN/Inf, 필수 부품 누락, 배열 shape, 1e−15 부품 합산 변경, 공개 train/query 정답, 학습·평가 중첩, 중복 학습 ID도 거부했다. 정상 합성은 학습 3행/2일로 만들어 행수와 일수의 혼동을 검사했다. 기존 캐시 생성 코드의 실제 canonical_hash를 AST로 추출해 한글을 포함한 합성 provenance로 key를 생성했으며 guard와 일치했다. 기존 메타데이터 1개의 필수 key와 필드 타입도 guard가 기대하는 구조와 일치했다. 대상의 원래 `--synthetic`은 PASS/합성 비교 원소 40,036개와 5종 거부로 별도 실행됐다. 우리 helper 검산은 25사례(정상 1, 오염 거부 23, 아래 범위 한계 확인 1), 비교 원소 87개다.

3. **v18 생략은 보강됐지만 전체 원 학습 재증명은 아니다.** 실제 verifier 경로는 원 NPZ의 SHA를 계산해 metadata의 prediction_sha256과 대조한 뒤 load한다. 학습·평가 ID 순서 및 중복·중첩, 저장 query 목표와 fresh 공개 목표, 정확한 `.6raw_et+.3raw_lgb+.1raw_mlp`, 공개 학습 목표의 min/max, 원 학습 행수·일수 및 기존 baseline bounds를 확인하고 원 metadata SHA도 66개 기록한다. 이것은 파일·입력 ID·목표·query 부품 정합성을 보강한다. 반면 metadata key는 저장된 provenance를 다시 해시한 자기일관성 검사다. 원 `train_hash`와 `validation_hash`를 현재 FULL38 특징으로 새 계산해 비교하지 않으므로 원 모델의 모든 학습 특징·season 변환까지 이번에 새로 확인했다고 말할 수 없다. 현재 runner manifest의 특징 재구성과 기존 input/core/runtime 대조는 유지되지만 이 둘은 원 R3의 저장 frame_hash 직접 재계산과 다른 증거다.
