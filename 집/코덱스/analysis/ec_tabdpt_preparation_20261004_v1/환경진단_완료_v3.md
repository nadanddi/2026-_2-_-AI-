## InvalidVersion(None)의 원인

[sandbox_metadata_resolution_v1.json](C:/work/farmai/집/코덱스/analysis/ec_tabdpt_preparation_20261004_v1/sandbox_metadata_resolution_v1.json)에서 샌드박스의 stdlib metadata 해석은 고정 overlay의 5개 dist-info를 정확히 찾았지만 **version=null**을 반환했다. 동일 파일의 직접 METADATA 읽기는 모두 **PermissionError**였다. 첫 순서의 TabDPT에도 같은 현상이 재현됐다.

그 후 같은 인터프리터·같은 파일을 `require_escalated` 승인된 읽기 실행으로 검사했다. [metadata_diagnostic_v2.json](C:/work/farmai/집/코덱스/analysis/ec_tabdpt_preparation_20261004_v1/metadata_diagnostic_v2.json)에 정상 Name/Version·METADATA 크기·경로·중복 기록을 저장했다. 5개 고정 버전이 모두 정상이다. 따라서 이 실패는 **패키지가 다른 버전이거나 metadata stub인 것으로 판정되지 않았고, sandbox의 파일 읽기 거부로 None이 전달된 경우**로 확인됐다.

core/extra에는 numpy·sklearn·scipy 등의 기존 정상 중복 배포와 extra의 Hub 2.0.0이 있다. 실제 선택은 core 및 새 overlay의 우선 경로로 확인했다. 빈 metadata를 건너뛰어 다른 버전을 고르거나 핀 문턱을 바꾸지 않았다. probe v3는 METADATA를 직접 읽어 권한 오류·Name/Version 누락을 명시적으로 실패시킨다.

## 부모 runner 연결

`runtime_probe_v3.py`의 **`import_probe(runtime_root)`를 positional 인자로 호출**한다. 반환 dict에는 다음이 있다.

- `versions`, `module_paths`: 정상 배포 metadata 버전과 실제 import 경로·모듈 버전
- `source_commit`, `source_sha256`: 전체 commit과 7개 실제 source 파일 hash
- `python`, `executable`, `dll_dirs_with_live_handles`
- `status=PASS_IMPORT_ONLY_FIT_PREDICT_UNTESTED`

numpy/sklearn/scipy가 core bootstrap에서 이미 import된 상태는 허용하며 실제 core 경로를 검사한다. **torch/TabDPT/FAISS/OmegaConf/Hub가 이미 import됐으면 중단**한다. 이전 PFN worker와 분리한다. DLL 핸들은 probe 모듈의 `DLL_HANDLES`에 보관하므로 부모가 실행 동안 probe 모듈 참조를 유지한다.
