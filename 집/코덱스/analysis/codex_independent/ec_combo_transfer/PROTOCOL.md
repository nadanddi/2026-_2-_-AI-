# EC 조합 사후 전이 진단 프로토콜

작성 시점: 원본 `ec_combo_v1_gpu.py`의 사전 ADOPT 및 EXT10/12
결과를 모두 본 뒤. **독립 확인이 아니다.** 새 모델을 선택하거나
비율·문턱을 조정하는 게이트로 사용하지 않는다.

목적: 원본 GPU 실험의 전체 RMSE만으로는 보이지 않는 일별 이득
집중도와 평가 날짜 범위·밀폐일에서의 방향을 확인한다. 실제
평가 정답은 읽지 않는다.

1. 원본 DIAG10과 같은 5일 묶음 폴드 8·9만 재실행한다. 같은
   온실의 확인일과 양옆 하루를 학습에서 제외한다. 다른 폴드는
   학습에 허용한다. 원본 코드의 두 3회차 시드 11·12와
   TabPFN 문맥 묶음 301~308·311~318을 그대로 사용한다.
2. 각 시드/폴드에서 v2는 원시 모델 0.8 + 그 묶음 첫 4문맥
   0.2, combo는 원시 모델 0.6 + 같은 묶음의 8문맥(당일 누적
   실내 평균 3개 추가) 0.4다. 수축 0.5와 클리핑은 원본과 같다.
3. 저장할 것은 공개 확인 행별 `row_id`, 정답 EC, 두 예측 및
   입력만으로 정의한 집단 표시다. **평가 입력에 대한 예측 파일,
   제출 CSV는 만들지 않는다.**
4. 고정된 진단: 폴드별·온실별 RMSE 변화, 평가 입력의 날짜
   범위에 속하는 공개 확인일, 밀폐일, 개선된 온실-일 수,
   긍정적 제곱오차 감소 중 상위 5일 몫, 그 5일 제외 후 변화.
   밀폐일 판별은 하루 전체 입력을 쓰므로 사후 진단 전용이다.
5. 코드·입력·원본 실험 로그 해시를 기록한다. 다른 무거운
   학습 프로세스가 실행 중이면 시작하지 않는다. 각 문맥
   예측을 작업 사본에 저장해 중단 후 같은 설정으로 재개한다. 결과가
   나쁘더라도 조합의 비율·특징을 사후 수정하지 않는다.

이 진단은 원본 ADOPT 판정을 소급해 바꾸지 않는다. 한랭
EXT12 두 시드의 악화도 별도로 유지한다. 비공개 RMSE를
추정하거나 플랫폼 제출을 정당화하지 않는다.
