# EC v3 실행 전 고정 계획 — 배지 온도 보조 학습

## 가설과 범위

두 공개 정답(sub_ec, sub_temp)을 함께 학습한 ExtraTrees가 EC만 학습한
ExtraTrees보다 온실의 일별 상태를 더 잘 나눌 수 있는지 검증한다.
온도 정답은 **학습 분할의 목적변수**에만 넣는다. 검증·평가 행의 온도 정답은
특징·보정값·예측 중 어느 곳에도 넣지 않는다. 모델이 낸 온도 예측도 EC의
특징으로 사용하지 않는다. 원시 입력, 동일 분할·후처리, EC 모델 나머지
구성원(LightGBM, MLP)은 v1/v2와 같다. 온도 예측 자체를 평가하지 않는다.

두 선택지: 보조 온도 목표의 훈련 표준편차를 EC 훈련 표준편차의 0.5배 또는
1.0배가 되게 스케일한다. EC 목표 자체는 원래 단위로 유지한다. 스케일은
각 훈련 분할로만 계산한다. 출력에서 EC 예측만 사용한다. 두 선택지 외의
스케일 탐색은 이번 실험에서 하지 않는다.

## 선별 및 확인

v1에서 지정한 확인 폴드 8·9와 인접일은 학습/탐색에서 제외하고 **채점하지
않는다**. 초기 탐색: 폴드 0·2 × 시드 7·101. 네 조합 모두 대조군보다
RMSE가 낮고, 같은 조합의 상대 감소율 평균이 1% 이상이면 폴드 4·6 ×
두 시드를 추가 평가한다. 확장 후보가 없으면 종료한다. 확장 8개 조합 모두
개선하고 평균 1% 이상이어야 후속 검증 후보로 남긴다. 대조군은 같은
학습행·검증행·시드에서 새로 생성하거나 입력/코드 해시가 일치하는 캐시를
사용한다. 후보는 기존 3회차 EC 구성 기준이며 최신 TabPFN 혼합 후보와의
비교가 아니다.

후보 잠금 전 확인 자료를 열지 않는다. 캠페인 전체 후보 수는 v3까지 7개로
누적한다. 신규 독립 평가가 없고 기존 연구가 전체 공개 라벨을 활용했다는
한계를 유지한다. 탐색을 통과해도 최종 채택에는 A/B·DIAG10·최신 혼합 후보,
온실·일 블록 신뢰구간 및 전체 후보 수에 대한 다중 비교 보정,
최종 재현·끝단 인과성 검사가 필요하다.

## 규정·재현 검사

- `train_y`의 공개 온도 정답만 학습 분할에서 읽는다. 검증 분할의 EC·온도
  정답은 채점에만 읽는다. 예측 함수에는 검증 온도 정답을 전달하지 않는다.
- 학습·검증 사이에 온실·일차 단위 1일 버퍼를 둔다.
- 특징은 v1에서 검증된 0시 지문 및 현재/과거 당일 구동기 요약이다.
- 특징 이름에 `sub_temp`·`sub_ec`가 없고, 검증 온도 정답을 삭제·변조해도
  예측이 비트 단위로 변하지 않는지 검사한다.
- 입력/계획/코드/분할 해시, 시드, 성능, 실패한 후보를 새 폴더에 보존한다.
- 원본 자료와 기존 제출물을 덮어쓰지 않는다. 대회 제출은 하지 않는다.
