# TabPFN EC 4문맥 CPU 재현 — 2개 탐색 구간

2026-09-28. 기존 연구에서 고정했던 TabPFN v2, 2,000행 문맥 4개 평균,
혼합 비율 20%를 오프라인 CPU에서 재생성했다. 탐색 폴드 0·2에서 기준
모델 시드 7·101과 비교했다.

| 탐색 구간 | 기준 시드 | 기준 RMSE | 4문맥 혼합 RMSE | 상대 변화 |
|---|---:|---:|---:|---:|
| 0 | 7 | 0.150758 | 0.147075 | −2.44% |
| 0 | 101 | 0.150542 | 0.146652 | −2.58% |
| 2 | 7 | 0.123053 | 0.120381 | −2.17% |

네 조합 모두 개선, 평균 상대 RMSE 변화 −2.36%로 사전 탐색 기준(네 조합
모두 개선, 평균 1% 이상 감소)을 통과했다. 이전 단일 문맥 선별의 −4.80%는
평균 후 −2.44%로 줄어, 한 문맥의 좋은 결과만 채택하지 않은 의미가 있다.

총 CPU 계산 시간은 문맥별 예측 마지막 완료까지 약 690초였다.
폴드 0·문맥 1은 이전 프로브 결과를 입력·코드·환경·행 순서 검사 후
재사용했고, 나머지 7개 문맥은 새로 예측했다. 각 문맥 파일을 저장했다.
실행 핸들은 대화 환경 전환 뒤 사라졌고, 4개 점수 저장 직후 최종 요약은
남지 않았다. 별도 `finalize_existing.py`가 네 문맥 파일과 폴드별 평균,
저장된 네 RMSE를 다시 계산·일치 확인한 뒤 `result.json`만 복구했다.
모델을 다시 적합해 새 독립 성적처럼 세지 않았다.

이 두 폴드는 탐색 자료이며 비공개 평가 정답과 확인용 폴드 8·9는 사용하지
않았다. 기존 연구는 공개 정답 전체를 이미 활용했으므로 확인 폴드도
완전히 새로운 독립 시험이 아니다. CPU 수치는 기존 GPU 기록과 비트 단위
일치를 전제로 하지 않는다. 이 단계는 통계적 유의성이나 최종 채택을
증명하지 않는다. 다른 탐색 구간, 최신 후보와의 비교, 블록 신뢰구간,
끝단 인과성·재현 검사가 남았다.

실행 결과: analysis/local/tabpfn_cpu_bag/20260927_182052/.
`manifest.json`, `fold*_context*.csv`, `fold*_bag.csv`, `partial_results.json`,
`result.json`, `progress.log`로 감사할 수 있다. 모델은 로컬 CPU 파일을
사용했고 외부 조회는 비활성화했다. 대회 제출은 하지 않았다.
