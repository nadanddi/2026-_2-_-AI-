**유력 — 자정의 출처 전환과 초기 상태의 부족이 0~3시 오차에 관여한다.** 자정 실내온도 점프와 초기 오차 사이에 음의 상관이 있다. 다만 이전 날 이력을 모두 버리는 모델이 단독 성능에서 우월하지 않아, 자정 초기화만으로 원인이 해결된다고 볼 수 없다.

## 3. 문제 A — 하루 수준 오차를 얼마나 설명할 수 있나

### 3.1 현재 모델에 남은 오차

현재 온도 OOF 전체 RMSE는 0.69654. 온실-날별 평균 오차를 각 행에 대응시켜 오차를 분해하면, 하루 수준 성분이 오차제곱합의 **56.51%**다. 하루 안 잔여 오차의 RMSE는 **0.45934**다. 이는 사후 진단이며 당일 정답 평균을 예측 피처에 넣지 않았다.

### 3.2 독립 후보

온도 기본 후보 네 개를 먼저 비교하고, 하루 수준을 직접 겨냥한 두 개를 추가했다. 혼합 비중은 공통으로 20% 한 값만 사용했으며 최적 비중을 탐색하지 않았다.

- `ridge_reset`: 당일에 초기화하는 실내·외 온도, 일사, 난방의 지수평균과 현재값·시각·온실 표시를 쓰는 Ridge. 총 19개 피처, 결측값은 학습 폴드의 중앙값, 표준화 후 alpha=100.
- `ridge_history`: 위에 이전 날까지 이어지는 지수평균 12개를 추가.
- `resid_reset`: `ridge_reset`이 학습 폴드에서 남긴 행별 잔차를 LightGBM으로 학습. 현재값, 0시값, 당일 누적 평균·표준편차·차분, 지수평균 등을 사용하며 총 89개 피처. 이전 날 입력은 쓰지 않는다.
- `resid_history`: 연속 지수평균과 자정 센서 점프를 추가한 115개 피처 버전.
- `daily_reset`: 행별 잔차 대신 학습 온실-날의 평균 잔차를 목표로 삼아, 현재 시각까지 입력으로 예측.
- `daily_h0`: 동일한 하루 평균 잔차를 0시 센서값·온실·일차·구간 표시만으로 예측하여 당일 보정값을 고정.

## 4. 문제 B — 자정 직후 오차

0~3시 전체 RMSE는 **0.82337**, 4~23시는 **0.66830**이다. 2차 구간의 0~3시는 **1.00598**로 더 어렵다.

자정의 실내온도와 직전 23시 실내온도 차이를 점프로 정의했다. 직전 관측이 정확히 1시간 전일 때만 계산했다. |점프|≥3℃인 초기 228행의 RMSE는 **0.88553**, 작은 점프 초기 1,320행은 **0.80286**이다. 점프가 결측인 52행은 이 비교에서 빠졌다. 큰 점프 집단에서 점프와 예측 오차(예측−정답)의 상관은 **−0.5624**, 작은 집단에서는 **−0.2248**이었다.

이는 갑자기 따뜻해진 날에 예측이 상대적으로 낮아지는 양상과 맞는다. **출처 전환 뒤 이전 날 이력이 부적절한 초기 상태를 줄 수 있다는 설명은 유력하지만, 이 상관으로 원인을 확정할 수는 없다.** 잡음, 실제 초기 배지 상태, 모델 수축이 함께 작용할 수 있다.

실제로 단독 Ridge는 이전 날 이력을 포함할 때 초기 RMSE가 1.10283 → 0.97365로 좋아졌다. 독립 행별 잔차 모델 역시 단독 초기 RMSE는 이력 포함 쪽이 0.85281, 초기화 쪽은 0.88357이다. 따라서 **이전 이력을 일괄 삭제하는 변경은 지지되지 않는다.** 유망한 결과는 초기화 모델을 기존 모델의 보완재로 섞었을 때 나왔다.

후속으로 0~3시에만 `resid_reset`을 20% 섞고 나머지 시간은 기준값을 유지했다. 전체 RMSE는 **0.69202**, 차이 구간은 **[-0.00717, -0.00227]**. 초기 시간 RMSE는 **0.80015**, 초기 구간 차이 구간은 **[-0.03655, -0.01164]**다. 전체 시간 혼합의 0.68733보다 효과가 작다. 이는 초기 개선을 확인한 뒤 추가한 **사후 탐색 6개** 중 하나이므로 독립적인 확증 결과로 취급하지 않는다. 2차 구간의 초기 전용 혼합 차이 구간 역시 0을 포함한다.

**추측:** 하루 시작의 실제 배지 상태를 직접 측정하지 못하는 문제가 일부 남을 수 있다. 현재 입력만으로 복원할 수 없는 정도를 이번 실험으로 식별하지는 못했다.

## 5. 문제 C — EC 고값

현재 EC 기준 RMSE는 **0.20921**다. EC>1.5인 **510행(5.31%)**이 전체 오차제곱합의 **62.56%**를 차지한다. 해당 행의 평균 오차는 **−0.51502**, RMSE는 **0.71791**로 과소예측이 뚜렷하다.

고값 행이 한 번이라도 있는 날은 **33개**다. 하루 평균 EC>1.5인 날은 **19/400개**다. 두 정의를 혼동하면 희소성 및 분류 성능 해석이 달라진다.

현재 기준 예측을 위험 점수로 사용하면, 고값 행 판별의 ROC-AUC는 **0.9763**, 평균정밀도(AP)는 **0.7737**이다. 하루 평균 고값 여부를 각 시각까지의 예측으로 판별한 AP는 **0시 0.7054, 3시 0.7423, 12시 0.7369, 23시 0.7807**이었다. 이는 판별 가능한 신호가 있음을 뜻하지만 실제 임곗값에서의 정밀도·재현율이나 고값 수준의 정확도를 보장하지 않는다. 이번에는 임곗값을 선정하지 않았다.

비교한 모델은 당일 누적 피처를 사용하는 동일 설정 LightGBM 두 개다. 하나는 일반 제곱오차, 다른 하나는 학습 정답 EC>1.5 행에 가중치 3을 주었다. 학습 가중치는 평가 정답이나 평가 입력을 사용하지 않는다.

가중 모델은 고값 구간 오차를 낮췄지만 나머지 구간 오차와 고값 순위 판별은 악화했다. 일반 독립 모델에 비해서도 전체 RMSE가 0.23727 → 0.24264로 나빠졌다. **이 실험에서의 고값 일괄 가중은 실패**다.

**추측 수준의 다음 방향:** 현재 앙상블의 고값 위험 점수를 이용한 수준 보정을 검토할 수 있다. 다만 저장된 OOF 전체에 보정기를 학습하고 같은 OOF에서 재평가하면 낙관적 결과가 나온다. 외부 폴드를 제외한 상태에서 내부 OOF를 새로 만드는 중첩 검증이 필요하다. 이번에는 보정기를 구현하거나 개선 효과를 주장하지 않았다.

수치 재현: `independent_analysis.py`, `supplement_analysis.py`.

## 6. 인과성·누출 점검

1. 새 피처 생성 함수는 정답을 받지 않는다. train_X와 test_X를 시각 순서로 연결하되, 각 온실 안에서만 연산한다. **다른 온실 입력을 평가 행 피처로 합치지 않는다.** 학습용 다른 온실 행과 정답을 모델 훈련에 함께 쓰는 것은 학습 자료 사용 범위다.
2. 당일 평균·표준편차는 expanding, 차분은 과거 방향이다. 지수평균도 현재까지 계산한다. 0시값은 0시에서만 생성한 뒤 같은 날 안에서 전방 채움한다. `groupby.first()`처럼 결측 0시를 미래 관측값으로 채우지 않는다.
3. history 후보의 이전 날 이력도 같은 온실의 과거 입력이다. 규정상 허용되는 이력인지와, 출처 전환에 유용한 이력인지는 별개의 문제다. 전체 평가 입력의 평균·순위·클러스터를 피처나 학습 조정에 쓰지 않았다.
4. F13·F47 각각 205일차의 0·3·12·23시를 절단점으로 잡았다. **절단점 이후 모든 입력과 다른 온실의 모든 입력**을 `값×17+133`으로 바꿔 다시 생성했다. 절단점까지 피처 전체가 정확히 같은지 `assert_frame_equal`로 확인했고 **8개 검사 모두 통과**했다. 이는 값 변경에 대한 피처 불변성 검사이며, 모든 가능한 누출을 수학적으로 증명한 것은 아니다.
5. 결측값 대체, 표준화, Ridge 및 LightGBM은 각각 학습 폴드에서만 적합한다. 새 모델의 가중치·보정 목표에 검증 정답을 사용하지 않는다. 하루 평균 잔차 목표는 학습 날에서만 생성하므로 학습 자료 가공 범위다. 평가일의 인접 날 정답을 피처에 넣지 않는다.
6. 기준 OOF는 비교와 고정 비중 혼합에만 사용한다. 다른 폴드의 기존 OOF 잔차를 학습 목표로 삼아 보정기를 만들지 않았다. 기존 OOF 생성기 전체에 대한 인과성 재감사는 이번 범위가 아니다.
7. 실제 평가행 예측이나 제출 CSV를 만들지 않았다. 새 파일은 모두 `analysis/codex_independent/` 안에 저장했다. 파이썬 바이트코드 생성을 꺼서 기존 모듈 폴더에 캐시를 만들지 않았다. 커밋·푸시도 하지 않았다.

## 7. 다중비교와 실패 기록

온도 기본 4개와 하루 수준 2개 = **6개 모델**, 각각 단독/20% 혼합으로 **12개**를 비교했다. 초기 개선 관찰 후 초기 시간에만 적용하는 변형 **6개**를 추가했다. EC는 **2개 모델×단독/혼합=4개**. 합계 **22개 예측 변형**이며, 36개 잔차 상관도 탐색했다. 이후 선정한 한 후보에 저온 조건 3개 및 온실·폴드별 분석을 추가했다. 통계 구간은 다중비교를 보정하지 않았다.

실패하거나 지지되지 않은 시도:

- 하루 평균 잔차를 당일 누적값으로 학습: 20% 혼합 0.69616, 차이 구간 [-0.00725, +0.00636]; 2차 구간은 악화.
- 하루 평균 잔차를 0시값만으로 학습: 20% 혼합 0.69881; 전체 개선 없음.
- Ridge만 섞기: 초기화/이력 포함 모두 전체 성능 악화.
- 이전 날 이력을 버리는 모델로 단독 교체: 기준 모델보다 나쁨.
- 고값 EC 행의 단순 3배 가중: 고값 구간 개선을 전체 성능으로 연결하지 못함.
- 실행 중 OOF의 row_id가 객체 배열이라 기본 np.load에서 읽기 오류가 한 번 발생했다. 이번에 만든 스크립트에서 제공된 로컬 NPZ에 대해 allow_pickle=True를 지정해 재실행했다. 아래 완료 수치는 수정 후 실행 결과다. 데이터 파일은 변경하지 않았다.

## 8. 권장 후속 작업과 산출물

우선순위는 **고정된 resid_reset 20% 혼합을 F47 2차 구간에서 추가 검증하는 것**이다. 비중을 여러 개 다시 고르기 전에, 평가 배치와 유사한 미사용 연속 블록 또는 중첩 검증에서 유지되는지 확인하는 편이 낫다. 이번 분석은 현재 모델 수정이나 제출 작업까지 진행하지 않았다.

재현 순서: 제공된 파이썬으로 `-B` 옵션을 사용해 `independent_analysis.py`, `daily_offset_analysis.py`, `supplement_analysis.py`, `extrapolation_analysis.py`, `stability_analysis.py`를 실행한다. 모든 경로는 이 보고서와 같은 폴더다. 실행 환경 의존성은 요청 문서의 환경을 그대로 사용했다. 저장된 NPZ는 검증행 예측이며 제출 파일이 아니다.

- `results.json`: 기본 후보, 오차 분해, 상관, 감사 결과, 입력 해시.
- `daily_results.json`: 하루 수준 목표 실험.
- `supplement_results.json`: 시간대 제한 혼합, 오차 성분 변화, EC 하루 판별.
- `extrapolation_results.json`: 세 저온 외삽 검증.
- `stability_results.json`: 온실별·폴드별 안정성.
- `sub_temp_independent_oof.npz`, `daily_offset_oof.npz`, `sub_ec_independent_oof.npz`: 재분석용 검증 예측.
- `sub_temp_diagnostic.json`, `sub_ec_diagnostic.json`: 행 정렬 및 잔차 진단용 자료.
