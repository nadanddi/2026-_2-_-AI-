# EC 후보의 실제 점수 확인 판단

작성일 2026-09-28. 이번 메모는 **제출 명령이 아니다**. EC 전담
요청서의 사용자 결정인 “제출 파일 제작·제출은 사용자 지시
전에는 하지 않습니다”를 따른다. 원본 파일과 플랫폼 상태는
변경하지 않았다.

## 현재 확인된 상태

- 대회 문제설명서 6.2·7.3절: 팀당 총 25회 업로드, 즉시 채점,
  **마감 전 마지막 유효 제출**이 최종 답안. 별도의 비공개 평가
  세트는 없다. 마감은 2026-10-16 18:00 KST.
- 제출 기록상 유효 제출은 5회. 마지막 유효 점수는 온도
  **0.5456**, EC **0.2134**. 목표별 기제출 최고는 온도 0.5456,
  EC 0.2055다. 실제 플랫폼의 남은 횟수는 여기서 직접 조회하지
  못했으므로 20회라는 값은 제출 기록이 완전하다는 전제다.
  현재 연결된 브라우저에는 열린 대회 탭이 없고, 원본 기록과
  문제설명서 추출에도 로그인된 제출 현황 주소가 없어 플랫폼
  현재 상태를 독립 조회하지 못했다.
- 기존 `submission_07.csv`는 두 기제출 최고 열을 합친 미제출
  답안이다. 파일 SHA-256은
  `d6f22abc403290a50fbf6e87e73e125e656865c1eed5d25b56656fb8d5b7a3c0`으로
  원본 기록과 일치한다. 온도 0.5456/EC 0.2055는 열 동일성에서
  나온 예상이며 이 **조합 파일 자체는 미제출**이다. 대응 재현
  ZIP과 설명자료도 원본 저장소에 있다. ZIP 무결성 검사에서 손상
  항목이 없었고, ZIP 안의 `submission_07.csv`는 바깥 CSV와
  바이트 해시가 같다.
- EC v2 미제출 로컬 후보는 위 온도 열과 원본 3회차 EC 80% +
  TabPFN 네 문맥 20%다. CSV SHA-256
  `074c1b519772c441c0b919b211950b02a60ad25014e894646ba7d6560af1703d`,
  재현 ZIP SHA-256
  `51710f357faeab77b2ab63407e9dfff3ba48f5bf71b56ea27ba48ccdc4772dd8`.
  새 폴더에서 압축을 풀어 재생성한 CSV가 바이트 단위로 일치했다.
  ZIP 무결성 검사도 통과했다. 실제 플랫폼 EC 점수는 없다.

## 판단

| 선택지 | 현재 근거 | 남는 위험 |
|---|---|---|
| 마지막 유효 5회차 유지 | 이미 채점됨 | EC 0.2134로 기제출 최고 0.2055보다 나쁨 |
| 기제출 최고 열 조합 07 | 두 열 각각 채점됨, 대응 파일·패키지 존재 | 조합 파일 자체의 플랫폼 채점·재현 심사는 아직 없음 |
| EC v2 실제 채점 | 탐색 4폴드와 고정 확인 2폴드 개선, 여러 문맥 재현 | 평가 날짜 범위 확인 10일은 −0.32%뿐; 밀폐·F47 전이 불확실 |
| EC combo 실제 채점 | 원본 사전 검증 6칸 통과 | EXT12와 추가 전이 진단에서 악화. 현재 비권고 |

**현재 결론:** 추가 로컬 분할은 이미 폭넓게 사용한 같은 400일의
정답을 재사용하므로 실제 평가 EC 개선 여부를 확정할 수 없다.
후보를 계속 조정하면 운 좋은 RMSE를 고르는 위험이 커진다.
EC combo는 제출 후보로 승격하지 않는다. EC v2는 검증을 통과한
미제출 후보로 유지한다. 플랫폼 점수를 확인하려면 사용자 지시에
따라 기존 준비물을 제출하는 단계가 필요하다. 어떤 후보를
언제 제출할지는 팀이 마지막 유효 제출 규칙과 남은 횟수를
확인하고 결정해야 한다. 성적 확정 전에는 실제 최고 열 조합을
마지막 유효 제출로 남길 필요도 있다.
