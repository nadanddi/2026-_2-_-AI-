# 자료 출처·이용조건·접근 절차·선택 기준 (팜모니_이미지)

## 1. AI Hub 「지능형 수직농장 통합 데이터(딸기)」(데이터셋 596)
- **역할**
  - 실제 사진(라벨 0)
  - 모든 자체 가짜와 GPT 편집의 원본
  - 지문 DB 두 개(`fp_db.npz.xz` 12×16 색 평균, `finefp_db.npz.xz` 흑백 24×32 + 12×16 라플라시안 에너지)의 원천. 원천 사진 152,043장 전체에서 만들었습니다.
- **접근 절차**: AI Hub 회원 가입 → 데이터셋 이용 신청 → 승인 → 팀원 계정으로 다운로드. 연구·AI 학습 목적입니다. 받은 파일은 `01.데이터/1.Training/원천데이터_add_20260807/*.tar` 271개와 `01.데이터/2.Validation/원천데이터/*.tar` 35개입니다.
- **이용조건**: AI Hub 데이터는 승인받은 이용자만 쓸 수 있고 원본 재배포가 제한됩니다(AI Hub 이용 약관, 일반 지식으로 적은 것이며 원문은 AI Hub 사이트 기준). 그래서 원본 사진과 그 파생 이미지(자체 가짜·GPT 편집본)는 넣지 않고, 목록(manifest)과 제작 코드만 넣었습니다.
  - 지문 DB는 사진이 아니라 사진별 숫자 통계입니다. 사진당 576바이트(색 지문), 정밀 지문은 흑백 768 + 에너지 192값입니다.
  - 팀 결정(2026-10-12)에 따라 출처를 밝히고 제출물에 넣었습니다.
- **선택 기준**(`data/manifests/*/im_real_raw`, `im_new_raw`, `im_h_raw`, `im_i_raw`, `im_r5_raw` 목록)
  - tar마다 개체를 돌아가며 고르게 뽑았고, 품종·농장·축소 배율이 고르게 되도록 추가 추출했습니다.
  - 붉은 LED 조명 사진(지문 평균 R−G > 25)은 뺐습니다.
  - 새 추출 때마다 이미 쓴 파일은 뺐고, 봉인 검증용은 촬영 묶음(group)이 겹치지 않게 했습니다.
  - 추출 코드: `im01*`, `im30`, `im41`, `im51`, `im63`
- **처리**: 배포 형식에 맞춰 덮게 축소 → 가운데 768×1024(가로 사진은 1024×768) 크롭 → JPEG Q92 4:2:0. 공개 샘플 21장의 형식을 실측해 맞췄습니다.

## 2. 학습 이미지 목록 (`data/manifests/`)
- 세트마다 `manifest.csv`가 있습니다.
  - 열: `file`, `label`(0 실제/1 가짜), `kind`(유형), `info`(제작 정보: 필터 강도, 생성 모델·지시문, 마스크 넓이 등), `source`(AI Hub 원본 파일명), `group`(촬영 묶음), `farm_code`, `tar`, `other`(합성·스타일 참조 원본)
- 최종 모델 구성 요소별로 쓴 세트
  - 기본 판별기: `im_set_v4`, `im_set_sd2`, `im_set_v5`(연구실 PC `local_pc/`·서버 `server/`), 실제 원본 목록 `im_real_raw`
  - 전문가 E_pg·E_ps·E_L: 위 세트 + `im_set_gpt1`, `im_set_gpt2`, `im_set_newreal`, `im_set_v7tr`, `im_set_qwentr`
  - 전문가 H: `im_set_h3`, `im_set_h3j`
  - E_gr: `im_set_gptr`(split=train), `im_set_gptr_src`, `im_set_h3`(실제), `im_set_h3j`
  - E_gpt: `im_set_gpt1`·`gpt2`·`gpt3`·`gptr`(가짜 전부), `im_set_h3`(실제), `im_set_h3j`, `im_set_gptr_src`
- 검증 전용(학습 미사용): `im_set_r2`~`r5`(봉인 검증, 각각 한 번만 개봉), `im_set_r3p_*`(처리 변형), `sealed_c3/*`, `im_set_realg`·`realn`, `jig500`
- 탐색 중 만들었지만 최종 모델에 쓰지 않은 세트: `im_set_h3s`·`h3g`(기각된 후보 I), `im_set_v6`·`v7`·`sd3`·`h1`·`gpt3r` 등

## 3. 생성 모델과 GPT 자료

|---|---|---|

| SDXL base 1.0 / SDXL inpainting 0.1, sdxl-vae-fp16-fix | 같음 | CreativeML OpenRAIL++-M / MIT |

| ChatGPT 내장 이미지 생성·편집 (연구실 코덱스 수행) | GPT 4묶음 600장 | OpenAI 이용약관(생성물 권리는 이용자에게 귀속, 일반 지식) |
- 가중치는 Hugging Face에서 받았고(다운로드 스크립트 `history_repro/팜모니_이미지_재현패키지_01/server/s01_weights.sh`, `s02_weights_xl.sh`), 학습 자료 제작에만 썼습니다.
- GPT 자료의 요청서·지시문·기록은 `data/gpt_generation/`에 있습니다. `codex_ai_gen_work_*`는 gpt1~gpt3, `codex_gpt_regen_20261015`는 gptr, `claude_ai_gen_work`는 원본 목록과 요청서입니다. 각 이미지의 원본 AI Hub 파일명, 지시문, 결과 파일 해시가 기록돼 있습니다.

## 4. 공개 샘플 21장 사용 내역 (실제 사용한 대로)
- **학습에는 넣지 않았습니다**(어떤 모델 파일에도 공개 샘플 행 없음).
- 설계 참고
  1. 파일 형식 실측(`im02_public_forensics.py`): 21장 모두 JPEG Q92·4:2:0·EXIF 없음 → 배포 처리 형식과 형식 게이트의 근거
  2. 공개 가짜 일부의 원본을 AI Hub 지문 DB에서 찾아 비교(`im10`·`im12`) → 원본 대조 규칙 R1을 착안. 문턱 값 자체는 학습 자료 분포로 정함
- 검증·선택 지표로 사용
  - 10-10~10-12 초기에는 "공개 21장 중심 검증"(`IM_계획_v3.md`)으로 후보 구성(가짜 제작 5판 포함 여부, 기본 판별기 조합)을 고를 때 공개 21장 정확도·로그손실을 지표로 썼습니다. 계획한 열람 상한을 넘어 5회 이상 봤고(사용자 지시로 진행), 그 뒤로는 참고로만 봤습니다(작업일지 10-11·10-12).
  - 나단3 이후 모든 후보는 "공개 21/21 유지"를 비열화 점검 조건으로 썼습니다.
