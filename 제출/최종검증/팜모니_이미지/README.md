# 팜모니_이미지 — 이미지 미션 최종 검증 자료

작성: 팀 팜모니, 2026-10-17(10-20 보완).

## 개요
- **과제:** 딸기 시설재배 사진이 실제 사진(0)인지, 생성·편집된 가짜(1)인지 판별합니다.
- **기본 판별:** 사진 한 장에서 두 갈래 확률을 내 평균합니다.
  - CLIP 의미 특징(사전학습 고정) + 로지스틱 회귀
  - 저수준 통계 38개(잡음·선명도·JPEG 격자 등) + 결정나무 부스팅
- **원본 대조:** 실제 사진의 원천인 AI Hub 사진 15만 장의 축소 지문 DB와 대조합니다.
  - 원본이 있는데 국소적으로 다르면 가짜 쪽으로, 원본과 거의 같으면 진짜 쪽으로 확률을 옮깁니다.
- **유형별 전문가:** 기본 판별이 놓치기 쉬운 유형만 따로 보는 작은 판별기들입니다. 부분 생성, 부분 스타일, 국소 조각, 필터, GPT 재그리기, GPT 편집이 있습니다.
  - 전문가 하나라도 자기 문턱을 넘으면 가짜 쪽으로 올립니다.
- 모든 계산은 이미지 한 장 단위로 독립적이며(GPU 8장 묶음 계산에 따른 수치 차는 최대 .008, ③), 문턱은 학습 자료에서 정했습니다(⑤).

## ① 사용 자료와 출처
1. **AI Hub 「지능형 수직농장 통합 데이터(딸기)」(데이터셋 596)**: 실제 사진, 가짜 제작의 원본, 지문 DB의 원천입니다.
   - 데이터셋 페이지: https://www.aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&aihubDataSe=data&dataSetSn=596 (접근 절차·활용 방법은 `data/README_data.md` 1절)
   - **고른 경위:** 대회가 제공한 공개 샘플과 촬영 환경(딸기 시설재배, 재배 시설·구도·조명)이 가장 비슷한 공개 실제 사진을 찾다가 이 데이터셋을 골랐습니다. 공개 샘플 일부는 이 데이터셋의 사진과 매우 가깝게 대응했습니다(`data/README_data.md` 4절). 이 데이터셋이 운영진의 원자료인지는 확인된 사실이 아니며, 팀은 '비슷한 외부 실제 사진'으로 다뤘습니다.
   - **학습에 쓴 방법:** 데이터셋 안에서 사진을 촬영 묶음·품종·농장이 고르게 되도록 뽑았습니다(대회 이미지 한 장 한 장에 맞춰 고른 것이 아님). 뽑은 사진을 대회 배포 조건(덮게 축소 → 가운데 768×1024 크롭 → JPEG 품질 92, 4:2:0)에 맞게 변형해 실제 사진으로 썼고, 같은 사진에 문제설명서의 6유형을 적용해 가짜를 만들었습니다.
   - 이용 신청·승인 후 팀원 계정으로 원천데이터 tar 306개(Training `원천데이터_add_20260807` 271, Validation `원천데이터` 35)를 내려받았습니다. 재배포 제한 때문에 AI Hub 원본과 그것을 소재로 만든 이미지는 넣지 않고 문서로 대신합니다(7번).
   - 지문 DB는 사진이 아니라 사진별 숫자 통계라서, 출처를 밝히고 추론 모델에 포함했습니다(팀 판단, AI Hub 약관 조항과의 원문 대조는 하지 않음). 자세한 내용은 `data/README_data.md`에 있습니다.
2. **자체 제작 가짜**: 문제설명서의 6유형(필터·합성·부분 생성·부분 스타일·전체 생성·전체 스타일)으로 만들었습니다. 전체 생성은 문장만으로 생성했고(AI Hub 원본 없음), 나머지 유형은 위 실제 사진을 가공했습니다.
   - 프로그램 처리: 필터, 합성, 색·톤 스타일
   - Stable Diffusion 1.5 / 1.5 inpainting, SDXL base 1.0 / SDXL inpainting 0.1, sdxl-vae-fp16-fix
   - Qwen-Image-Edit(Apache-2.0, Lightning 8단계 LoRA)
3. **GPT 생성·편집 자료**: ChatGPT 내장 이미지 생성·편집 기능으로 만들었습니다. 편집은 AI Hub 원본에 지시문을 주어 만들었고, gpt1의 전체 생성 25장은 문장만으로 만들었습니다. 묶음별 수량은 다음과 같습니다.

   | 묶음 | 수량 | 내용 |
   |---|---|---|
   | gpt1 | 100 | 전체 생성·전체 스타일·부분 생성·부분 스타일 각 25 |
   | gpt2 | 150 | 부분 생성 100, 부분 스타일 50 |
   | gpt3 | 200 | 부분 생성 100, 부분 스타일 50, 전체 다시 그리기 50 |
   | gptr | 150 | 같은 구도 전체 다시 그리기 |

   요청서·지시문·기록은 `data/gpt_generation/`에 있습니다.
4. **사전학습 가중치**: OpenAI CLIP ViT-L/14@336px, ViT-B/16(MIT). open_clip 3.3.0 `pretrained="openai"`로 받은 시각부만 fp16 safetensors로 저장했고, 추가 학습은 하지 않았습니다. 생성 모델(SD·SDXL·Qwen)은 학습 자료 제작에만 썼고 제출물에는 넣지 않았습니다.
5. **공개 샘플 21장**: 학습에 넣지 않았습니다. 다만 ① 파일 형식 실측과 원본 대조 규칙 착안(설계 참고), ② 10-10~10-12 초기 후보 구성(가짜 제작 5판 포함 여부, 기본 판별기 조합)을 고를 때 검증 지표로 5회 이상 썼습니다, ③ 이후 모든 후보에서 21/21이 유지되는지 점검했습니다. 자세한 내용은 `data/README_data.md` 4절에 있습니다.
6. 그 밖의 외부 자료는 없습니다. 이전 대회 자료도 쓰지 않았습니다.
   - 개발 도구: 코드 작성과 GPT 이미지 생성 작업에 생성형 AI 도우미(Anthropic Claude, OpenAI Codex·ChatGPT)를 썼습니다. 문서의 '코덱스'는 OpenAI Codex로 수행한 작업, '연구실 PC·GPU 서버'는 팀이 학습에 쓴 장비입니다. 추론에는 AI 도우미를 쓰지 않습니다.
7. **학습 이미지 제출 범위(2026-10-20 보완):** 최종 모델 학습 이미지 17,164장을 두 가지로 나눴습니다. 자세한 내용은 `data/README_학습이미지_제출범위.md`에 있습니다.
   - **파일로 제출:** AI Hub 원본 없이 문장만으로 만든 전체 생성 967장(SDXL 900, SD1.5 42, GPT 25). 접수용 ZIP의 `data/generated_images/`에 넣었습니다.
   - 목록 17,164장 가운데 4장(`im_set_sd2`의 통째 타일 2장, 원본이 빨간 조명 사진인 2장)은 학습 코드 규칙으로 제외되어 실제 학습은 17,160장입니다. 기본 판별기 학습 수(실제 2,467 + 가짜 7,124 = 9,591)는 이 제외를 반영한 수입니다.
   - **문서로 대체:** AI Hub 소재 16,197장(원본과 그 편집·합성본). 원본 대응 해시는 `data/source_sha256.csv`에 있습니다.

## ② 특징 구성과 사용하는 시간 범위
- 이미지 미션이라 시간 축이 없습니다. **각 이미지는 그 이미지 파일 하나만 입력으로** 계산합니다.
- 특징
  - 의미 특징: CLIP ViT-L/14@336, 원해상도 336 조각 3×3 평균
  - 국소 조각 특징: ViT-B/16, 224 조각 54개(간격 112)
  - 저수준 38특징: 잡음 잔차·선명도·JPEG 격자·채도·주파수·타일 편차(`lowfeat.py`)
  - 원본 대조 특징: 12×16 색 지문, 정밀 지문(흑백 24×32 + 12×16 라플라시안 에너지)과 학습 전에 만든 AI Hub 지문 DB의 L1 거리
  - 파일 형식 판별: JPEG·4:2:0·Q92 양자화표

## ③ 평가 입력의 사용 범위
- 평가 이미지끼리 정보를 주고받지 않습니다. 이미지마다 독립적으로 계산합니다(다른 이미지의 값·통계를 쓰지 않음). 경로를 정렬한 뒤 8장씩 묶어 GPU로 계산하므로 **입력 순서와는 무관**합니다. 다만 묶음 구성(함께 들어온 파일 집합)이나 GPU fp16/CPU fp32 차이로 확률에 작은 수치 차가 생길 수 있습니다. 나단3·4 사이 최대 .008, 판정 1장 차이가 있었습니다.
- 공식 `self_check.py` 순서 독립성 검사는 OK였습니다(10-16, 서버, `logs/README_logs.md`).
- **비공개 평가 자료는 학습·설정 선택에 쓰지 않았습니다.** 운영진 시험 이미지는 코드 제출 방식이라 팀이 접근할 수 없었습니다. 정답 없이 시험 입력의 통계만 모으는 분석도 10-16에 검토했지만, 규정 취지상 하지 않았습니다.
- Colab 시간 측정에 쓴 `test_images_521.zip`은 **우리 자료로 구성한 시간 측정용 대용품**이며, 운영진 시험 자료가 아닙니다. 521장으로 잰 시간을 524장 기준으로 환산했습니다(⑥, 524장은 팀이 채점 장수로 보고 써 온 시간 환산 기준). 구성은 gpt3 200 + 처리 실제(realn) 300 + 공개 샘플 21이고, 목록과 SHA는 `logs/test_images_521_구성.txt`에 있습니다.
- 리더보드 점수 사용 내역은 ⑤ 끝에 정리했습니다.

**정의**
- 정밀 지문: 사진을 덮게 축소·가운데 768×1024 크롭 후 흑백 24×32 평균 g(768값)과 64px 구역 12×16 라플라시안 분산 log값 e(192값). DB 1위와의 거리 dg1 = 평균 abs(g−g_db), gap = 2위 거리 − dg1.
- 국소·전체 차이: dg = abs(g − g_db1), de = e − e_db1. **lg** = (dg − 중앙값(dg)) 상위 2% 평균, **le** = abs(de − 중앙값(de)) 상위 5% 평균, **ge** = 중앙값(de).
- 12×16 색 지문(R1): 사진 12×16 RGB 평균과 DB의 평균 절대차 1위 d1, gap = 2위 − 1위.
- 형식 게이트: PIL로 연 파일이 JPEG이고, 크로마 서브샘플링이 4:2:0(`JpegImagePlugin.get_sampling == 2`)이며, 양자화표가 PIL quality=92로 저장했을 때의 표와 **완전히 같을 때**만 참.
- 예외 대체(이미지별 고정)
  - 저수준 특징 실패 → p = p_CLIP만 쓰고, 저수준을 입력으로 쓰는 E_f·E_gr·E_gpt는 미적용
  - CLIP 실패 → p_low만
  - 둘 다 실패 → .5
  - 원본 대조 실패 → R1·정밀 대조 규칙 미적용
  - 전문가 계산 실패 → 그 전문가 미적용
  - NaN → .5

**E_gpt의 rc 제외 결정**
- E_gpt 첫 판(rc에도 적용)은 GPT 묶음 하나씩 빼기 검증에서 효과가 있었습니다. 나단9가 놓친 26장 중 14장을 새로 잡았습니다.
- 하지만 실제 비용 기준을 근소하게 넘어 불통과였습니다(합집합 실제 오탐 +0.12%p, R5 균형 정확도 −0.28%p).
- 분해해 보니 새 실제 오판 대부분이 진짜 확정(rc) 사진이었고, GPT 가짜 600장 중 rc는 0장이었습니다. 그래서 rc 사진은 제외했습니다.
- 같은 자료로 다시 집계하면 사전 기준을 충족합니다: 합집합 +0.03%p, R5 변화 0, R2 −0.027%p(실제 1장), 빼기 검증 14장 유지. 다만 불통과를 본 뒤 같은 자료로 정한 변형이라 수치가 낙관적일 수 있습니다.
- 이 결정은 내부 자료로만 했고, 리더보드는 쓰지 않았습니다. 근거: `code/claude_image/IM_Egpt_rc제외_v1.md`.
