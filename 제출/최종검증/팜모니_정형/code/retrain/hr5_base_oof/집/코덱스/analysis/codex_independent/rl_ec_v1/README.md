# EC 보상 기반 탐색

`PROTOCOL.md`는 점수를 보기 전에 고정한 실험 계획입니다.
`run.py`는 단일 상태 밴딧으로 세 학습 방법 중 다음 실험을 선택합니다.

보상은 `1 - 후보 RMSE / 동일 환경 대조군 RMSE`입니다. 처음 각 후보를
한 번씩 실행한 후 `평균 보상 + 0.03 × sqrt(2 log(회차 + 1) / 평가 횟수)`가
큰 후보를 선택합니다. 같은 후보에 같은 폴드·시드를 재사용해 새로운 증거로
세지 않습니다. 환경의 난이도와 보상이 서로 독립이라는 보장은 없으므로
이 점수는 탐색 휴리스틱이며, 이론적인 UCB 후회 한계를 주장하지 않습니다.

## 실행

PowerShell에서 원본 프로젝트 경로를 지정하고, 번들 Python 3.12로 실행합니다.
기존 프로젝트의 라이브러리를 읽을 수 있는 권한이 필요합니다.

```powershell
$env:AGRI_SOURCE_ROOT = '원본 프로젝트의 절대 경로'
$env:PYTHONPATH = ''
& 'C:/Users/aozks/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' -X utf8 -B -u ./analysis/codex_independent/rl_ec_v1/run.py
```

입력은 `train_X.csv`와 `train_y.csv`뿐입니다. test_X를 읽지 않습니다.
결과는 `analysis/local/rl_ec_v1/실행시각/`에 새로 저장됩니다. 기존 파일은
덮어쓰지 않으며, 실행 디렉터리를 자동으로 재개하지 않습니다.

## 해석

- 탐색 성과와 확인 성과를 구분합니다. 선택 당시 보상은 일반화 성능 추정치가 아닙니다.
- 확인 네 조합 모두와 보정된 블록 신뢰구간을 통과해야 예비 통과입니다.
- 기존 연구에서 전체 공개 데이터가 사용됐으므로 신규 독립 테스트는 아닙니다.
- 예비 통과해도 전체 DIAG10·A/B·최신 후보 비교, 최종 파이프라인 인과성
  검사 전에는 채택하지 않습니다. 실패하면 기존 모델을 유지합니다.
- 이번 버전은 EC만 다룹니다. 온도 실험과 최종 제출 생성 기능은 없습니다.
- 원본 지문 특징과 구현 일치를 검사하지만, 기존 제출 패키지 전체를 비트 단위로
  재현한 것은 아닙니다. 대조군은 기존 구성의 동일 분할 재학습입니다.
- 신뢰구간의 단위는 온실·연속 5개 관측일 묶음입니다. 숨겨진 실제 날짜 및
  출처 의존성을 완전히 제거할 수는 없습니다.

`manifest.json`: 입력/코드/계획 해시 및 라이브러리 버전

`checks.json`: 특징 인과성·결측·행 순서·기존 지문 일치 검사

`search_history.json`: 순차 선택과 보상

`selection_lock.json`: 확인 전에 잠근 후보

`result.json`: 채택 여부, 확인 RMSE, 보정 신뢰구간, 부분집단 결과

`confirmation_8.csv`, `confirmation_9.csv`: 공개 정답 검증 예측(제출 파일 아님)
