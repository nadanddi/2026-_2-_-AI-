# EC 보상 기반 탐색 1차 결과

2026-09-27. **실행 완료, 개선 입증 실패, 새 후보 채택 없음.**

## 실제 수행한 학습

단일 상태 밴딧으로 학습 설정을 선택하고, 기존 3회차 EC 구성 대비 검증
RMSE 감소율을 보상으로 사용했다. 온실을 조작하는 강화학습이나 PPO/DQN
학습은 아니다. UCB 방식의 보상 기반 실험 선택기를 실제 실행했다.

온도는 이번 실험에서 학습하지 않았다. 원래 프로젝트는 읽기만 했고,
현재 작업 사본에 새 코드와 결과를 저장했다. 대회 플랫폼 제출은 하지 않았다.

공개 EC 정답 9,600행에서 1,920행을 확인용으로 지정했다. 확인일과 앞뒤
하루를 제외한 7,344행에서 탐색했으며, 각 내부 폴드의 검증일과 앞뒤 하루도
학습에서 제외했다. 각 기준 모델은 해당 학습 분할에서 새로 학습했다.

## 결과

| 후보 | 평가한 폴드·시드 조합 수 | RMSE 변화율 평균 | 개선 조합 | 판정 |
|---|---:|---:|---:|---|
| 트리 말단 최소 표본 수 1 → 4 | 8 | **+0.37%** | 4/8 | 탈락 |
| 온실·일 단위 재표집, 8개 숲 평균 | 2 | +4.20% | 0/2 | 탐색에서 낮은 보상 |
| Tweedie 구성원 → 지문 포함 L2 회귀 | 2 | +6.70% | 0/2 | 탐색에서 낮은 보상 |

양수는 악화다. 평균은 각 조합에서 동일 시드·동일 분할의 대조군과 비교한
상대 변화율의 산술평균이다. 전체 자료의 통합 RMSE나 대회 점수가 아니다.
밴딧이 보상을 보고 계산을 배분했으므로 후보별 평가 횟수는 다르다.
후보 간 효과 크기를 같은 정밀도로 추정한 표가 아니며, 두 번만 평가한
방법의 모든 변형이 무효라고 결론 내릴 수는 없다.

첫 번째 후보의 첫 구간에서는 시드 7에서 0.150758 → 0.150532로 소폭 개선됐지만,
시드 101에서는 0.150542 → 0.152239로 악화됐다. 점수가 좋아진 경우만
골랐다면 개선으로 오해할 수 있는 사례다.

정해둔 12회 탐색을 완료하고 평균 보상이 가장 높은 첫 번째 후보를 고정했다.
해당 후보는 이미 4개 폴드 × 2개 시드 모두 평가됐고, 평균 보상이 음수였다.
사전 기준에 따라 **확인용 정답으로 모델을 채점하지 않고 종료했다.**
확인 점수·확인 신뢰구간은 생성하지 않았으며, 기존 모델을 대체하지 않았다.

## 누출 및 재현 검사

- test_X를 읽지 않고 train_X만으로 특징을 생성했다.
- 같은 온실의 미래 입력을 바꾼 6개 절단점에서 이전 특징이 동일했다.
- 다른 온실 입력을 바꾼 6개 절단점에서도 대상 온실의 이전 특징이 동일했다.
- 입력 행 순서를 바꿔도 정렬 후 특징이 동일했다.
- 0시 값을 결측으로 만들었을 때 이후 값으로 역방향 채우지 않았다.
- 기존 `fp_features.py`의 지문 특징과 새 구현의 값이 일치했다.
- 탐색/확인 행 격리 및 학습/검증 행 비중첩을 검사했다.
- 12회 기록에 동일 후보·동일 폴드·동일 시드를 중복 보상으로 센 경우가 없다.
- Python 3.12.14, NumPy 2.5.3, scikit-learn 1.9.1, LightGBM 4.7.0.
- 실행 시작 전에 계획·실행 코드·입력 CSV의 SHA-256을 기록했다.

이 검사는 특징과 이번 탐색 파이프라인에 대한 검사다. 최종 제출 모델의
재학습부터 추론까지 끝단 검사를 완료했다는 의미는 아니다. 채택 후보가
없어 제출 모델이나 최종 답안을 만들지 않았다.

## 해석의 한계와 다음 기준

이 결과는 **시험한 세 설정에서 안정적인 이득을 찾지 못했다**는 뜻이다.
강화학습 전체가 불가능하다거나 이 데이터의 최적 성능에 도달했다는 뜻은 아니다.
이번 대조군에는 TabPFN을 넣지 않았으므로 최신 혼합 후보를 이겼다는 주장은 없다.

확인용 자료는 이번 선택기에서는 미사용이지만, 기존 연구는 공개 자료 전체를
이미 활용했다. 따라서 완전히 새로운 독립 평가 자료라고 부를 수 없다.
숨겨진 실제 날짜·온실 출처로 인한 의존성도 남는다.

다음 실험은 이번 결과에 맞춰 시드·분할·판정 기준을 바꿔 재도전하는 대신,
새 가설과 고정된 예산을 먼저 기록해야 한다. 이번 실행에서 열지 않은 확인
점수는 새 가설을 잠근 후에만 사용한다. 채택 전에는 전체 DIAG10과 A/B,
최신 TabPFN 포함 후보 비교, 다중 비교 보정, 끝단 인과성·재현 검사가 필요하다.
