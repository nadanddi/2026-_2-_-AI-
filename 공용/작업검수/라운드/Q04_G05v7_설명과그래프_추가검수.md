## 1. [필수 A01] 8장에 ‘사전 기준’의 내용·이유·예외를 본편 정보로 제시

### 확인한 현재 상태

- 화면 표에는 ‘사전 기준’ 열과 통과·근소 미달·미달·공개 점수 비교만 있다.
- 표 캡션은 “미리 정한 기준 충족”, “기준은 노트”라고 설명한다. **무슨 기준인지에 대한 답을 다시 노트로 미룬다.**
- 외부 대본 §8에는 “모든 경우에 같은 방향”, “우연일 가능성이 아주 작아야”라고 되어 있다. 반복 학습·여러 조건을 비교한다는 취지는 있지만, 실제 문턱과 왜 이 기준을 만들었는지는 충분하지 않다.
- 상세 노트에는 “모든 시드·검증기 같은 방향 + 블록 부트스트랩 P<.025”가 있다. 따라서 근거가 없는 것이 아니라, 청자가 접하는 경로에 빠진 것이다.

### 실제 기준과 근거

이 장에서 요약하는 기본 기준은 실행 전에 고정한 **여러 검증 방식·반복 학습에서 개선 방향이 일치하고, 기록 묶음 재추출로 측정한 악화·동률 비중이 .025 미만인 것**이다. 개별 실험의 적용 범위·예외 경로는 실행 전 코드에 고정한 해당 규칙으로 추적해야 한다. 전체 연구 기간에 모든 부품이 하나의 동일한 문턱만으로 선정됐다고 확대하면 안 된다.

기준을 만든 이유는 사용자 요구인 **한 번의 운 좋은 결과와 반복 가능한 개선의 구분**이다. `공용/ai-memory/skill-not-luck.md`는 학습 난수만 바꿔도 개선이 악화로 뒤집혔던 사례와 단일 공개 점수의 불안정성을 계기로 기록한다. 이는 재현성과 불확실성을 점검하려는 팀의 사전 의사결정 규칙이다. **.025가 농업에서 보편적으로 옳다고 입증된 문턱은 아니다.** 공개 점수 사례 네 건이 이 기준의 일반적인 예측력을 증명한 것도 아니다.

근거: 정형 README ‘⑤ 채택 근거’ 207~231줄, 카탈로그7.037~7.039, 위 메모리의 규칙 변경 이력, 개별 실험 머리말.

### 어디를 어떻게 보완할 것인가

1. **표 위에 기준을 두 줄로 먼저 제시한다.** 예:
   - “검증 방식을 바꾸고 반복 학습해도 개선 방향이 같아야 채택”
   - “기록 묶음을 다시 뽑아 비교한 악화·동률 비중 < 2.5%”
2. 대사는 “한 번 잘 나온 결과를 채택하지 않으려고, 실행 전에 이 규칙을 정했습니다”로 이유를 연결한다. 부트스트랩 비중을 실제 악화의 사후 확률이나 ‘개선이 참일 확률97.5%’로 말하지 않는다.
3. **공개 점수로 선택한 예외는 작은 각주가 아니라 표의 별도 선택 경로로 표시한다.** 예: ‘내부 검증 통과’와 ‘공개 점수 비교로 유지’. 최종 구성 전체가 엄격 기준을 통과했다는 인상을 피한다.
4. 제목은 결과 네 건의 범위를 드러내도록 줄인다. 예: “**내부 검증과 공개 점수를 함께 확인했다**”. 통과 사례2건·미달 사례2건은 ‘공개 점수에서 같은 방향을 보인 사례’로 설명하고, 통과하지 않으면 언제나 나빠진다는 규칙처럼 말하지 않는다. 실제로17·23·24회차는 기준 미충족·다른 선택 경로여도 공개 점수가 좋아졌다.
5. 선택 경로 설명과 사례를 추가하는 대신 기존 긴 제목·중복 캡션을 줄인다. 모든 정보를 각주에 더 붙이는 방식으로 처리하지 않는다.

## 2. [필수 A02] 6장 ‘세 모델’의 정체와 선정 근거를 먼저 설명

### 무엇이 빠졌는가

현재 1단계는 “세 모델 섞기 / 8℃ 이하는 TabPFN 제외”다. 청자는 세 모델 중 하나의 이름만 보게 된다. 왜 세 개이며 무엇이 다른지, 왜 TabPFN만 제외하는지를 알 수 없다. 외부 대본도 “세 모델을 섞어”라고만 말하므로 빈칸이 그대로 남는다.

### 확인한 세 구성원

| 실제 이름 | 처음 듣는 청자에게 제시할 설명 | 근거 |
|---|---|---|
| BASE | 물리식에 학습한 오차 보정을 더한 모델 | 정형 README 온도 기본 모델 설명, 6장 상세 노트 |
| CODEX | 다른 입력·오차 특징을 쓰는 물리식 기반 보정 모델 | 같은 근거. Ridge 물리 기준선+LightGBM 잔차, 자정 재시작 잔차 특징 |
| TabPFN | 표 자료를 예측하도록 미리 학습된 모델 | 같은 근거. 학습 행2,000개를 참고 예시로 넣고, 참고 표본8개 예측을 평균 |

BASE·CODEX를 모두 이름만 바꿔 ‘AI모델1·2’라고 적는 것도 충분하지 않다. 둘 다 물리식과 학습 보정을 사용하는 만큼 **구분되는 입력·오차 특징을 한마디로 설명**해야 한다. BASE의 상세 구성에는 LightGBM 잔차와 Ridge·Nystroem 등이 포함되므로 하나의 단일 선형모델이라고 축약하지 않는다. CODEX는 이 발표에서 개발 도구가 아니라 구성원의 내부 이름임도 혼동하지 않게 한다.

### 선정 근거의 범위

- 혼합 비중·저온 조건을 바꾼 검증 기록은 카탈로그6.60~6.70에 있다. 초기 혼합의 재확인, 추운 구간의 TabPFN 악화, 다른 비중의 비교를 설명할 근거는 있다.
- **모델이 서로 다르므로 섞으면 반드시 좋다**, **세 개가 최적이다**라는 결론을 이 기록만으로 단정하면 안 된다. 다양성은 설계 동기이며 성능 근거는 비교 실험이다.
- 세 모델 각각을 빼 본 최종 구성 비교가 제시되지 않았다면, ‘최종 구성에서 세 구성원 각각의 독립 기여를 입증했다’고 말하지 않는다. 기존 비교가 있으면 해당 결과를 연결하고, 없으면 확인 범위를 한정한다. 이번 보완을 위해 새 실험을 반드시 요구하는 것은 아니다.

### 어디를 어떻게 보완할 것인가

1. 1단계에 세 구성원의 **기능 이름**을 짧게 나열하고, 대본에 “물리식 기반 두 모델과 사전학습 표 모델의 예측을 섞었습니다”를 넣는다.
2. 선택 근거는 “학습 자료에서 비중과 저온 조건을 바꿔 비교했습니다”로 연결한다. 다만 다음 A03의 공개 점수 선택 예외를 같이 밝힌다.
3. 저온 제외는 “추운 기록에서 TabPFN의 오차가 커져, 8℃ 이하에서는 제외했습니다”처럼 관측→결정 순서로 말한다. **8℃는 실내 공기온도 기준**이다.
4. 공간이 부족하면 원리를 다루는6장에는 모델 정체와 저온 동작을 남기고, 선택 근거 요약은8장의 검증 설명과 연결한다. 각주에 세 이름만 추가하고 끝내지 않는다.

## 3. [필수 A03] 가중치를 전부 사전 기준으로 정한 것처럼 보이지 않게 설명

6장 상세 노트와 정형 README는 다음 선택 경위를 구분한다.

| 실내 공기온도 | BASE | CODEX | TabPFN |
|---|---:|---:|---:|
| 10℃ 이상 | 40% | 20% | 40% |
| 8℃ 이하 | 40% | 60% | 0% |

8~10℃는 두 상태 사이에서 비중이 연속적으로 바뀐다. 실내온도 결측 시의 세부 처리는 노트에 유지한다.

- 초기 비중과 저온 조정은 비교·재확인 기록이 있다. 저온 구간의 단독 TabPFN 오차가 큰 관측이 제외의 근거다.
- **따뜻한 구간의 TabPFN 최종40%는 내부 검증이 엇갈렸고, 30%안과40%안의 공개 점수 비교로 선택했다.** 카탈로그6.198, 정형 README218줄, 6장 노트와 부록A7에 명시돼 있다.
- 따라서 “모든 가중치는 실행 전 사전 기준을 통과해 결정했다”거나 “최적 가중치40%를 입증했다”고 표현하면 사실과 다르다.

**보완 요청:** 본편에서 최소한 “저온 비중은 검증 결과로 조정했고, 따뜻할 때의 최종40%는 내부 검증이 엇갈려 공개 점수 비교로 골랐습니다”를 전달한다. 두 온도 구간의 비중표는 화면 또는 바로 확인할 수 있는 근거 표로 제시한다. 최종 비중의 선택 경로를 부록 링크만으로 감추지 않는다.

## 4. [필수 A04] 그림3·4의 축 이름을 실제 축에 배치

PowerPoint로 다시 렌더했던6·8장 PNG를 재확인했다. **잘림은 없지만, 축 숫자보다 의미 설명이 멀리 떨어져 있다.** Q03의 ‘깨짐0’은 이 전달력 문제가 없다는 뜻이 아니다.

### 6장 그림3

현재 가로축은0·3·6… 시각 숫자뿐이고 세로축은0.0~0.8이다. 오른쪽 긴 설명에 “가로축: 오늘의 시각”, “세로축: 반영 비율”을 써 두었다.

**요청 배치와 표기:**

- 가로축 바로 아래: **오늘 시각 · 시**
- 세로축 바로 옆: **어제 실측 차이 반영률 · %**
- 세로 눈금은0·20·40·60·80으로 표시하면 더 직관적이다. 이 경우 원래0.2를20%로 **표시 변환**해야 한다. 데이터0.2에 % 기호만 붙여0.2%로 쓰면 오류다. 0~1 눈금을 유지한다면 축 이름은 ‘반영 비율’로 쓰고 단위 없는 비율임을 분명히 한다.
- 짧은 제목: **어제 실측의 보정 비중은 새벽에 크다**
- 오른쪽의 축 설명 문단은 제거하고, 해석 한 문장만 남긴다. 예: “새벽에는 어제 상태를 더 반영한다.”
- 이 그림은 어제 실측 보정계수 β의 예다. 기본 모델의 혼합 비중이나 예측 정확도라고 읽히지 않게 대본에서 구분한다. 상수 보정·절단이 포함된 정확한 식은 노트에 둔다.

### 8장 그림4

현재 가로축17·19·20·21·22·23·24, 세로축.44~.52다. 단위와 방향은 아래 캡션 “회차별 온도 RMSE(공개 점수, 낮을수록 좋음)”에 들어 있다.

**요청 배치와 표기:**

- 가로축 바로 아래: **플랫폼 제출 회차**
- 세로축 바로 옆: **배지온도 오차 · ℃**
- 차트 제목: **공개 채점 오차 — 낮을수록 좋음**. RMSE라는 정확한 지표명은 축이나 짧은 보조 표기에 한 번 남긴다.
- 축 제목·눈금·점의 수치가 본문과 비교해 지나치게 작지 않도록 키운다. 가로축 공간은 긴 캡션을 줄여 확보한다.
- 제출 회차는 날짜 간격이 아니다. 17→19 같은 간격을 달력상의 시간 흐름처럼 해석시키지 않는다.
- 그래프에는23회차가 있으나 오른쪽 표에는 없다. 선택 경로를 비교하려면23회차를 표에도 넣거나 양쪽에 같은 사례를 보여 줘야 한다.

## 5. [필수 A05] 9장 세로축의 단위는 유지하되, 무엇의 %인지 직접 표시

**검산 결과: 온도와 EC가 모두 %인 것은 맞다.** 그래프는 온도·EC의 원래 RMSE가 아니라, 어제 이력 보정을 껐을 때 **각 대상의 현행 RMSE 대비 증가율**이다.

`오차 증가율 = 100 × (이력 보정 끈 RMSE − 현행 RMSE) / 현행 RMSE`

| 사례 | 원래 RMSE의 단위 | 현행 → 이력 보정 끔 | 증가율 |
|---|---|---|---:|
| 온도·추운10℃ | ℃ | .7599 → .8387 | 약10.4% |
| EC·기록 묶음 가림 | dS/m | .2135 → .2787 | 약30.5% |

계산에서 분자와 분모의 ℃ 또는 dS/m가 약분되므로 양쪽 세로축은 같은 %를 쓸 수 있다. 실제 차트도0~35의 같은 범위·눈금10을 사용하고 있어 상대 증가율을 나란히 보는 방식으로 문제가 없다. **온도10.4℃, EC30.5dS/m를 뜻하지 않는다.** 10.4%와30.5%를 같은 절대 오차나 같은 농업적 피해 크기로 해석할 수도 없다. 좌우는 검증 방식도 완전히 같지 않다.

**요청:**

- 두 그래프 세로축 옆에 각각 **현행 대비 오차 증가율 · %**를 직접 표시한다.
- 가로축 아래에는 **검증 방식**을 두고, 범주 이름을 짧게 쓴다. ‘2차’의 뜻은 처음 등장할 때 대사에서 풀어 준다.
- 짧은 제목 예: **어제 이력 보정을 끄면 오차가 증가한다**. 아래 해석은 “온도3~10%, EC8~31% 증가” 한 줄이면 된다.
- 공통 축이라고 숨기지 말고 각 그래프에서 단위를 바로 읽을 수 있게 한다. 단위가 다를 것이라는 이유로 각각℃·dS/m로 바꾸면 현재 막대값의 의미가 틀어진다. 절대 RMSE를 보여 주려면 데이터와 눈금을 함께 바꿔야 하며 이번 검수는 그 변경을 요구하지 않는다.
- ‘높을수록 어제가 중요’보다는 **높을수록 보정을 끈 손해가 큼**이 이 실험에 더 직접적이다. 다른 모든 단서 중 어제가 가장 중요하다는 순위는 이 비교만으로 증명하지 않는다.

## 6. [필수 A06] 본문 주석을 축·핵심 조건·출처로 나누고 문장량을 줄일 것

현재 주석에는 축 정의, 숫자의 분모, 적용 조건, 예외, 출처, 코드명 대응이 한꺼번에 들어간다. 괄호를 길게 달아 정확성을 보충하다 보니 청자는 그림보다 해설 문단부터 읽게 된다. **설명을 빼는 것과 필수 설명을 노트로 숨기는 것은 다르다.** 아래처럼 각 정보가 쓰이는 자리에 놓아야 한다.

1. **무엇을 그렸는지:** 그림 위 짧은 제목.
2. **단위와 수치 의미:** 축 옆·아래에 직접 표시.
3. **판단에 필수인 조건:** 표의 열 이름이나 짧은 독립 문장. 예: ‘후보 선택에 사용’, ‘새 농장 성능 미측정’, ‘EC에는 예측 이어받기 없음’.
4. **긴 기술 정의·코드 대응·상세 출처:** 발표자 노트나 부록. 화면 출처는 파일명과 항목 번호 정도로 짧게 유지.

장별 요청은 다음과 같다.

| 장 | 현재 부담 | 보완 방향 |
|---|---|---|
| 5 | 지표 설명·다른 온실 역할·하단 결론 동시 제시 | Q03 F06대로 상세 역할 표를 옮기고 진단→방법 한 흐름 유지 |
| 6 | 온도·EC 예외가 긴 괄호, 그림3 축 설명이 오른쪽 문단 | 온도 흐름 제목 명시. EC는 ‘기본 예측→하루 수준 보정→어제 실측 보정’ 별도 한 줄. 축 정보는 실제 축으로 이동 |
| 8 | ‘통과’ 정의·공개 점수 선택·출처·기준 링크가 아래에 집중 | 기준을 표 위에 올리고 선택 경로를 열로 구분. 긴 괄호·중복 캡션 제거 |
| 9 | 증가율·가로축·현장 조건이 아래 문장에 집중 | 축 이름 직접 표기. 현장 조건은 온도/EC 경로 구분해서 짧게 제시 |
| 11 | 제작 도구·학습 장수·원천 수의 의미 혼동 가능 | 제작 흐름은 동사로, 기본 학습 수는 ‘실제2,467 / 가짜7,124’ 독립 표기 |
| 13 | 학습·선택 사용·농장 겹침·참고 묶음 사유가 긴 캡션 하나 | ‘모델 학습 미사용 / 후보 선택 사용 / 새 농장 미검증’을 짧은 별도 항목으로 제시. 참고 묶음 제외 이유는 해당 행 가까이에 배치 |
| 14 | 방향·시험 조건·처리 방식이 캡션에 혼재 | 각 차트 제목에서 ‘균형 정확도·높을수록 좋음’과 ‘진짜 사진 오탐률·낮을수록 좋음’을 바로 읽게 함 |

예를 들어 “사진은 학습에 안 썼지만 후보 선택에 썼고, 농장·촬영 묶음은 학습과 겹침(새 농장 성능 아님)”을 작은 한 문장으로 두기보다 **학습 미사용 / 후보 선택 사용 / 새 농장 미검증**을 해당 표 가까이에 분리하는 편이 전달하기 쉽다. 다만 농장·촬영 묶음 겹침이라는 실제 조건은 노트에 보존하고, 필요하면 대사에서 한 번 명확히 말한다.

보완의 완료 조건은 **괄호를 없앤 글자 수 자체가 아니라, 그림과 표를 본 자리에서 뜻·단위·적용 범위를 알 수 있는가**다. 긴 문장을 작은 글씨로 다시 배치하는 것으로 완료 처리하지 않는다.
