# Q03 G05v7 검수

판정: **수정요청**

2026-11-03 · 연구실 코덱스 · 검수만 수행. 원본 PPTX·생성기·대본·실험 코드·결과·카탈로그는 수정하지 않았다. 아래 장 번호는 PPT의 실제 순번이다. 예: 5장 = 1.2, 9장 = 1.6, 13장 = 2.3.

**요약:** Q02 24건은 화면과 외부 대본 v3 기준으로 **반영 20건 / 일부 4건 / 미반영 0건**이다. 그러나 PPT 내부의 발표 대사가 v3와 다르고, EC 처리·형식 조건·보정 허용 조건에 사실과 다른 축약이 남았다. PowerPoint 재렌더에서 본문 1~16장 깨짐은 없었다. ABL3 조건 2·3과 ABL1의 비교값 및 제시한 비율 계산은 맞지만, ‘링커 오류의 손해’라는 해석 범위는 좁혀야 한다.

## 1. 수정 요청

### F01 [필수] PPT의 발표 대사와 외부 대본 v3를 일치시킬 것

- **어디:** G05v7 본문 1~16장 발표자 노트의 `[말할 것]`; 생성기 `build_g05_v7.js`의 해당 노트 작성 부분. 기준은 `발표대본_G05v7_v3_2026-11-03.md` 각 장 대사.
- **문제:** 노트 앞에 새 이름 대응표를 추가했지만 실제 읽을 대사는 이전 내용이다. 6장에는 “링커가 찾은”, 8장에는 EXT10·시드·P 등 이전 전문 용어, 13장에는 “봉인 묶음”, “R3~R5”가 남아 있다. 7장의 “남은 한계는 계절 지표 하나”는 외부 대본의 “실제 달력으로 바꾼 성능은 아직 재지 않았습니다”와 범위도 다르다. 3장의 외부 대본은 용어 정의인데 PPT 대사는 발표 순서 설명이다. 16장도 외부 대본의 결과·미실시 검증 정리가 반영되지 않았다.
- **어떻게:** 본문 각 장의 `[말할 것]`을 최종 대본과 맞추고, 아래의 상세 근거·코드명 대응표는 유지한다. F02~F05를 먼저 반영한 뒤 두 대사 경로를 맞출 것. 발표자 화면만 보며 읽어도 같은 발표가 되어야 한다.

### F02 [필수] ‘실측이 없으면 예측 이어받기’는 온도에 한정할 것

- **어디:** 9장 하단 “기록이 없으면 어제 예측 이어받기”, 외부 대본 §6·§9, 질의응답 J01 등 공통 처리처럼 설명한 부분.
- **문제:** 6장 캡션은 EC에 “이어받기·추운 시간 보정 없음”이라고 정확히 적었지만, 9장 화면과 대사는 온도·EC 모두에 이어받기가 있는 것처럼 들린다. 실제 EC는 기본 예측+하루 수준 보정+조건부 어제 실측 보정이며 예측 사슬이 없다. 온도 역시 사용할 전날 예측 이력이 있어야 이어받는다.
- **근거:** 정형 README 용어표 29~35줄, 온도·EC 구성 설명, 특히 137~138줄. ABL3 `ec_plan` 106~113줄도 가려진 전날이면 EC 앵커를 적용하지 않는다.
- **어떻게:** 예: “어제 실측 보정은 전날 센서 기록이 있을 때만 쓴다. **온도는 사용할 전날 예측이 있으면 줄여 이어받고, EC는 실측 보정 없이 기본 예측과 하루 수준 보정을 쓴다.**” §6 첫머리에도 “온도 모델은 세 단계”라고 한정한다. 이 구분을 리허설 시간이 남을 때만 넣는 선택 문장에서 필수 대사로 올릴 것.

### F03 [필수] 저장 형식 조건을 ‘JPEG 품질 92만’으로 정의하지 말 것

- **어디:** 12장 점선 상자 “저장 형식 조건: JPEG 품질 92일 때만 일부 판별기”.
- **문제:** 현재 표기는 품질 92이면 모두 해당하는 조건으로 읽힌다. 실제 조건은 JPEG·4:2:0·지정 양자화표의 일치다. 이전 화면의 4:2:0을 지우면서 조건의 의미가 넓어졌다. 상세 노트는 정확하다.
- **근거:** 이미지 README 25·97줄, 12장 상세 노트의 “PIL quality=92 양자화표와 완전히 같을 때”.
- **어떻게:** 쉬운 화면 표현은 “**지정 JPEG 저장 설정과 일치할 때만 일부 판별기 적용**”으로 바꾸고, 노트에 JPEG·색 정보 축소 방식 4:2:0·품질92 양자화표 완전 일치 조건을 유지한다. 품질92를 화면에 남기려면 다른 조건도 함께 적을 것.

### F04 [필수] 실측 보정의 허용 조건과 91% 수치의 범위를 바로잡을 것

- **어디:** 대본 질의응답 ‘어제가 맞다는 걸 어떻게 아나?’의 “확신이 0.8 이상일 때만 실측 보정을 씁니다”.
- **문제:** 최종 구성은 p≥0.8 경로 외에 TAG2의 .5≤p<.8 확장도 사용한다. 91%는 높은 확신 구간의 확인값이지 확장된 전체 보정의 정확도가 아니다.
- **근거:** 정형 README 113줄의 TAG2 조건, 138줄 “p≥.8 + TAG2”, 222·231줄의 채택 경위. 세부 조건은 .5≤p<.8, 자정 실내 변화 제한, 외기만 또는 실내만 본 별도 판단과 선택한 어제의 일치다.
- **어떻게:** “기본 경로는 확신 0.8 이상이며, 그 구간의 확인 정확도는 약 91%입니다. 일부 중간 확신 기록도 별도 일치 조건을 만족하면 보정합니다.”처럼 답한다. 상세 조건은 노트로 연결한다. **91%를 전체 연결·전체 보정 정확도로 확대하지 않는다.**

### F05 [필수] ABL3를 ‘알려진 짝의 오라클 교체 진단’으로 한정하고 비율의 정의를 밝힐 것

- **어디:** 9장 ABL3 추가 노트, 대본 질의응답 `(새)`, 카탈로그 7.076의 해석 문구, 향후 실험 설명 문서. 실행 전 고정한 기존 코드·로그는 보존하고 설명 정정으로 처리할 것.
- **문제:** 계산 자체는 맞다. 그러나 조건 1은 전체 기록의 실제 날짜·동을 확보한 실험이 아니다. 알려진 190쌍 안에서 교체하고, 밖에서는 현행 연결을 유지한다. EC는 전날 선택뿐 아니라 보정 강도의 확신 q를 1로 바꾼다. 온도는 ID를 넘는 사슬을 허용하고 연결 적용·미적용 대상도 달라진다. 따라서 차이 전체를 순수한 ‘링커 오류의 손해’로 분리했다고 볼 수 없다.
- **어떻게:** 아래 내용을 상세 노트에 필수로 넣고, 짧은 답에서도 첫째·둘째 의미는 전달할 것.
  1. “정답 이어짐으로 확인한 짝만 오라클로 바꾼 **진단용 비교**이며, 나머지는 현행 연결을 유지했습니다. 실제 날짜·동을 넣은 최종 현장 성능은 측정하지 않았습니다.”
  2. “연결 상대와 보정 적용 범위·일부 보정 강도가 함께 바뀌므로 차이를 연결 오류만의 손해로 분리할 수 없습니다.”
  3. “0.8~2.2%, 1.3~6.7%는 **현행 C2 RMSE 대비 O1 RMSE 감소율**입니다. 62~95%는 **2차 행에서 ‘어제 없음’ 대비 RMSE 감소 폭의 비**이며, 연결 정답률이나 오차 전체 중 설명 비중이 아닙니다.”
  4. 정답 0·1시로 짝을 고른 조건1의 낙관 편향, 링커 전체 적합으로 조건2도 낙관적일 가능성을 함께 적을 것. 두 편향이 존재하므로 차이를 엄밀한 상한·하한으로 보장할 수 없다.
  5. EC의 2차 블록 부트스트랩 값은 .0597이므로 사전 채택 문턱 .025를 통과한 개선이라고 말하지 않는다. 서술용 평균 비교라는 현재 성격을 유지한다.
- **권고 짧은 답:** “정답 이어짐으로 확인한 일부 짝을 교체하는 진단에서는 현행 대비 RMSE가 온도 0.8~2.2%, EC 1.3~6.7% 낮았습니다. 다만 연결과 보정 조건을 함께 바꾼 비교이고, 정답으로 짝을 골라 낙관적일 수 있습니다. 실제 날짜·동을 넣은 현장 성능은 아직 재지 않았습니다.” 62~95%는 추가 질문이 있을 때 정의와 함께 답해도 된다.

### F06 [필수] 5장(1.2)의 본문 글 양을 줄일 것

- **어디:** 5장 왼쪽 진단 표+오른쪽 온실 역할 표+하단 결론.
- **문제:** 재검사 본문 글자 수 180자. 기존 G01 완료 기준의 “본문 대략 120자 이하”보다 약 50% 많다. 넘침은 없지만, 45초 동안 설명하는 왼쪽 세 지표와 말하지 않는 오른쪽 표가 경쟁한다.
- **어떻게:** 대본에서도 말하지 않는 오른쪽 온실 상세 표를 부록·노트로 옮기고, 화면에는 “예측 대상 두 ID / 다른 49곳은 확인용” 정도만 남긴다. 또는 같은 정보를 더 짧게 묶어 120자 안팎으로 줄인다. 숫자의 분모와 ‘오늘 정답은 쓰지 않음’은 보존할 것. 작은 글자로 줄이는 방식은 피한다.

### 권장 보완

- **R01:** 4장 제목을 “**두 제공 ID 사이에서도 하루 기록의 연속성이 관측된다**”처럼 관측 사실 중심으로 바꾸면 좋다. 외부 대본은 같은 동이라는 해석과 원인 미확인을 구분했지만, 화면 제목 “하루가 두 온실 ID를 넘나들며 이어진다”는 실제 소속을 확정한 듯 읽힐 여지가 있다.
- **R02:** 6장 첫 TabPFN을 “표 자료를 예측하는 사전학습 모델 TabPFN” 정도로 소개한다. ‘2차 구간’은 처음 사용할 때 평가와 같은 기록 번호 구간이라는 뜻을 풀어 주고, 실제 달력상 다음 시기라고 설명하지 않는다. 질의응답 J07의 rc도 “원본과 거의 같다고 확인한 사진”으로 먼저 설명한다.
- **R03:** 5장 0.49는 “제곱오차 중 하루 평균 어긋남의 몫”으로 정확히 지칭하면 RMSE 49% 감소나 정확도49%와 혼동이 줄어든다. 13장에서는 자체 균형 정확도와 운영진 정답률이 지표·자료가 달라 직접 비교값이 아니라는 한마디가 유용하다.
- **R04:** 4장·질의응답의 0.015℃·EC0 예시는 원시 23시값과 0시값의 단순 차이처럼 읽히지 않게 “양쪽 기울기로 외삽한 자정 경계 차이”라고 명시한다. 관측값과 경계 연속성 계산을 구분할 것.
- **R05:** ABL3 `oracle_temp`의 반환 통계 `same/diff/none_before`는 초기화 후 갱신되지 않아 모두0이다. 현재 실험 RMSE에는 영향이 없지만 연결 변화의 증거로 쓰면 안 된다. 현재 로그는 보존하고, 재실행이 필요하다면 새 버전에서 채우거나 미집계로 표시한다. 별도의 `plan_vs_truth` 출력과 혼동하지 않는다.

## 4. C — 대본 정합성과 10분 가능성

외부 대본 본편은 화면의 설명 순서를 대체로 따른다. 정의가 생긴3장, 하루 오차를 예로 푸는5장, 후보 선택과 새 농장 한계를 말하는13장, 결과와 남은 검증을 말하는16장은 이전 판보다 명확하다. 주요 불일치는 F01·F02·F04다. ABL3는 질의응답이므로 본편 길이에 포함하지 않았다.

### 길이 확인

- 본편1~16의 실제 대사에서 제목·화면 지시·시간 조절 문장·질의응답을 제외해 센 한글 음절은 **1,909개**다. 표기한 약1,910과 일치한다.
- 장별 배정 시간 합계는 **545초=9분5초**, 넘김15초를 더하면9분20초다. 따라서 문서의 시간표 산술은 맞다.
- 다만 이 시간은 낭독 실측이 아니다. 숫자·영어·단위는 한글 음절 계산에 충분히 반영되지 않고, 그래프를 가리키는 정지와 호흡도 필요하다. **10분 이내는 가능성이 있지만, 현재 자료만으로 확정할 수 없다.** 9분~9분30초 추정은 리허설에서 확인할 가정이다.
- 실제 화면 넘김까지 포함한 리허설에서9분20~30초 이내인지 확인하고, 30~40초 이상 여유를 확보하는 편이 좋다. F02의 EC 구분을 추가한 최종 대본으로 잴 것.

### 줄일 우선순위

1. **5장 오른쪽 표의 화면 정보량부터 줄인다.** 대사에서 말하지 않으므로 발표 시간을 늘리지 않으면서 읽기 부담을 줄일 수 있다.
2. 8장 채택 기준 설명의 중복을 “정답을 숨기는 방식과 학습을 바꿔 반복했고, 사전 기준으로 채택했습니다”처럼 압축할 수 있다. 공개 점수 비교 선택이라는 예외는 화면·노트에 유지한다.
3. 12장 “놓치기 쉬운 유형은…” 한 문장은 상자의 존재를 가리키며 짧게 합칠 수 있다. 저장 조건 불충족 시 생략한다는 설명은 남긴다.
4. 16장의 의지 표현을 줄이고, 확인한 결과와 미실시 검증을 남긴다.

현재 ‘뺄 문장’ 목록의 **4장 하루 기록 정의**와 **6장 그래프 뜻**은 Q02 핵심 이해를 해결한 문장이다. 이 둘부터 삭제하는 것은 권하지 않는다. EC에 사슬이 없다는 설명도 시간이 남을 때만 추가하는 선택 항목으로 두지 않는다.

### 5.4 2차 행 수치 재계산

아래 C3=어제 이력 보정 없음, C2=현행, O1=자정 제한을 유지한 알려진 짝 교체다. RMSE는 표시만 소수4자리로 반올림했고, 비율은 CSV 원정밀도로 계산했다.

| 대상·검증 | C3 | C2 | O1 | 현행 대비 O1 감소율 | RMSE 감소 폭 확보 비율 |
|---|---:|---:|---:|---:|---:|
| 온도·추운10℃ | .8387 | .7599 | .7433 | 2.189% | 82.557% |
| 온도·추운12℃ | .9059 | .8791 | .8717 | .843% | 78.350% |
| 온도·무작위 | .7388 | .7146 | .7014 | 1.840% | 64.825% |
| EC·무작위 | .2522 | .2329 | .2299 | 1.277% | 86.669% |
| EC·묶음 가림 | .2787 | .2135 | .2100 | 1.626% | 94.944% |
| EC·한 기록씩 가림 | .1913 | .1723 | .1608 | 6.655% | 62.343% |

- 감소율 = `100 × (C2−O1) / C2`。반올림하면 온도 **0.8~2.2%**, EC **1.3~6.7%**로 제시값이 맞다.
- 확보 비율 = `100 × (C3−C2) / (C3−O1)`。전체 범위 **62.3~94.9% → 약62~95%**로 제시값이 맞다.
- 이는 **RMSE 감소 폭**의 비다. 제곱오차 감소 폭으로 계산하면 다른 값이 되므로 지표 이름을 생략하면 안 된다.
- ‘복원 손해’를 오라클 O1 대비 현행 증가율 `(C2−O1)/O1`로 정의하면 EC 최대는 **7.129%**다. 현재6.7%가 틀린 것이 아니라 **분모가 C2인 감소율**이라는 뜻을 밝혀야 한다.
- 이 범위를 cert_p2에 그대로 적용하면 안 된다. 예를 들어 EC cert_p2는 무작위 가림에서 C3 .2388보다 C2 .2455가, 한 기록씩 가림에서 C3 .1689보다 C2 .1939가 나쁘다. ‘알려진 짝에서 언제나 현행이 이득’이라는 뜻은 아니다.

### 5.5 한계 서술의 충분성

| 한계 | 현 상태 | 검수 의견 |
|---|---|---|
| 대상0·1시 정답으로 짝 선택 | 코드 머리말·카탈로그·9장 추가 노트·새Q&A에서 인정 | 기본 고지는 있음. ‘진짜 전날’이 독립적인 날짜 확인인 것처럼 들리지 않게 할 것 |
| 링커 전체 적합 | 코드·카탈로그·PPT 상세 근거·별도Q&A J03에서 인정 | 은폐는 아님. 새 비교 설명에서도 함께 연결할 것 |
| 짝 밖 현행 유지 | 코드·카탈로그에 있음; 새Q&A에는 없음 | 실제 날짜·동을 모두 넣은 비교와 다름. F05 |
| 연결 외 조건 변경 | EC q=1, 보정 적용 범위 변경, 온도 ID간 사슬 허용 | 현재 짧은 해석은 불충분. 순수 오류 손해로 부를 수 없음 |
| 계절 지표 유지 | 코드·기존ABL1 노트·별도Q&A J02에 있음 | ‘어제 모두 끄기’는 이력 보정만 제거라는 범위를 함께 유지할 것 |
| 통계 불확실성 | 로그 p2 온도 .0100 / EC .0597, 카탈로그 .010/.060 | EC 개선이 사전 채택 기준을 통과했다는 주장은 불가. 확률값 자체도 실제 개선의 사후 확률로 읽지 않음 |
| 현장 최종 성능 | 실제 달력 대체·새 현장·농작업 효과 미측정 | ABL3가 이를 대신 검증한 것처럼 말하면 과장 |

**결론:** 로그·CSV의 계산은 맞고, 구현도 선언한 혼합 오라클과 맞는다. 다만 한계가 여러 곳에 흩어져 있어 새Q&A만 읽으면 결과를 넓게 해석하기 쉽다. F05처럼 설명을 한곳에 모으면 진단 결과를 정직하게 사용할 수 있다. 이 검수는 ABL3를 새 구성의 채택 근거로 승인한 것이 아니다.
