## 1. 운영위원·심사위원 관점

### J01. 어제의 배지 실측이 필요한데 센서 없는 현장에서 무엇을 해결하나?

- **장·제목:** 9장(1.6) 「'어제' 정보를 끄면 오차가 온도 3~10%, EC 8~31% 늘어난다」, 6장(1.3) 「기본 예측 위에 '어제'를 얹고, 추운 시간대를 보정한다」.
- **질문:** “어제 배지 온도와 EC를 실제로 재야 앵커를 쓴다면, 센서가 없는 농가는 못 쓰는 것 아닌가요? 센서가 있는 농가에는 어떤 이득이 있습니까?”
- **중요도: 상.** 현장 적용성의 사용 목적·입력 확보 조건을 직접 묻는다. 예측 정확도만으로 농가 효용은 확정되지 않는다.
- **덱·노트 답: 일부.** 전날 배지 실측이 있어야 한다는 조건과 센서 없는 경우의 한계는 있다. 실제 업무·경제적 이득은 없다.
- **근거·답변 초안:** 정형 README ②의 A 정의, 카탈로그 **7.069**, 9·23장 노트. “실측 앵커는 전날 목표 센서 기록이 남아 있을 때 쓰는 조건부 방법입니다. 센서가 전혀 없는 환경의 성능, 단순 전날 값 유지 대비 이득, 관수·난방·수익 개선은 확인하지 않았습니다.” **농가 효용을 입증하는 근거 없음.**

### J02. 대회 특성을 모두 없앤 정형 성능은 얼마인가?

### J03. 링커도 검증 정답을 완전히 보지 않았나?

- **장·제목:** 26장(A4b) 「공통 2: 성능 수치의 출처(정형)」, 9장(1.6).
- **질문:** “기본 모델은 폴드별로 다시 학습했다지만 링커 가중치는 전체 자료로 맞춘 값을 썼다고요? 그럼 어제 정보의 개선 폭이 낙관적으로 나온 것 아닌가요?”
- **중요도: 상.** 검증 수치의 독립성·수치 출처를 묻는 요청 공통 2에 직결한다. 제출 입력 규정 준수와 별개의 문제다.

- **근거·답변 초안:** 26장 노트, 진위 확인 **4.2절**, 카탈로그 **7.074**. “온도는 FL5에서 가림 기록과 ±1 정답을 후보 특징에서 빼지만 FL3 전체 적합 가중치를 재사용합니다. EC도 FL3 연결표를 사용합니다. 따라서 완전한 폴드 밖 링커 결과라고 부를 수 없고, 그에 따른 성능 차이는 측정하지 않았습니다.” **영향 크기 근거 없음.** β·0.36의 1차 구간 겹침 가능성도 별도 공개되어 있다.

### A07. 온도와 EC에 같은 모델을 쓰는가?

- **장·제목:** 6장(1.3) 「기본 예측 위에 '어제'를 얹고, 추운 시간대를 보정한다」.
- **질문:** “그림을 보면 온도와 EC가 똑같이 보정되는 것 같은데, 세 모델과 추위 보정이 EC에도 들어가나요?”
- **중요도: 중.** 하나의 도식에서 목표별 차이를 놓치기 쉽다.
- **덱·노트 답: 있음.** 본문 주석과 노트에 EC 별도 경로가 있다.
- **근거·답변 초안:** 정형 README **②·⑤**, 발표자 안내서 **2.4절**. “온도는 BASE·CODEX·TabPFN에 실내 온도 게이트, 앵커, TX3, 사슬을 적용합니다. EC는 트리·신경망 조합과 TabPFN, 일내 수축, HR5, 실측 앵커, 범위 자르기를 씁니다. 온도 TX3·예측 사슬을 EC에도 똑같이 적용한 것은 아닙니다.”

### A08. AI가 만든 사진만 가짜인가, 일반 편집도 가짜인가?

- **장·제목:** 10장 「이미지 미션」, 11장(2.1) 「정답을 아는 학습 자료를, 공개 데이터로 우리가 직접 만들었다」.
- **질문:** “밝기나 선명도를 조금 바꾼 사진도 가짜인가요? 이 모델은 사진이 거짓 내용을 담았는지 판단하는 건가요?”
- **중요도: 상.** ‘가짜’라는 일상적 의미와 대회 라벨 정의가 다를 수 있다.
- **덱·노트 답: 일부.** 생성·편집 및 제작 유형은 있으나 일상 편집의 경계를 전부 정의하지는 않는다.
- **근거·답변 초안:** 이미지 README **①의 6유형**, 11·14장 노트. “대회에서 정의한 필터·합성·부분/전체 생성·스타일 등의 실제/가짜 분류 과제입니다. 현실의 사건 진위나 내용의 거짓을 검증하는 모델은 아닙니다. 처리한 실제 사진을 별도 대조군으로 평가했을 때 선명화 등에 큰 오탐도 있었습니다.” **모든 일상 편집에 적용할 보편 라벨 경계·내용 진위 판단 근거 없음.**

### A09. 15만 장과 실제 학습 9천여 장, GPT 600장은 어떻게 다른가?

- **장·제목:** 11장(2.1), 27장(A5) 「공통 3 ①②: 이미지 자료의 외부 서비스·환경 처리」.
- **질문:** “사진 15만 장을 학습한 건가요? GPT 600장이면 원본 600장을 보냈다는 뜻인가요?”
- **중요도: 중.** DB 전체·기본 판별기·전문가 학습 수를 혼동하기 쉽다.
- **덱·노트 답: 있음.** 각 용도와 GPT 입력/출력 수가 있다.
- **근거·답변 초안:** 이미지 README **①·④**, 11·27·28장 노트. “152,043장은 지문 DB 원천 전체 수입니다. 기본 판별기 학습은 실제 2,467장과 가짜 7,124장이고 전문가마다 학습 세트가 다릅니다. GPT는 중복 제외 원본 525장을 넣어 편집 575장을 만들었고, 문장만으로 생성한 25장을 더해 600장입니다.”

### A10. 지문은 워터마크인가, 사진을 외우는 것인가?

- **장·제목:** 12장(2.2) 「핵심은 사진 한 장만 보는 일반 판별기다」, 28장(A6).
- **질문:** “사진 지문이란 숨겨 둔 표시를 읽는 건가요? 원본을 미리 모아 놔야만 가짜를 잡는 건가요?”
- **중요도: 중.** 일반 판별과 원본 대조의 서로 다른 역할을 이해해야 한다.
- **덱·노트 답: 있음.** 두 DB 구조와 fallback을 설명한다.
- **근거·답변 초안:** 이미지 README **②·⑤**, 28·30장. “워터마크를 읽는 것이 아니라 작은 색·흑백·선명도 요약 배열로 비슷한 원본을 찾는 방법입니다. 대조 가능한 원본이 없으면 그 규칙은 건너뛰고 사진 자체를 보는 기본 판별기와 적용 가능한 전문가로 판단합니다. DB 없이도 출력은 내지만 정확도가 같다는 뜻은 아닙니다.”

### A11. JPEG 품질 92가 무엇이며 왜 저장 형식으로 모델이 달라지나?

- **장·제목:** 30장(A8a) 「팀별 이미지 2: 장치가 작동하는 사진」, 14장(2.4).
- **질문:** “같은 사진을 PNG나 WebP로 저장하면 판단하는 모델이 바뀌나요? 품질 92라는 것은 사진이 92점이라는 뜻인가요?”
- **중요도: 중.** 파일 형식 조건이 현장 취약성으로 연결되는 이유를 설명해야 한다.
- **덱·노트 답: 있음.** 정확한 조건과 꺼지는 전문가를 노트에 제시한다.
- **근거·답변 초안:** 이미지 README **⑤ 형식 게이트**, 30장 노트. “품질 92는 JPEG 저장 설정이고 사진의 진위 점수가 아닙니다. 실제로는 JPEG 양자화표와 색 정보 저장 방식 4:2:0이 지정 조건과 정확히 같은지 봅니다. 그 조건에서 학습된 일부 전문가만 켜므로 형식이 달라지면 적용되는 전문가가 달라집니다. 형식만으로 진짜·가짜를 확정하는 규칙은 아닙니다.”

### A12. 3% 증가와 3%p 감소는 같은 뜻인가?

- **장·제목:** 9장(1.6) 「'어제' 정보를 끄면 오차가 온도 3~10%, EC 8~31% 늘어난다」, 14장(2.4) 「대회 자료용 장치를 모두 끄면 균형 정확도가 2.7~3.0%p 내려간다」.
- **질문:** “앞에서는 3~10%, 뒤에서는 3%p라고 하는데 얼마나 다른 건가요? 균형 정확도는 보통 정확도와 다른가요?”
- **중요도: 중.** 숫자 비교의 기준을 잘못 잡으면 효과 크기를 오해한다.
- **덱·노트 답: 일부.** 수치·기준은 있으나 비전공자용 비교 풀이가 짧다.
- **근거·답변 초안:** 카탈로그 **7.069·7.073**, 이미지 README **용어**. “정형은 최종 RMSE 대비 끈 판의 상대 증가율입니다. 예를 들어 .7599에서 .8387이면 약 10.4% 증가입니다. 이미지 .9617에서 .9317은 3.0퍼센트포인트 감소입니다. 균형 정확도는 실제를 맞힌 비율과 가짜를 맞힌 비율의 평균입니다.”

### A13. 두 미션은 하나의 농장 시스템인가, AI 도구가 곧 모델인가?

- **장·제목:** 1장 「현장에서 그 시각에 알 수 있는 정보로 예측하고 판별하기」, 15장(3) 「판단과 설계는 팀이, 실행과 초안은 AI 도구가 맡았다」, 16장(4).
- **질문:** “센서 예측과 가짜 사진 판별이 한 시스템으로 연결돼 있나요? 농가가 쓸 때도 ChatGPT나 Claude에 매번 물어보는 건가요?”
- **중요도: 중.** 발표의 공통 주제와 실제 구현된 범위를 분리해서 이해할 필요가 있다.
- **덱·노트 답: 일부.** 두 미션·개발 도구와 추론의 구분은 있다. 통합 운영 흐름은 없다.
- **근거·답변 초안:** 정형 README **①**, 이미지 README **①·⑥**, 15·16장. “두 개의 대회 과제를 같은 팀이 수행했고, 현장에서 알 수 있는 정보와 대회 특성 의존을 구분한다는 주제를 공유합니다. Claude·Codex는 개발 보조, ChatGPT는 가짜 제작에 사용했습니다. 제출 추론은 저장된 모델·규칙으로 실행하며 AI 도우미를 호출하지 않습니다. 사전학습 모델 자체는 사용합니다.” **두 기능을 통합해 농장에서 운영한 실증 근거 없음.**
